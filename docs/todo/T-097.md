## Concept

Build the **App-side view + integration** slice of D-004's "Bulk Cut" tab. This task owns the XAML and wiring only — the row/tab view models (`BulkCutViewModel`, `BulkItemViewModel`) are a **sibling task** (dependency below); T-097 binds against their documented surface.

Deliverables:
1. **`BulkCutView`** (`UserControl`) — an `ItemsControl` of row cards, a top toolbar (Apply-to-all + gold/blue legend + subtitle), and a footer (output note + overall gold `ProgressBar` + Run/Cancel + the **same four lifecycle surfaces as `JoinView`**: Running / Completed+Open-folder / Cancelled-neutral / Failed-some+jump-links+Retry-failed). Empty state is Join-style + legend.
2. **`BulkRowScrubView`** (`UserControl`) — the per-row **view-only** dual-handle scrub bar, rendered onto a `Canvas` in code-behind from VM offsets (exactly like `TimelineView`), so no rendering logic leaks into any Core type and `CoreIsUiFreeTests` stays green. Dropped-span scrim, gold KEEP span, two disambiguated handles (color/cap/glyph), handle-drag → set-requested + snap-on-release, hover → `IThumbnailService` preview popup.
3. **`DropScrimBrush`** token in `Tokens.xaml` (~near-black @70%, dark-theme-safe).
4. **Wiring** — `MainViewModel` 2-way→3-way `SelectedTabIndex` routing (`CurrentOperation`/`CurrentClearCommand`/`CurrentLoadLabel`/`CurrentClearLabel`/tooltips for `index==2` → Bulk **aggregate** op) + construct `BulkCut` sharing existing services + add its aggregate op to `HookOperations`; `MainWindow.xaml` 3rd `TabItem`; `MainWindow.xaml.cs` `Load_Click` `==2` branch.

Core insight preserved: Bulk Cut adds **no new ffmpeg path** — the view only surfaces VM state and routes gestures; the batch engine is reused wholesale in the VM task.

## Design (step-by-step build plan)

**1. `Tokens.xaml` — new `DropScrimBrush`.** After the surface-color block add `<Color x:Key="DropScrimColor">#B30A0B0D</Color>` (near-black `Surface0` @ ~70% alpha `0xB3`) and, in the brush block, `<SolidColorBrush x:Key="DropScrimBrush" Color="{StaticResource DropScrimColor}" />`. Additive; no existing token touched. Semi-transparent over the track so the dropped spans read as "removed" while the underlying track tint still shows through.

**2. `BulkRowScrubView.xaml` + `.cs` (the per-row scrub control).**
- XAML: a `Border` (`Surface1Brush` sunken track, `BorderBrush`, `RadiusSm`) wrapping `Canvas x:Name="Track" ClipToBounds="True" Background="Transparent" SizeChanged="OnSizeChanged" MouseMove="OnMouseMove" MouseLeftButtonDown="OnDown" MouseLeftButtonUp="OnUp" MouseLeave="OnLeave"`, plus the hover `Popup` bound to `Preview.*` (mirror `PlayerView.xaml:79-115`). Fixed height ~34px.
- `.cs` (mirror `TimelineView.xaml.cs`): `DataContextChanged` → cache `BulkItemViewModel`, subscribe `PropertyChanged`, call `SetInput` on `Preview`, `Redraw()`. Redraw on `Duration`/`IntroEnd.Snapped`/`OutroStart.Snapped`/`HasOutro`/`State`/`Progress` changes and `SizeChanged`.
- **Draw order** (from VM offsets; `norm(t) = t / Duration`, guarded when `Duration` null/zero → draw empty track only):
  1. dropped intro `Rectangle [0 → introEndX]` filled `DropScrimBrush`; dropped outro `Rectangle [outroStartX → width]` filled `DropScrimBrush` (only when `HasOutro`).
  2. **KEEP span** `Rectangle [introEndX → (outroStartX | width)]` filled `AccentMutedBrush` (gold @25%) — the primary "this is what you keep" cue; **literally the brightest thing on the bar**.
  3. intro-end handle: gold `AccentBrush` 3px bar at `introEndX`, a **top** cap block, and a `▸` glyph (right-facing).
  4. outro-start handle (when `HasOutro`): blue `InfoBrush` 3px bar at `outroStartX`, a **bottom** cap block, and a `◂` glyph (left-facing).
  5. 3px bottom progress fill spanning `[0 → Progress*width]` in `AccentBrush` while the row is Running.
  - Resolve brushes via `TryFindResource` with frozen fallbacks (`AccentColor #FFE0A83A`, `InfoColor #FF5B9CF0`, `AccentMutedColor #40E0A83A`, `Surface0Color` for scrim) so design-time/test hosts don't crash.
- **Handle hit-test + drag** (`OnDown`/`OnMouseMove`/`OnUp`): on down, pick the nearer handle within a ~6px hit radius (intro vs outro). While dragging, `t = clamp(x/width, 0, 1) * Duration` and call `SetIntroEndRequested(t)` / `SetOutroStartRequested(t)` (live requested position, no snap yet), `Redraw()`. On up, call `CommitSnap()` (VM re-snaps → `Snapped`/`Delta` update → `Display` refresh + a `⟲ snapped` flash). Guard `Duration` null → ignore drags.
- **Hover** (non-drag `OnMouseMove`): `Preview.UpdateHover(t, x)`; `OnLeave` → `Preview.MouseLeave()`. `OnDown` on empty track (not near a handle) does nothing (rows are not click-to-seek).
- **Three-axis disambiguation** baked into the draw so it never relies on color alone: warm gold vs cool blue (color) · top vs bottom cap (position) · `▸` vs `◂` (glyph). Legend in the view header names both.

**3. `BulkCutView.xaml` + `.cs`.**

- `Grid` rows: `Auto` (header toolbar) / `*` (list) / `Auto` (footer).

- **List** (Row 1): `ScrollViewer` → `ItemsControl ItemsSource="{Binding Items}"` with an `ItemTemplate` `DataType="{x:Type vm:BulkItemViewModel}"`. Row card = `Border` (`SurfaceBrush`/`BorderBrush`/`RadiusMd`) laying out: `CheckBox IsChecked="{Binding IsEnabled, Mode=TwoWay}"`; a name/info column (`FileName` bold + `InfoText` mono muted via `NullToCollapsed`); the `<views:BulkRowScrubView DataContext="{Binding}"/>`; a mono IN/OUT readout column (`IntroEnd.Display`; `OutroStart.Display` when `HasOutro`, else `— end —` + a `[+ outro]` `Button` bound to `AddOutroCommand`); a per-row **state chip** (color-coded pill off `State`); a remove `Button Content="✕"` bound to `RemoveCommand`. ## Risks

- **Aggregate op vs per-row op** — the footer/taskbar/title bind the tab VM's **aggregate** `Operation`; each row card binds its **own** `Operation` (progress/chip). Do not cross-wire; the aggregate is the VM task's rollup.
- **ItemsControl + named Canvas** — a `Canvas x:Name` inside a `DataTemplate` is not addressable from code-behind. Mitigation (baked): factor the row scrub bar into `BulkRowScrubView` (its own `UserControl` with `DataContextChanged`-driven redraw), exactly like `TimelineView`.
- **Two-handle hit ambiguity** — when intro/outro are near each other, disambiguate the grabbed handle by nearest-within-radius on down; if equidistant, prefer the one whose cap the cursor is vertically closer to (top→intro, bottom→outro).
- **Popup lifetime across scroll/virtualization** — close the hover `Popup` on `MouseLeave`/`DataContextChanged` so a scrolled-away row can't leave a stuck preview.
- **Snap-on-release timing** — set `Requested` during drag but only `CommitSnap()` on release, else every mouse-move re-snaps and the handle "sticks" to keyframes mid-drag (poor feel). The snapped value remains the shown truth after release.
- **Design-time/test brush resolution** — always `TryFindResource` + frozen fallback (proven pattern in `TimelineView.xaml.cs`) so the control renders in hosts without merged token dictionaries.
