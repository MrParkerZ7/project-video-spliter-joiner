## Concept
Lay the dependency foundation: add the FFME NuGet, download the ffmpeg SHARED build whose major version FFME requires, wire `Library.FFmpegDirectory` at startup, and point the split/join engine at the same build. Make-or-break: the FFME↔ffmpeg version must match exactly.

## Design
- Resolve the exact **Unosquare.FFME.Windows** version ↔ required **ffmpeg major** (read the package's docs/release notes; do NOT assume). Add the package to `src/App`.
- Download the matching **ffmpeg shared** build (gyan.dev `ffmpeg-<ver>-full_build-shared` or `-shared`) → place its `bin/*.dll` in a repo-local **gitignored** `ffmpeg-shared/` (dev) + a known env location. The shared build also ships `ffmpeg.exe`/`ffprobe.exe`.
- Startup: set `Unosquare.FFME.Library.FFmpegDirectory = <dll folder>` in `App.xaml.cs` (or before the first player use) — BEFORE any FFME control loads.
- Engine consolidation (D2): the split/join `FfmpegBinaryLocator` should resolve the SAME shared build's `ffmpeg.exe`/`ffprobe.exe` (app-local `ffmpeg/` → the shared build). One build serves both.

## Detail
- Verify FFME can initialize against the DLLs (a headless probe: `Library.LoadFFmpeg()` after setting the directory → succeeds without throwing; catch + report the version mismatch clearly if it fails).
- Keep the DLLs OUT of git (D4) — add `ffmpeg-shared/` to `.gitignore`; a `packaging/` or README note documents where to get them.
- Do NOT swap the player control yet (T-020) — this ticket only lands the dependency + init + a passing FFME init probe.

## Interfaces / contracts
- Produces: the FFME package reference, the `Library.FFmpegDirectory` startup wiring, the on-disk shared build, and a documented dev-setup step. Consumed by T-020 (player swap) + T-021 (packaging).
