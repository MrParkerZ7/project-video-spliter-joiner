## Concept
Expose the mode without letting anyone destroy a master by mis-click. Today the only output control is a plain
peer checkbox "Overwrite existing output" (`BulkCutView.xaml:813-816`) sitting inches from the reassuring note
"Output → same folder → _trimmed suffix → originals kept" (`:810`). A second look-alike checkbox beside it
would be the single most dangerous control in the app.

## Design
- Present the output destination as an explicit **choice** (New file `_trimmed` [default] vs **Replace original**),
  not a second anonymous checkbox — so the destructive option can never be mistaken for the collision one.
- The UI Designer establishes the destructive-affordance tokens FIRST (danger colour-role + icon + weight — ≥2
  differentiators, never a tint alone), consistent with the existing dark+gold theme.
- Selecting Replace original updates the reassurance line to state plainly what will happen, and **visibly inerts
  the collision checkbox** (it is ignored in this mode — T-121 precedence).
- **Confirm gate on Run**, naming the count: "This will replace N original files. Originals go to the Recycle Bin."
  Required — not bypassable by row-level state.

## Acceptance criteria + Case-Coverage Matrix
- [ ] The default is unchanged (`_trimmed`, originals kept) — a user who ignores this ships identical behaviour.
- [ ] Choosing Replace original: destructive styling applies, the note updates, the collision control is visibly inert.
- [ ] Run under Replace original blocks on an explicit confirmation naming the file count; cancelling it runs nothing.
- [ ] Both layout modes; on-theme tokens; the choice survives a settings round-trip if persisted.
- Matrix — Required-Success: mode selected + confirmed → the engine receives `OutputMode.ReplaceOriginal`.
  **Required-Fail: confirmation declined → ZERO engine calls.** Boundary: 0 rows, 1 row, all-invalid rows.
  **Perf (no-I/O-on-path): declining the gate invokes the engine zero times (recording fake).**

## Out of scope
A Recycle-Bin browser/restore UI.
