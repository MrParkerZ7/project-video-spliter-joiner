## What is wrong

Two problems that only look like one.

**1. The work is unreleased.** 25 commits sit after `release: v1.1.0` (3188328), 17 of them `feat`/`fix`:
delete-originals after a batch, profile backup/restore, the delete-originals handle release, Exact cut
verified on real media, the test-settings-pollution fix, last-tab restore, and four Bulk Cut layout
fixes. `CHANGELOG.md`'s `## [Unreleased]` section is **empty**, `Directory.Build.props` still reads
`<Version>1.1.0</Version>`, and root `CLAUDE.md` is staler still (says 0.1.0).

**2. No tag has ever existed.** `git ls-remote origin` returns exactly two refs: `HEAD` and
`refs/heads/main`. **Zero tags**, local or remote; `git describe --tags` fails with "No names found".
`.github/workflows/release.yml` triggers only on `push: tags: ['v*.*.*']`, so it has **never executed** —
for v1.0.0 or v1.1.0 — despite CHANGELOG and ROADMAP recording both as shipped.

## The concrete failure it allows
Cutting the next release by pushing a tag would be the **first ever end-to-end run** of that workflow. It
would (a) pass its `Test (release gate)` step vacuously (see [[T-149]]), then (b) hit whatever is actually
broken in a publish path nobody has executed. Meanwhile `generate_release_notes: true` on a main-only
history produces a commit dump rather than the curated CHANGELOG that already exists.

## Design
1. Land [[T-149]] first — releasing behind a gate that cannot fail is worse than not releasing.
2. Fill `## [Unreleased]` from the 17 commits, in the CHANGELOG's existing voice (user-facing outcomes,
   not commit subjects). Bump `Directory.Build.props` to 1.1.1 and fix the stale version in `CLAUDE.md`.
3. **Dry-run the release workflow before tagging** — `act`, a throwaway pre-release tag, or a
   `workflow_dispatch` path — so its first real execution is not also its first test.
4. Then tag and push.

## Acceptance criteria
- [ ] `[Unreleased]` describes every user-facing change since v1.1.0, in the file's existing voice.
- [ ] Version bumped in `Directory.Build.props`; the stale figure in `CLAUDE.md` corrected.
- [ ] The release workflow is proven to run before it is relied on.
- [ ] v1.1.1 tagged, pushed, and the published artifact verified to install and launch.

## Out of scope
Changing the release mechanism. It just has to be run.
