## Concept
Update packaging so the distributable ships the ffmpeg SHARED build — the DLLs FFME loads AND the exes the split/join engine runs — and FFME finds them at runtime from the packaged layout.

## Design
- `packaging/package.ps1`: copy the shared build's `bin/*.dll` + `ffmpeg.exe`/`ffprobe.exe` into the publish output where (a) `FfmpegBinaryLocator` resolves the exes (app-local `ffmpeg/`) and (b) FFME's `FFmpegDirectory` resolves the DLLs. Simplest: one `ffmpeg/` folder next to the exe holding both, with the app setting `Library.FFmpegDirectory` to that folder.
- `-FfmpegSource` param now points at the SHARED build's `bin`.
- Update `THIRD-PARTY-NOTICES.md`: FFME (Ms-PL/attribution) + the ffmpeg shared build license (still GPL for the gyan full/shared build — keep the GPL-vs-LGPL note; an LGPL shared build is the permissive-release path).
- Note the size increase (~+40MB).

## Detail
- Ensure the app's startup `FFmpegDirectory` points at the packaged `ffmpeg/` folder (works both in dev and packaged — resolve relative to `AppContext.BaseDirectory`).
- `dist/` stays gitignored; DLLs not committed.

## Acceptance criteria + Case-Coverage Matrix
- [ ] `package.ps1` produces a publish tree containing `ffmpeg/` with the shared DLLs + exes; the zip builds.
- [ ] The packaged app resolves FFME DLLs (FFmpegDirectory) AND the engine exes from the bundled `ffmpeg/`.
- [ ] THIRD-PARTY-NOTICES updated (FFME + ffmpeg shared build license/GPL note).
- [ ] Build + 237 tests green.
- Matrix — Required-Success: packaged tree has both DLLs + exes; app finds them. Boundary: missing shared source → script fails loudly (as today).

## Dependencies
T-020 (the app must use FFME to need the DLLs bundled).

## Risks
FFmpegDirectory resolution differing dev vs packaged → resolve via `AppContext.BaseDirectory/ffmpeg`. Size growth noted.

## Out of scope
Docs (T-022); an LGPL swap for public release (parked, noted).
