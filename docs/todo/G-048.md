## Why

User: *"after click on Save current as.. then save then UI gone broke untill I click X everything back to
normal"* and *"Thumnail is optional and it's should be update later or remove able"*

Two problems in the same dialog. **T-139** is understood and fixed: the popup's thumbnail controls were
bound to `SelectedProfile`, which during a new-profile save is still the PREVIOUS profile — so **Clear**
silently destroyed another profile's picture, and the section made an optional, automatic step look
mandatory. **T-138** — the UI breaking until something is dismissed — is NOT yet diagnosed and is
deliberately not guessed at.

## Out of scope
Redesigning cut profiles. This is about the save dialog behaving.

## Outcome — 2026-09-01

All three success criteria met; both tasks closed.

- *Saving a profile leaves the UI usable, with nothing to dismiss afterwards* — **T-138**. The cause was
  the **layout**, not the popup: revealing the populated profile bar makes the header taller, and the
  window's middle row has to defend its space or the content is pushed off screen. Fixed by T-141/T-142's
  header restructure, and now locked by `BulkCutViewLayoutTests`, which lays the real view out at five
  window sizes and fails if the content area collapses. Two earlier attempts blamed mouse capture and a
  layered popup; both were wrong, and both were shipped because "I could not reproduce it locally" was
  accepted instead of writing the test. The test takes a fifth of a second.
- *Nothing in the save dialog can modify a profile other than the one being created* — **T-139**. The
  dialog now names a profile and nothing else. Thumbnail controls bind to `SelectedProfile`, which during
  a new save is still the PREVIOUS profile, so a Clear there destroyed someone else's picture silently.
  All thumbnail editing moved to the profile bar, where `SelectedProfile` is by definition the profile
  being acted on (SPEC-007 I77).
- *The picture is clearly optional, and can be changed or removed later from one obvious place* —
  **T-139**. The save persists first and the auto-grab is best-effort afterwards, so a profile with no
  picture is a normal outcome rather than a failed save. It can then be set from the current frame,
  uploaded, or removed — all three from the bar, all after the fact (SPEC-007 I78).
