## Why / vision
After the two-column relayout (G-019), the default 900x600 window is too small — the video + a 360px tool panel need more room, so it opens cramped. And the custom WindowChrome frame (`SingleBorderWindow`, `CornerRadius=0`, no `BorderBrush`) shows the OS's default light hairline around the dark window — a visible "line" that clashes with the theme. Give the frame a themed border and open bigger.

## Grounding (2026-07-18)
- `MainWindow.xaml`: `Width=900 Height=600 MinWidth=600 MinHeight=400`, `WindowStyle=SingleBorderWindow`, WindowChrome `CaptionHeight=34 ResizeBorderThickness=6 CornerRadius=0`. No `WindowStartupLocation`, no themed `BorderBrush` on the root.
- Root is `<Grid Margin="{... ContentMargin}">` — the `ContentMargin` converter insets content only in the Maximized state (invisible resize border + taskbar clamp via `WM_GETMINMAXINFO`). Any border must not double-inset or show oddly when maximized.

## Decisions
- **D1 · Themed border line** — wrap the root in a `Border` with `BorderThickness=1` + `BorderBrush={DynamicResource BorderStrongBrush}` (#3a4250 — a clean, visible-but-subtle themed line) and `Background={DynamicResource BgBrush}` so the frame reads intentional. Gold (`AccentBrush`) is a one-token swap if a branded frame is wanted — default to the subtle border token. The border must collapse/agree with the maximized inset so it doesn't show a floating line when maximized.
- **D2 · Larger startup size** — default `Width=1280 Height=800`, `WindowStartupLocation=CenterScreen`. Bump mins so the two-column layout isn't cramped: `MinWidth=960 MinHeight=600`. Keep it resizable.
- **D3 · No chrome regression** — maximize/restore, the taskbar work-area clamp, and the 6px resize border must all still work.

## Plan
```
T-066 add a themed 1px window border (BorderStrongBrush) + open at 1280x800 centered, mins 960x600; verify maximize/clamp intact
```

## Risks
- A border on a WindowChrome window can show a stray line in the Maximized state — tie its visibility/thickness to the same state the ContentMargin converter uses, or verify it's covered by the maximized inset.
- Too-large a default on a small monitor — 1280x800 is safe for most; CenterScreen keeps it reachable.

## Out of scope
Rounded window corners; per-monitor DPI border tuning; restyling the caption buttons (already themed).
