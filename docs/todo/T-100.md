## Concept
Give BulkCutViewModel a **selected row** and a **single shared preview player**, so selecting a row opens that video in
one FFME-backed `PlayerViewModel` (the same player the Split tab uses). Only ONE decoder is ever active — never a player
per row. This is the VM/wiring foundation the preview pane (T-101) and profile-apply-to-selected (T-103) build on.

## Grounding (real signatures)
- `PlayerViewModel(IMediaPlayer player, IThumbnailService? thumbnails)` — `src/App/ViewModels/PlayerViewModel.cs:102`. WPF-free
  transport over `IMediaPlayer`: `Position`/`Duration`/`IsPlaying`/`IsReady`, `PlayPauseCommand`/`StopCommand`/`SkipCommand`
  (seconds param)/`StepForward`/`StepBack`. Split constructs exactly one: `Player = new PlayerViewModel(player ?? NullMediaPlayer.Instance, thumbnails)` (`SplitViewModel.cs:115`) and re-anchors it on load.
- `IMediaPlayer` (`src/App/Media/IMediaPlayer.cs`) — `FfmeMediaPlayer` in prod, `NullMediaPlayer.Instance` default, a fake in tests. `MainViewModel` builds the shared `FfmeMediaPlayer` for Split (`MainViewModel.cs:87`).
- `MediaReopenGuard` (T-080, `src/App/Media/MediaReopenGuard.cs`) + `IReopenTarget` — waits for FFME to settle out of IsClosing/IsOpening before Open; **required** to safely switch the player between rows (rapid selection changes = the exact native-AV hazard it fixes).
- `BulkCutViewModel(IMediaProbe, ISplitEngine, IThumbnailService, IAppSettings, IBulkTrimEngine?=null)` (T-096). Has NO selected-row concept today.
- `BulkItemViewModel` — has `Path`, `Duration`, `Keyframes`, `IntroEnd`/`OutroStart` handles.

## Design
1. **`BulkCutViewModel.SelectedItem`** (`BulkItemViewModel?`, observable, two-way from the list `SelectedItem`). On change:
   open `SelectedItem.Path` in the shared player via `MediaReopenGuard` (guard the previous open finishing first); on null
   (list cleared / nothing selected) unload the player. Auto-select the first row on first `AddFilesAsync` for convenience.
2. **Shared `Player`** — add `public PlayerViewModel Player { get; }` constructed `new PlayerViewModel(player ?? NullMediaPlayer.Instance, thumbnails)` from a NEW ctor param `IMediaPlayer? player = null` (default Null so existing test constructions keep working). Reuse the `thumbnails` already injected.
3. **MainViewModel wiring** — construct the Bulk player: pass a `FfmeMediaPlayer` into `BulkCut` (its OWN instance — a second FFME element is fine; Split/Bulk are different tabs, only the active tab plays). Add `Player.PropertyChanged`/hook if the window title/taskbar should reflect Bulk playback (optional — the aggregate op already owns batch progress; playback is preview-only, likely NO taskbar wiring).
4. **Lifecycle** — pause/stop the Bulk player when the tab loses focus or a batch run starts (don't decode while trimming). Unload on `ClearCommand`. Respect `MediaReopenGuard` on every switch.

## Acceptance criteria + Case-Coverage Matrix
- [ ] `BulkCutViewModel.SelectedItem` (observable) + `Player` (PlayerViewModel) exist; selecting a row opens its file in the ONE shared player (verify via a fake `IMediaPlayer` recording Open calls — exactly one Open per selection, previous closed first).
- [ ] Switching selection rapidly does not crash / uses `MediaReopenGuard` (no Open-before-Close); null selection unloads.
- [ ] Only one decoder active; the per-row scrub bar (T-097) still works; Split/Join unaffected.
- [ ] Player is WPF-free-VM-clean; existing `BulkCutViewModel` tests still pass; new ctor param is optional (old constructions compile).
- [ ] Build 0-warning; suite green (baseline 671+) + tests: select→Open, switch→Close-then-Open, clear→Unload, run-batch→stop-player.
- Matrix — Success: select a row → it plays. Boundary: rapid switch (guarded), select while a scan is indexing (still opens), clear during playback (unloads), start batch while playing (player stops). Required-Fail: none. (Live = app-run.)

## Dependencies
Reuses PlayerViewModel/IMediaPlayer/FfmeMediaPlayer/MediaReopenGuard/NullMediaPlayer. Consumed by T-101 (pane UI) + T-103 (apply-to-selected). No Core change.

## Risks
Two FFME elements (Split + Bulk) in one process — ensure only the active tab decodes (stop the inactive one) to avoid CPU/handle waste; MediaReopenGuard must gate every switch. Don't let a stale selection open a removed row (guard against SelectedItem pointing at a just-removed item).

## Out of scope
The pane XAML + jog/set-at-playhead buttons (T-101); profiles (T-102/103). Per-row players.
