## Concept

The copy passes run at disk speed (verified: the split's ffmpeg step takes 0.74-0.78 s against 0.86-1.47 s for a raw
copy of the same file; join runs at about 815 MB/s). G-020 writes outputs next to the source, so a big 4K file on a
5400-rpm drive is read and written on the same spindle, which is the slowest case. No engine change beats that.

Proposals:
- an ETA from bytes and observed throughput;
- a hint to choose another output drive when the source is on a rotational or network disk.

The default folder stays as G-020 requires.

## Why later

It is UX with no measured basis yet.

## Trigger

After G-059, the owner still finds split or join slow, and the file sits on an HDD or NAS.
