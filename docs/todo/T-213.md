## Concept

The FFME preview decodes 4K with hardware devices and a `scale=W:H` filter capped near 1080p
(`FfmeMediaPlayer.cs:494, 528`; SPEC-013). Formats NVDEC cannot decode (4:2:2, some 10-bit) silently fall back to
software decode on 3-4 cores. The ideas:

- `flags=fast_bilinear` scaling: 30-50% less scale CPU in a CLI proxy. On thumbnails it gave a visibly different
  picture (PSNR 20 dB);
- a 720p cap when software decode is in effect;
- FFME `DecoderParams`;
- a notice when hardware decode did not engage.

## Why later

It is on the preview side of the seam, and it is verifiable only live with `app-run`. The GUI was not run in T-187,
and the preview is not on the export path.

## Trigger

The owner reports choppy 4K scrubbing or playback. Measure with `app-run` on a synthetic fixture first.
