## Why / vision
Cut profiles (G-037) are reusable by NAME, but a name alone is easy to mix up across a library of intros. A small
**thumbnail** makes a profile instantly recognizable ("that's the anime OP"). Two related asks:
- **A — profile thumbnails:** an optional, user-uploaded image on a profile (auto-defaulting to the intro-end frame),
  shown in the profile picker — so reuse is by sight, not just text.
- **B — cut-point frame thumbnails:** show the actual video frame at each cut point (intro-end / outro-start) on the row,
  so you can verify the cut visually at a glance without hovering/scrubbing.

Both extend Bulk Cut; both reuse the existing `IThumbnailService` (the app already grabs frames for hover previews, G-030).

## Design decisions (chosen — flag if you'd prefer otherwise)
- **Profile thumbnail = a FILE under %LOCALAPPDATA%/VideoSplitJoiner/profile-thumbs/, path stored in settings** (not
  base64 in the JSON — keeps settings lean, matches the thumb-cache precedent). Copied on upload; deleted with the profile.
- **Auto-default profile thumbnail = the source row's intro-end frame**, captured via `IThumbnailService` when you
  "Save current as…". A user **Upload image…** overrides it; **Clear** falls back to a placeholder chip. (Bridges A+B.)
- **Cut-point thumbnails on EVERY row, both handles, debounced + best-effort** — reuse `IThumbnailService` (shared LRU
  cache, cheap) + the `ThumbnailPreviewViewModel` debounce/coalesce; grab at the handle's keyframe-**snapped** time so the
  thumb matches the real cut; a placeholder while loading / if unavailable (never blocks the UI).
