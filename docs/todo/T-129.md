## Concept
The upload button exists and is wired. Find out why it did not work for the user, then stop the path from
failing silently.

## Investigate first — do not write a fix before this is answered
Against a **rebuilt, running** app, with a profile selected:
- [ ] Does "Upload image…" open the picker, and does choosing a PNG/JPG replace the visible thumbnail?
- [ ] Does the change survive an app restart (stored path persisted onto the profile)?
- [ ] With **no** profile selected, what does the button look like — is its disabled state legible?
- [ ] Does the panel read as "you can change this", or does it look like a read-only preview?

Record the answer here. The fix depends on which of G-044's three causes it turns out to be.

## Design (contingent on the finding)
1. **If it fails silently** — give the deliberate gesture a real contract: on copy/decode failure, surface
   an error to the user (the existing operation/error surface, not a swallowed `catch`). Keep the
   auto-thumbnail-on-save path best-effort as it is; only the explicit upload changes contract.
   This means SPEC-007 I66 must be re-scoped rather than just re-tested — it currently *specifies* the
   silent no-op.
2. **If it is the disabled state** — make the reason visible ("select a profile first") instead of an
   inert button.
3. **If it is discoverability** — surface the affordance on the thumbnail itself (click-to-change on the
   preview) rather than only as a separate button.

## Acceptance criteria
- [ ] The investigation questions above are answered in this ticket, from a running build.
- [ ] A user-chosen image that cannot be stored produces a visible message, not a no-op.
- [ ] A successful upload persists across restart.
- [ ] SPEC-007 updated where the contract changed (I66's silent-no-op scope), with `serves-spec` tests for
      the success path and each failure path that now reports.
- [ ] Rebuilt + relaunched, and the gesture verified by hand.

## Out of scope
Cropping, rotating, or resizing the chosen image. Changing the auto-thumbnail-on-save behaviour.
