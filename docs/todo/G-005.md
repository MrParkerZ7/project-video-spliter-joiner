## Why / vision
Two user calls: (1) **auto-detect isn't useful — remove it** (simplify the app, drop the black/white/scene detector + its UI). (2) **4K must be smooth** — the preview should play 4K without choppiness, and splitting 4K must stay fast. (Note: split is `-c copy`, already resolution-independent — the real 4K cost is the *preview decode*, plus the keyframe scan on very large files.)

## Gap from current state
- Auto-detect (G-001 T-006 `Core/Detect` + SplitViewModel `Candidates`/`AutoDetectCommand`/`PreviewCandidate` + SplitView candidate UI + Timeline candidate ticks) is fully present — to be removed.
- FFME preview (G-004) decodes 4K on the CPU by default → can be choppy at 3840x2160. No hardware-decode / downscale tuning yet.
- G-004's packaging (bundle FFME shared DLLs) + docs are still pending — folded here as the finalization.

## Decisions
- **D1 · Remove auto-detect wholesale** — delete `Core/Detect/*`, the detector wiring in `MainViewModel`, SplitViewModel `Candidates`/`AutoDetectCommand`/`AddSelectedCandidates`/`PreviewCandidate`, SplitView's auto-detect button + candidate list, TimelineViewModel `CandidateTicks` + TimelineView candidate rendering/legend. **Keep** manual markers, playhead, click-to-cut, seek-to-marker. Remove the now-dead detect tests.
- **D2 · 4K play = try hardware decode first, fall back to a downscaled preview** (auto-picked under --auto-approve). FFME supports hardware-accelerated decoders (D3D11VA/DXVA2) + render options; if HW decode isn't reliable, cap the preview render resolution (decode → scale to the view size) so the UI stays smooth. The SOURCE is untouched — this only affects the preview, never the cut (which is stream-copy).
- **D3 · Split stays copy** — confirm 4K split is already fast (no decode); optimize only the keyframe-scan path (T-003) if it stalls on large files (it's cached; verify + bound it).
- **D4 · Finalize G-004 here** — T-025 packages the FFME shared build; T-026 docs cover FFME + removal + 4K in one pass.

## Plan

## Risks
- FFME hardware-decode config is version/GPU-specific (beta) → fall back to downscaled-preview if HW is flaky; verify live via app-run.
- Removal touching shared VM/timeline files → do it first, keep tests green, before perf work.
- 4K measurement needs a real 4K file → generate a 3840x2160 fixture with ffmpeg to profile.

## Out of scope
Re-adding a smarter detector later, GPU-encode, thumbnail filmstrip, network/streaming sources.
