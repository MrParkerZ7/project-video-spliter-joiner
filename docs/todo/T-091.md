## Concept
The Cut-markers section and Parts-to-export section should arrange themselves by layout MODE:
- **Horizontal mode** (narrow tall tool panel): **stacked**, 50/50 **height** (the current D-003 build).
- **Vertical mode** (wide short tool panel): **side by side, on the same row**, 50/50 **width**.
(Correction of the D-003 miss: "on vertical" meant vertical MODE, not the vertical axis.)

## Key insight
The markers/parts split flips **opposite** to the main video/tools split. Reuse `OrientedSplitPanel` (it already
flips rows↔columns + splitter orientation on `IsVertical`, with per-axis ratios) — but bind its `IsVertical` to the
**INVERSE** of `MainViewModel.IsVertical`:
- `Main.IsVertical=false` (horizontal mode) → inner `IsVertical=true` → **rows (stacked)** ✓
- `Main.IsVertical=true` (vertical mode) → inner `IsVertical=false` → **columns (side by side)** ✓

## Design
1. **Add a bool-inverter** — a small `InverseBoolConverter` (`src/App/Views/Converters.cs`) OR a `MainViewModel`
   property `IsToolPanelSplitStacked => !IsVertical`. Prefer the converter (reusable, no VM churn).
2. **Restructure the tool panel** (`SplitView.xaml`, D-003 state): the two list-bearing sections become the two
   regions of a **nested `OrientedSplitPanel`**:
   - `FirstChild` = the **Cut markers block** (header + the Add-cut-at-playhead / POSITION wrap-row + marker `ListBox`).
   - `SecondChild` = the **Parts to export block** (header + "(N selected)" + All/None chips + segments `ListBox`).
   - `IsVertical="{Binding DataContext.IsVertical, RelativeSource Window, Converter={InverseBool}}"`.
   - `HorizontalRatio` / `VerticalRatio` **default 0.5** (true 50/50). Persisting these is optional (session-only /
     DP-default 0.5 is acceptable; add `AppSettings` fields only if trivial).
   - This nested panel sits as ONE region of the tool-panel Grid (fills the `*` space); file-info card (Auto) stays
     above it, Output + Run (Auto) below — unchanged. Each `ListBox` still scrolls internally within its region.
3. Verify BOTH modes: horizontal → markers above parts (50/50 height, current); vertical → markers | parts (50/50
   width, same row). The themed GridSplitter between them is draggable in both (like the outer panel).
4. **Re-parent, don't rewire** — all bindings intact (`SetCutAtPlayheadCommand`, `NewMarkerPosition`+`AddMarkerCommand`,
   `SelectAll/NoSegmentsCommand`, per-part `IsSelected`, `SeekToMarkerCommand`/`RemoveMarkerCommand`,
   `SelectedSegmentCount`, per-part progress). Don't touch the OUTER OrientedSplitPanel/D-001, the video region, Load/Clear (tab line), Output/Run logic.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Horizontal mode: Cut markers stacked ABOVE Parts, ~50/50 height (unchanged from D-003).
- [ ] Vertical mode: Cut markers and Parts SIDE BY SIDE on one row, ~50/50 width.
- [ ] Toggling the layout mode flips the markers/parts arrangement live (opposite to the main panel).
- [ ] The nested splitter is draggable in both modes; each list scrolls internally; all controls work; Run reachable.
- [ ] Build 0-warning; suite green (baseline 593); a converter unit test if `InverseBoolConverter` is added.
- Matrix — Success: horizontal=stacked, vertical=side-by-side, both 50/50. Boundary: mid-session toggle (live flip); narrow horizontal (still stacked, usable); many markers/parts (internal scroll each region). Required-Fail: none. (Exact look = app-run/user-verified.)

## Dependencies

## Risks
The inner `IsVertical` MUST be the inverse of the main one (get the flip direction right). Nested OrientedSplitPanel
needs a bounded region (the tool-panel `*` row gives it one). Don't disturb the OUTER panel or its ratio bindings.

## Out of scope
