## Concept
Move the Load / Clear buttons out of the top of each tool panel and onto the **Split/Join tab-strip row**,
**right-aligned** — so they sit on the same horizontal line as the "Split"/"Join" tabs, reclaiming a line in the
tool panel below. The empty space right of the two tab headers is the natural home.

## Design (grounded)
- **The tab row** is a `TabControl` in `MainWindow.xaml` (`:231-239`, two `TabItem`s, empty space to the right).
  Host a **right-aligned button group (Load / Clear) on that same row**. WPF approaches (build picks the cleanest):
  (a) a `Grid` at `MainWindow` Grid.Row=1 overlaying the tab strip — the `TabControl` + an `HorizontalAlignment=Right`
  button panel positioned over the tab-header band; or (b) retemplate the `TabControl` to add a right-hand content
  region beside the `TabPanel`. Align the button height to the tab-header height; use the themed button style.
- **Per-screen routing (the key wiring):** Load/Clear are per-screen today (Split → `LoadCommand`/`ClearCommand`;
  Join → its add/clear-all). Since the tab row is shared, bind the moved buttons to the **active screen's** commands:
  expose `CurrentLoadCommand` / `CurrentClearCommand` (+ tooltips/labels) on `MainViewModel`, resolved from
  `SelectedTabIndex` exactly like the existing `CurrentOperation` (T-068) — Split's on tab 0, Join's on tab 1. (Join's
  "Load" = add clips, "Clear" = clear all — label/tooltip follow the active screen.) `Load…` uses a file picker via
  code-behind today (`OnLoadClicked`) — route that through a command or a MainWindow-level handler that calls the
  active screen's load.
- **Remove** the old Load/Clear row from `SplitView.xaml` (`:130-141`) and the Join equivalent, reclaiming the line.
- Buttons disabled appropriately (Clear disabled while an op runs, as today).

## Acceptance criteria + Case-Coverage Matrix
- [ ] Load / Clear render right-aligned on the tab-strip line, same row as the Split/Join tabs; tool panels lose the top button row (a line reclaimed).
- [ ] They act on the ACTIVE screen — switch Split↔Join and Load/Clear drive that screen's load/clear (labels/tooltips follow).
- [ ] Behavior unchanged: Load opens the picker + loads; Clear resets; Clear disabled during a running op; drag-drop load still works.
- [ ] Composes with D-001 vertical mode (tab row is above the layout, mode-independent).
- [ ] Build 0-warning; suite green + a `MainViewModel` test that `CurrentLoad/ClearCommand` follow `SelectedTabIndex`.
- Matrix — Success: buttons on the tab line drive the active screen. Boundary: tab switch mid-session; op running (Clear disabled); narrow window (buttons + tabs coexist — may need the tabs to compress or the buttons to shrink). Required-Fail: none.

## Dependencies
None. Pairs with T-087 (both reshape the Split tool panel). Reuses the `SelectedTabIndex`/`CurrentOperation` pattern (T-068).

## Risks
TabControl header customization (overlay vs retemplate) + the per-screen command routing are the real work (hence M).
At a narrow window the tab headers + the two buttons must coexist without clipping — verify. Don't break drag-drop load
or the Clear-while-running guard.

## Out of scope
Restyling the tabs themselves; moving other tool-panel controls; the side-by-side lists (T-087).
