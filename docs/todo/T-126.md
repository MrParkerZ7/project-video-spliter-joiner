## Concept
Document the new precision choice, and fix the process failure that let a shipped fix stay invisible.

## Design
1. **SPEC** — a new/extended spec section for smart cutting: the head-fragment re-encode, the parameter
   matching, the fallback rule, and the invariant that the copy leg stays byte-identical. Update SPEC-011
   (Bulk screen) for the mode surface and SPEC-001's scope note (`SplitEngine` remains copy-only).
2. **USER_GUIDE** — explain plainly why a lossless cut moves to a keyframe and what Exact costs. This is
   the question the user actually hit; the guide should answer it before they have to ask.
3. **CHANGELOG** — the G-041 fixes + this epic.
4. **Process fix (the real lesson):** G-041 was committed, pushed, and tested-green while the app the user
   clicks was never rebuilt. Add a `verify` step to the build/dev loop so a UI-affecting change is
   rebuilt + relaunched before it is reported as done — a green suite is not evidence the user can see it.

## Acceptance criteria
- [ ] Specs describe smart cut + the fallback; SPEC-001's copy-only scope stays true.
- [ ] USER_GUIDE answers "why did my 5s cut become 4s?" directly.
- [ ] CHANGELOG updated.
- [ ] The rebuild-before-reporting rule is written down where the build loop will actually honour it.

## Out of scope
Re-cutting a release (that is `release-local`, once this epic converges).
