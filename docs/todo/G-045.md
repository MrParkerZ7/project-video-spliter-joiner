## Why

User: *"I can't do multi bulk cut, Invalid URI: The hostname could not be parsed."*

That string is .NET's, surfaced verbatim by `FfmeMediaPlayer`'s catch-all. Reproduced on this machine:
`new Uri(path, UriKind.RelativeOrAbsolute)` throws it when a UNC path's server name is not a legal URI
hostname — most realistically because it contains a **space** (`\\Seagate NAS\...`, `\\my nas\...`).
A mapped drive letter, an IP address, and hosts with dots or dashes all parse fine; only the space (and
a few other illegal-in-a-host characters) fails.

The cutting engine never touches `Uri` — it passes raw paths as process arguments and handles UNC
correctly. What breaks is the preview, and therefore the "Set intro-end here" / "Set outro-start here"
buttons, which are the normal way to place cuts. So the practical effect really is "I can't do bulk cut",
even though Run itself would work if the times were typed in by hand.

T-131 makes it legible and actionable now; T-132 makes it work.

## Out of scope
Non-file sources (http/rtsp). Changing how the engine addresses files — it is already correct.
