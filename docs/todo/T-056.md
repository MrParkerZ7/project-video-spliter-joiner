## Concept
Replace the default light Windows title bar with a themed dark+gold caption (app title + min/max-restore/close buttons) that still drags, resizes, and maximizes correctly.

## Design
- **`MainWindow.xaml`**: add `WindowChrome.WindowChrome` — `CaptionHeight="34"`, `ResizeBorderThickness="6"`, `GlassFrameThickness="0"`, `CornerRadius="0"`, `UseAeroCaptionButtons="False"`. Keep `WindowStyle="SingleBorderWindow"` (WindowChrome handles the maximize-taskbar case better with it) OR `None` + the WM_GETMINMAXINFO fix — pick the one that works and note it.
- Add a **custom caption row** at the top (its own Grid row, height 34, `BgBrush`/`SurfaceBrush`): app title/name on the left in `TextPrimaryBrush` with a small gold accent mark; on the right a horizontal stack of 3 caption buttons (minimize, maximize/restore, close), each `WindowChrome.IsHitTestVisibleInChrome="True"`. The rest of the row is draggable caption (default).
- **Caption buttons** (styles in `Themes/Controls.xaml` or MainWindow resources): flat, no rounded, ~46x34, dark; hover = `SurfaceHoverBrush`; **close hover = `DangerBrush`** (red) with light glyph. Glyphs via Segoe MDL2 Assets (``/``/``/``) or simple paths. Max button toggles glyph on `WindowState`.
- **Wire** the buttons: minimize → `WindowState=Minimized` (or `SystemCommands.MinimizeWindow`), max/restore → toggle `WindowState` Maximized/Normal + swap glyph, close → `Close()`. Double-click on the caption → toggle maximize; drag on caption → move (WindowChrome default).
- **Maximize correctness (the key gotcha):** a maximized WindowChrome window must not cover the taskbar. Handle it — either the `SingleBorderWindow`+WindowChrome combo (usually correct), or add a `WM_GETMINMAXINFO` hook clamping to the current monitor's work area (`MonitorFromWindow` + `GetMonitorInfo`). Also add a small content margin (`~7px` or `SystemParameters`) in the Maximized state so content isn't clipped by the invisible resize border.
- The window bg is already dark (G-017 implicit Window style) — the caption row completes the frame.

## Detail
- Keep everything else (the TabControl content) intact below the caption row.
- Resize must work on all 4 edges + corners (`ResizeBorderThickness`).
- App icon can appear in the caption left (optional).
- No Core/logic change — this is MainWindow chrome only.

## Acceptance criteria + Case-Coverage Matrix
- [ ] The window shows a dark themed caption (no light native title bar); app title + gold accent visible.
- [ ] Minimize, maximize/restore (glyph toggles), and close buttons work; caption drags the window; double-click caption toggles maximize.
- [ ] Maximized window does NOT cover the taskbar and content isn't clipped; restore returns to the prior size; resize works on all edges.
- [ ] Build 0-warning; prior tests green (chrome change → no logic/test change); app launches.
- Matrix — Required-Success: themed frame, all window ops work. Boundary: maximize on a monitor with the taskbar on each edge; restore; snap (drag to edge); minimize+restore. Required-Fail: n/a. (Live behavior is app-run/user-verified — headless can't render.)

## Dependencies
None (builds on the G-017 tokens).

## Risks
Maximize-covers-taskbar / resize edge cases (see Design) → handle WM_GETMINMAXINFO or use the SingleBorderWindow combo; verify maximize/restore live. Fallback: DWM dark native title bar if custom chrome regresses window behavior — but aim for the custom bar.

## Out of scope
Acrylic/mica backdrop, frameless, animations; docs (T-057).
