## Concept

The user turned **Auto-clear list** on, ran a batch that finished with no failures, and the list stayed. That is
the shipped behaviour: T-171 keeps a finished row when **(b)** its original is still on disk (✕ Delete originals
works from the rows) or when the run left a **warning** on it. In the default output mode — a new `_trimmed` file
beside each original, *Auto-delete originals* off — **every** finished row still has its original, so Auto-clear
clears nothing and only appends "Kept in the list: N originals left to delete", a line the user did not read. The
user's `settings.json` confirms the case: `BulkAutoClearAfterRun = true`, `BulkAutoDeleteOriginals = false`.

Warnings are the second trap. Lossless new-file runs put a planner note on many rows (an outro-only row's
"cut at 0:00 … ignored", a coarse-GOP "moved to the nearest keyframe"), and an exact cut whose codec cannot be
re-encoded falls back on every row — more often once T-186 remembers *Exact cut*. Keeping warned rows would keep the
list full for the same user.

**Other causes ruled out.** A batch with a *Skipped* row resolves to `CompletedWithFailures` and never auto-clears,
but no row reaches the engine as Skipped in practice: the view-model auto-disables a no-op row before Run, and the
screen never selects `CollisionPolicy.Skip` (only AutoSuffix or Overwrite, `BulkCutViewModel.cs` `RunBatchAsync`).

## Design

**What clears.** `RunAutoClearIfArmed` (unchanged gate: after `RunAutoDeleteIfArmed`, only on
`BulkBatchState.Completed`) clears **every row this run finished** (`RowState.Done`, still in the list), with one
exception: **when Auto-delete originals was armed**, a row whose original the sweep could not bin (it is still in
`DeletableOriginals()` after the sweep — "still in use") **stays**, because the user asked for it to go and
*✕ Delete originals* is how they retry once the holder lets go. Such a kept row is **unticked**, so the next Run does
not trim it again (the delete button works on Done rows regardless of the tick). Rows **not in this run** (unticked,
no cut yet, added while the batch ran) stay exactly as they are.

This reverses T-171 decision (b) for the auto-delete-off case, and drops the warned-row exception.

**What the summary says instead** — parts joined with ` · `, in this order:
1. the run's own line (`Trimmed N …`), unchanged;
2. the auto-delete sweep's line, unchanged (T-171 I162 already joins it);
3. **kept originals** (auto-delete off): `Cleared N from the list — their originals are still on disk`, where N counts
   the cleared rows whose original still exists and is not the output (`!FileFacts.Same(OutputPath, Path) &&
   FileFacts.Exists(Path)`); omitted when N is 0 (Replace originals, or every original binned);
4. **exact-cut fallbacks** among the cleared rows: `Not cut exactly (snapped to a keyframe): a.mkv, b.mkv` — up to three
   file names, then `and N more`. These are the only run warnings the user could not have seen before Run (the row
   showed its snap and GOP notes already), and the row is gone, so the summary is where they are said. Planner notes
   are not repeated. Identified by a shared constant, `BulkTrimEngine.ExactFallbackPrefix` (`"exact cut unavailable"`),
   used by both engine sites that write the warning and by the view-model — no free-text matching on a copy;
5. `Kept in the list: …` — only for rows still shown: `N original(s) still in use` (auto-delete on, refused) and
   `N not in this run`, each part only when non-zero.

**A manual delete keeps the report.** `DeleteOriginals()` currently replaces `ResultSummary`. While a completed run's
report is on screen (`BatchState == Completed`), a manual sweep's line now **joins** it with ` · ` exactly as the
automatic sweep's does — one shared helper for both — so pressing *✕ Delete originals* on a kept row after the
auto-clear never erases what the run trimmed. Otherwise it replaces the summary as today.

**Wording.** The checkbox tooltip becomes exactly:
*"After a batch finishes with no failures, take the videos it trimmed out of the list and keep its summary on screen.
Their originals stay on disk beside the outputs, where ✕ Delete originals can no longer reach them — tick Auto-delete
originals to have them binned, or leave this off to review first. Videos not in this run, and originals still in use,
stay in the list."*

## Acceptance criteria

- [ ] **Repro first (fails on the shipped code):** Auto-clear ON, Auto-delete OFF, Replace OFF, a clean batch of 3
      ticked rows writing new files, no warnings → `Items` is **empty** and the summary is exactly
      `Trimmed 3 · Cleared 3 from the list — their originals are still on disk`. The 3 originals still exist
      byte-identical and nothing reached the disposer.
- [ ] **Repro, warned rows (fails today):** the same batch where one row's result carries a planner note
      (`Cut at 0:00 is outside the file bounds … ignored`) and one carries an exact-cut fallback → `Items` is
      empty; the summary contains `Not cut exactly (snapped to a keyframe): <that file>` and does **not** repeat the
      planner note.
- [ ] Fallback names: 5 fallback rows → three names then `and 2 more`.
- [ ] One kept original → `Cleared 1 from the list — their originals are still on disk` (the count is the cleared
      rows' originals, not every original on disk).
- [ ] Auto-delete ON, one original binned and one refused (in use) → the binned row goes; the refused row **stays and
      is unticked**; the summary keeps the sweep's `Still in use` line and says `Kept in the list: 1 original still in
      use`; there is no `Cleared … originals` clause for the binned one.
- [ ] Then pressing *✕ Delete originals* on that kept row (the holder gone) bins it, and the summary still starts
      with `Trimmed 2` — the manual sweep joined the report.
- [ ] Auto-delete ON, all binned → list empty, no kept-originals clause. Replace ON → list empty, no kept-originals
      clause.
- [ ] An unticked row and a row added while the batch ran stay (ticks unchanged) and are counted `N not in this run`.
- [ ] A failed / cancelled / blocked batch clears nothing and adds nothing (unchanged). Auto-clear OFF → nothing
      clears (unchanged).
- [ ] After the clear, **Open folder** still reveals the run's first output (`LastRunOutputPath`); *✕ Delete
      originals* is disabled when no row is left.

## Out of scope

anything about cleared rows; Skipped rows (unreachable from this screen, see Concept).
