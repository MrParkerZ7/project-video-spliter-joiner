# (note) I think on bulk cut check-box on button feature isn't fully yet remember latest…

## 1 — As captured (verbatim — never edited)

> I think on bulk cut check-box on button feature isn't fully yet remember latest stage

## 2 — Clarification

**Read as:** the option checkboxes at the **bottom** of Bulk Cut (beside Run) do not all remember their last state.
**Confirmed:** three persist (*Auto-clear list*, *Auto-delete originals*, *and empty bin*); **Overwrite existing
output**, **Exact cut** and **Replace originals** reset to off every launch — they are plain fields, and the user's
`settings.json` holds none of them. The literal reading ("the check-box on/under the buttons" = *Apply to all ticked
videos* under the *Set … here* buttons) is ruled out: that one already persists and is in their file.

**Generated:** [T-186](T-186.md) — the three persist like the rest; Replace keeps its per-batch confirmation;
Overwrite (no confirmation, no Recycle Bin) shows a red *existing _trimmed files will be overwritten* clause in the
footer's destructive note while it is on, so remembering it is never silent.

**Clarified with:** a UX lens, a QA lens and an adversarial check (three rounds) — they added the red Overwrite note,
the check that restored values reach the batch options, and the stale ADR-0015 / SPEC-009 / SPEC-011 text.
