## Concept
The heart of the app: given an input and a set of cut points, produce N segments using `-c copy` — lossless, near-instant, no re-render — with every cut snapped to the nearest keyframe (D2).

## Design
- `ISplitEngine` / `SplitEngine` in `Core/Split`, on `IFfmpegRunner` + `IMediaProbe`.
- `SplitAsync(SplitRequest, IProgress, ct)` where `SplitRequest { InputPath, CutPoints[], OutputDir, NamingPattern }`.
- For each cut point: `SnapToNearestKeyframe` (T-003) → build segment ranges [snap_i, snap_i+1]. Extract each with `ffmpeg -ss <start> -i <in> -to <end> -c copy -avoid_negative_ts make_zero <out>` (use `-ss` before `-i` for fast seek at keyframes; segment boundaries are keyframes so copy is clean).
- Alternative single-pass mode: `-f segment -segment_times <t1,t2,...> -c copy` (faster, one process) — prefer this when producing all contiguous segments; fall back to per-segment for arbitrary subsets.

## Detail
- Output naming: `<basename>_part01.<ext>`, configurable pattern; never overwrite without a flag.
- Report per-segment + overall progress (map to T-002 progress fraction).
- Return `SplitResult { Segments[] { Path, Start, End, ActualStart (snapped), Delta } }` so the UI can show how far each cut moved.
- Preserve all streams (video+audio+subs) in copy.

## Interfaces / contracts
- Consumes: `MediaInfo` + keyframes + snap (T-003), runner (T-002).
- Produces: `SplitResult` for T-007 (UI) and T-009 (progress/errors).
- Contract: guarantees no re-encode — asserts `-c copy` in every invocation (unit-verify the built args contain `copy` and no encoder flags).

## Acceptance criteria + Case-Coverage Matrix
- [ ] Splitting at 2 points yields 3 segments whose durations sum to (≈) the original; each cut lands on a keyframe.
- [ ] Every ffmpeg invocation uses `-c copy` (no `-c:v libx264` etc.) — asserted in tests.
- [ ] `SplitResult` reports the snapped time + delta per cut.
- [ ] Segment-mode and per-segment mode produce byte-consistent playable outputs (smoke: outputs probe cleanly).
- Matrix — Required-Success: valid cuts → correct segment count + playable + no re-encode. Required-Fail: cut at 0 or ≥ duration → rejected/clamped with message; overlapping/duplicate cuts → deduped. Optional-Success: single cut → 2 parts. Boundary: cut exactly on a keyframe (delta 0); source with sparse keyframes (large delta surfaced); cancel mid-split leaves no half-written final segment (temp-then-rename).

## Edge cases
Cut before first / after last keyframe; duplicate cuts; unsorted cuts (sort first); cancel mid-run; output dir not writable.

## Dependencies
T-003 (snap + info), T-002 (runner).

## Risks
`-c copy` cuts can produce a slightly-off first-segment start on some containers (`-avoid_negative_ts`). Mitigation: use segment muxer where possible; smoke-probe outputs.

## Out of scope
UI, detection, join.
