## Concept
The user asked "where's the apply-to-all button?" — both exist but are hard to find after the recent regroup + the added
thumbnail columns. Make the apply-to-all affordances **clearly findable + labelled** so they read as "apply to all" at a
glance, in both layout modes.

## Grounding (2026-08-23 — present but not discoverable)
- **Per-row apply-to-all** — `BulkCutView.xaml:713`, row DataTemplate **column 6**, a compact **⧉** button binding
  `DataContext.ApplyToAllCommand` (copies THIS row's cut points to all others). After T-108 added the cut-point thumbnail
  columns and T-113/T-112 reflowed the row, this small icon can be cramped / clipped — especially in horizontal mode where
  the row list is narrower.
- **Profile apply-to-all** — `:255`/`:260`, the profiles card's paired split-control **"⧉ selected" / "⧉ all"** (binds
  `ApplyProfileToSelectedCommand`/`ApplyProfileToAllCommand`). "⧉ all" is terse; a user scanning for "Apply to all" may miss it.

## Fix (investigate visibility first, then improve — UI Designer lens)
1. **Verify visibility in BOTH modes** — confirm the per-row ⧉ (col 6) is actually visible + not clipped when the row
   carries the two cut-point thumbnails + in horizontal (narrow-list) mode. If it's being squeezed/clipped, fix the row
   layout so it's always reachable (a stable Auto column, not squeezed by the `*` scrub column; wrap or a compact overflow
   if truly tight).
2. **Make it read as "apply to all"** — the per-row control: keep the `⧉` glyph but add a clear label or a strong tooltip
   ("Apply this row's cuts to all rows"); consider a slightly more prominent affordance (it's a common gesture). The
   profile control: relabel "⧉ all" → "⧉ Apply to all" (or "Apply → all") + tooltip so it's unambiguous; keep it grouped in
   the Profiles card (T-113).
3. **Consistent placement** — the per-row ⧉ in a stable spot on every row (aligned), findable at a glance; the profile
   apply-to-all clearly the primary apply action in its card.
4. **No behavior change** — same commands (`ApplyToAllCommand`, `ApplyProfileToAllCommand`), same semantics (the T-111 fix
   keeps them re-firing). Pure View/label/layout — this is discoverability, not new behavior.

## Acceptance criteria + Case-Coverage Matrix
- [ ] The per-row apply-to-all (⧉) is visible + reachable on every row in BOTH layout modes (not clipped by the thumbnail columns / narrow horizontal list) and reads clearly as "apply this row's cuts to all" (label/tooltip).
- [ ] The profile apply-to-all reads unambiguously as "apply to all" (relabelled from the terse "⧉ all") in the Profiles card.
- [ ] Both remain on-theme (tokens) + consistent with the app's icon vocabulary; no command/behavior change (all still fire).
- [ ] Works with the T-108 thumbnails + T-112 layout modes + T-113 profiles card; per-row scrub still fits.
- [ ] Build 0-warning; suite green (879 — view/label-only; existing tests stay green).
- Matrix — Success: user can find + use "apply to all" without hunting, both per-row and profile. Boundary: narrow horizontal-mode row (⧉ still reachable), many thumbnails on a row, long profile name (button not pushed off). Required-Fail: none. (Look = app-run/user-verified.)

## Dependencies
None on VM logic. Coordinates with T-112 (layout) + T-113 (profiles card) — same `BulkCutView`. Reuses tokens/icon styles.

## Risks
Don't crowd the row further — improving discoverability must not push other controls off in horizontal mode; balance label
vs space (a strong tooltip + a stable column may suffice if a full label doesn't fit). Keep the ⧉ glyph the user is now
partly familiar with; add clarity, don't fully replace the vocabulary.

## Out of scope
The selection-perf fix (T-115); new apply behaviors; the apply-to-all re-activation (already fixed in T-111).
