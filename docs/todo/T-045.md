## Concept
Show roughly how long until the operation finishes — "~1 min 20s left" — derived from real elapsed time vs progress, so the user knows what to expect.

## Design
- **`OperationViewModel`** (or a small `EtaEstimator` helper): when an op starts, start a `Stopwatch`. On each progress update (fraction `f`, 0<f<1), compute `remaining ≈ elapsed × (1 − f) / f`. Expose `EtaText` ("~1m 20s left" / "~15s left") + optionally `ElapsedText`.
- **Smooth it:** use a moving average / EMA of the rate so the ETA doesn't jump wildly on nonlinear `-c copy` progress. Prefix "~" and round to a friendly granularity (seconds under a minute, else `Nm Ss`). Don't show a precise-looking number.
- **Graceful degrade:** if progress is indeterminate / not granular (no usable fraction), show "estimating…" (or just the stage from T-044) instead of a fake ETA. Very early (f≈0) → "estimating…" until there's a usable rate.
- Clear `EtaText` on success/fail/cancel.
- **UI:** show `EtaText` next to the progress bar + `StatusText` (T-044).

## Detail
- `Stopwatch` is fine in the app (the workflow-script Date.now restriction does NOT apply to product code).
- Pure math (elapsed + fraction → remaining, formatting) → unit-test the `EtaEstimator` with synthetic elapsed/fraction sequences (monotonic-ish, clamps, formatting).
- Tie into T-044's status so stage + ETA read together: "Splitting (segment 2 of 4) — ~40s left".

## Interfaces / contracts
- `OperationViewModel.EtaText` (+ maybe `ElapsedText`) fed by a testable `EtaEstimator`. No engine change beyond the progress it already reports.

## Acceptance criteria + Case-Coverage Matrix
- [ ] `EtaEstimator`: given elapsed 10s at 25% → ~30s remaining (±smoothing); formatting "~30s", "~1m 20s"; f≈0 → "estimating…"; f≥1 → cleared. (unit)
- [ ] During a running op the VM exposes a non-empty `EtaText` once progress is usable, and clears it on completion.
- [ ] Indeterminate progress → "estimating…" not a fake number.
- [ ] Build 0-warning; prior tests green.
- Matrix — Required-Success: steady progress → sane decreasing ETA. Boundary: near-0 and near-100%; instant op (ETA barely shows, clears); stalled progress (ETA grows, doesn't crash). Required-Fail: op fails → ETA clears.

## Dependencies

## Risks
Jittery ETA → smoothing + "~". Divide-by-zero at f=0 → guard (estimating…).

## Out of scope
