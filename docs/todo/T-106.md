## Concept
Let a `CutProfile` carry an OPTIONAL thumbnail image (a recognizable label). This task is the MODEL + PERSISTENCE + the
file store — no UI (T-107). Backward-compatible: existing profiles (no thumbnail) load unchanged.

## Grounding (real signatures)
- `record CutProfile(string Name, TimeSpan IntroFromStart, TimeSpan? OutroFromEnd)` — `src/Core/Profiles/CutProfile.cs:25`
  (validating `init`s). Add an optional `ThumbnailPath` (string?, nullable — null = no thumbnail).
- `AppSettings` (`src/App/Settings/AppSettings.cs`): `CutProfileDto` round-trips `Name`/`IntroSeconds`/`OutroSeconds?`
  (`:340` write, `:242` MapProfiles read, backward-compat: absent field → default). SaveProfile upsert-by-name.
- Thumb-cache precedent: `IThumbnailService`/`FfmpegThumbnailService` store frames under
  `%LOCALAPPDATA%/VideoSplitJoiner/thumb-cache` (SPEC-005 I25 `DefaultCacheRoot`). Mirror the folder-composition + OS-temp fallback.

## Design
1. **`CutProfile.ThumbnailPath`** — add `string? ThumbnailPath` to the record (optional, validated non-crashing: a
   null/blank → null; no existence check at model level — the store owns the file). Keep the existing validation.
2. **DTO round-trip** — add `ThumbnailPath` (string?) to `CutProfileDto`; write it in the Save projection, read it in
   `MapProfiles`. **Backward-compat:** an older settings file with no `thumbnailPath` field → `null` (no crash, no loss).
   Store the PATH (absolute or %LOCALAPPDATA%-relative — pick one, be consistent), never image bytes in the JSON.
3. **`ProfileThumbnailStore`** (new, App — it does file I/O) — 
   - `string Save(string profileName, string sourceImageOrFramePath)` → copies the source image (an uploaded file OR a
     captured frame jpg from `IThumbnailService`) into `%LOCALAPPDATA%/VideoSplitJoiner/profile-thumbs/<safe(profileName)>.png`
     (or `.jpg`), returns the stored path. Overwrites the profile's prior thumbnail (rename-on-profile-rename optional).
   - `void Delete(string profileName)` / `void DeleteByPath(string path)` — remove the file when a profile is deleted or
     its thumbnail cleared. Best-effort (never throws on a missing/locked file).
   - `DefaultRoot()` mirrors the thumb-cache root composition (LocalAppData + OS-temp fallback). Safe filename sanitization.
   - Wire `DeleteProfile` (T-102's `AppSettings.DeleteProfile`) to also `Delete` the profile's thumbnail file.
4. Keep `CutProfileApplier` unaffected (thumbnail is metadata, not a cut offset).

## Acceptance criteria + Case-Coverage Matrix
- [ ] `CutProfile.ThumbnailPath` (string?, optional) exists + validates without crashing; persists through the JSON round-trip (Save→Load returns the same path; upsert keeps it).
- [ ] Backward-compat: an older settings JSON with no `thumbnailPath` loads → `null`, other fields intact (no crash/loss).
- [ ] `ProfileThumbnailStore.Save` copies a source image/frame into `%LOCALAPPDATA%/…/profile-thumbs/<safe-name>.*` and returns the path; `Delete`/`DeleteByPath` remove it best-effort; `DeleteProfile` cascades to the thumbnail file.
- [ ] `serves-spec: SPEC-007` on new tests; tokens/paths only; no image bytes in settings JSON.
- [ ] Build 0-warning; suite green (baseline 819) + tests: round-trip with/without thumbnail, backward-compat load, Save/Delete/cascade, safe-name sanitization, best-effort on missing file.
- Matrix — Success: save a profile with a thumbnail, reload → path preserved + file present. Boundary: no-thumbnail profile (null), older file (absent field→null), delete-profile removes file, duplicate/odd profile name (sanitized), missing file on Delete (no throw). Required-Fail: none.

## Dependencies
Extends T-102 (CutProfile + AppSettings persistence) + reuses the thumb-cache root pattern (SPEC-005). Consumed by T-107 (UI).

## Risks
Keep it backward-compatible (additive DTO field). Sanitize the profile name → filename (invalid chars, collisions). The
store is best-effort (a missing/locked thumbnail file must never break save/load/apply). Decide absolute-vs-relative path
storage and stick to it (relative-to-LocalAppData survives a moved profile-thumbs root; absolute is simpler — pick + note).

## Out of scope
The upload/clear UI + auto-default capture + ComboBox display (T-107); the per-row cut-point thumbnails (T-108).
