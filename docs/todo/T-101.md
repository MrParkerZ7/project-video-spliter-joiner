## Concept
Add a **preview pane** to the Bulk Cut tab that plays the selected row's video with a timing bar + jog buttons, and lets
you **set the selected row's intro-end / outro-start from the playhead** — so cuts can be placed by watching, precisely,
not blind. Reuses the Split tab's player + jog + timeline wholesale (T-100 wired the shared `Player`).

## Grounding (real reuse)
- `PlayerView.xaml` (`src/App/Views/PlayerView.xaml`) — the transport UI (play/pause, scrub slider, position/duration,
  the jog button row). Its jog buttons already bind `SkipCommand` with second params: `-1200/-600/-300/-60/-20/-10/-5/-1`
  and `+1/+5/+10/+20/+60/…` (PlayerView.xaml:127-169). **Reuse this control** bound to `BulkCut.Player`.
- `TimelineView` (`src/App/Views/TimelineView.xaml` + `.cs`) — the normalized playhead strip (`PlayheadNormalized`,
  click-to-seek `SeekMarkerTick`). Reuse as the bulk timing bar (bound to the shared player / selected row's markers).
- `BulkCut.Player` (PlayerViewModel) + `BulkCut.SelectedItem` (BulkItemViewModel) — from **T-100**.
- Setting a cut = write the selected row's `IntroEnd.Requested` / `OutroStart` from `Player.Position` (the
  `CutMarkerViewModel.Requested` setter re-snaps to the row's keyframes automatically — same path the scrub handles use).
  Precedent: Split's `SetCutAtPlayheadCommand`.

## Design
1. **Pane placement** — a preview region at the TOP of the Bulk tab (above the row list), visible when a row is selected;
   an empty/hint state ("select a video to preview") when `SelectedItem == null`. Respect vertical/horizontal layout modes
   if trivial (else a fixed top pane). Keep the row list + per-row scrub bars (T-097) intact below.
2. **Player + timeline** — embed `PlayerView` bound to `BulkCut.Player`; below/around it the `TimelineView` (or the player's
   own scrub) as the timing bar. The jog button row (±1s/5s/10s/20s/1m − and +) comes from PlayerView's existing set.
3. **Set-at-playhead** — two prominent buttons in the pane:
   - **"Set intro-end here"** → `SelectedItem.IntroEnd.Requested = Player.Position` (snaps); updates the row live.
   - **"Set outro-start here"** → if no outro, `SelectedItem.AddOutro(Player.Position)`, else set `OutroStart.Requested`.
   Both disabled when no `SelectedItem`/not `IsReady`. A small "▸ play to the intro end, then set" hint. Style the two like
   the HeroButton accent (they're the pane's primary gesture) but distinct from the batch Run button.
4. **Two-way selection** — clicking a row selects it (drives the pane); the pane reflects the selected row's current
   intro/outro as playhead markers on the timing bar (reuse the timeline marker overlay) so you see where the cuts sit.
5. **Playback discipline** — pane stops/pauses when a batch run starts (T-100 hook) and when the tab is inactive.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Selecting a Bulk row shows a preview pane playing that video; play/pause + the ±1s/5s/10s/20s/1m jog buttons work (reused PlayerView).
- [ ] "Set intro-end here" / "Set outro-start here" write the selected row's cut from the playhead, keyframe-snapped, reflected live on the row's scrub bar + the pane timing bar.
- [ ] No selection → hint state; batch run / tab-inactive → playback stops; the per-row scrub bars still work.
- [ ] View-only (no VM logic beyond binding to T-100's Player/SelectedItem + the existing CutMarkerViewModel.Requested); WPF-free VMs unchanged.
- [ ] Build 0-warning; suite green; a small MainViewModel/VM test if any binding-glue logic is added (the set-at-playhead command if it lands in the VM).
- Matrix — Success: watch → jog → set intro/outro precisely. Boundary: no selection (hint), player not ready yet (buttons disabled), set outro when none exists (AddOutro), switch rows mid-play (pane re-anchors via T-100 guard). Required-Fail: none. (Look/feel = app-run.)

## Dependencies
Needs **T-100** (SelectedItem + shared Player). Reuses PlayerView/TimelineView/SkipCommand + CutMarkerViewModel.Requested.

## Risks
Layout pressure — the pane + row list must both fit; consider a splitter or a compact pane. Don't regress the row scrub
bars or the mode-aware layout. The "set-at-playhead" command: if it needs VM logic, keep it WPF-free (a command on
BulkCutViewModel taking the selected row + player position), not code-behind reaching into the player.

## Out of scope
Profiles (T-102/103); per-row players; frame-stepping precision beyond the existing StepForward/Back; playback speed.
