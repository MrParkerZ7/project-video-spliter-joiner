**Feature facts to document (from D-004 `README.md` + `core-flow.md`, sealed):**
- Third tab `SelectedTabIndex == 2`, sibling to Split (0) / Join (1). Per-row dual-handle scrub bar: gold intro-end (`▸`, required-ish) + optional blue outro-start (`◂`); keep the middle `[intro-end → outro-start | EOF]`.
- Output `<source dir>/<name>_trimmed<ext>`; **originals never touched**; collision default **AutoSuffix** (`_trimmed_2/_3`) + per-run **Overwrite** toggle.
- **Apply-to-all**: intro-end applies as absolute time-from-start; **outro-start applies as time-from-END** (`Duration − outroStart`) so uneven-length series align; each target **re-snaps + re-validates** and reports (not silently drops) rows it invalidates.
- Batch is **sequential** (v1), **failure-isolated** (one bad row never aborts the batch), **cancel sweeps only the in-flight temp**; done rows kept.

**Core-insight / reuse facts to state in ARCHITECTURE + ADR (from the reuse map — cite signatures verbatim, do not re-invent):**
- `ISplitEngine.SplitAsync(SplitRequest req, IProgress<double>? progress, CancellationToken ct, IProgress<OperationStatus>? status, IProgress<PartProgress>? partProgress)`; internal `ExtractSelectedPerSegment` → `SplitArgsBuilder.PerSegment(input, TimeSpan start, TimeSpan? end, tempOut)`: `-ss` before `-i`, `-c copy`, `-avoid_negative_ts make_zero`; final/EOF part omits `-to`; `-to` passed as **duration** (`end−start`).
- `SplitRequest(string InputPath, IReadOnlyList<TimeSpan> CutPoints, string OutputDir, string NamingPattern="{name}_part{index:00}{ext}", bool Overwrite=false, IReadOnlyList<int>? SelectedSegmentIndices=null)` — Bulk sets `NamingPattern="{name}_trimmed{ext}"`, `CutPoints=[introEnd(,outroStart)]`, `SelectedSegmentIndices=[kept middle]` (or bypasses it — see index risk).
- `SplitPlanner.Plan(...)` DROPS cuts ≤0/≥duration, MERGES within ~10ms, DROPS a snap colliding with a neighbour ⇒ the kept 1-based index is **not always 2** (the "index risk"). Cure per design: a pure `KeptSegmentSelector.ResolveKeptIndex(...)` post-plan, **or** emit one `PerSegment([introEnd..outro|EOF])` directly bypassing `SelectedSegmentIndices`.
- `MediaProbe` (shared instance): `ProbeAsync`→duration; `GetKeyframesAsync` (cached by `(path,mtime,length)`, in-flight-deduped); `SnapToNearestKeyframe(kf,t)`→`KeyframeSnap(TimeSpan Snapped, TimeSpan Delta)` (ties→earlier, clamp); `AverageGop(kf)`.
- `CutMarkerViewModel` — **two per row** (intro-end required, outro-start optional/nullable); live `Requested→Snapped (±Δ)` display.
- `OperationViewModel` — **one per row** + **one aggregate** on the tab VM (taskbar/title bind ONE `CurrentOperation`).
- New VMs: `BulkCutViewModel` (list + aggregate op + apply-to-all + `RunBatchAsync`), `BulkItemViewModel` (Join-item shape + two `CutMarkerViewModel` + per-file keyframes + own `OperationViewModel` + `BuildRequest()`), `BulkCutView` (view-only Canvas render, keeps `CoreIsUiFreeTests` green); optional Core `BulkTrimEngine` + `KeptSegmentSelector`; one new token `DropScrimBrush`.
- Safety: `SatisfiesCopyInvariant` + `ForbiddenEncoderTokens` asserted before launch; `FfmpegErrorMapper`, `ErrorLogWriter`, `EnsureEnoughFreeSpace` reused per-row.
- **Verify against shipped code before writing:** the ADR/ARCHITECTURE must state which of the two index-risk cures actually shipped (`KeptSegmentSelector` vs direct `PerSegment`), and whether `BulkTrimEngine` landed in Core or the loop stayed in the VM. Read `src/App/ViewModels/BulkCutViewModel.cs` + `src/Core/` for the final shape; document what shipped, not both options.

2. **`docs/adr/0015-bulk-trim-reuses-split-single-segment.md`** — author the ADR (immutable; follow `0001`'s structure):
   - `# ADR 0015: Batch intro/outro trim reuses SplitEngine's single-segment path — no second ffmpeg code path`
   - `## Status` → Accepted.
   - `## Context` — the forces: the app's whole reason to exist is lossless `-c copy` (ADR 0001); a bulk trim is structurally *a Split that keeps exactly one middle segment*; a second ffmpeg path would double the surface that must uphold the copy invariant, keyframe-snap, temp-then-move cancel-safety, and disk pre-flight. Reference D-004 + the reuse map.
   - `## Decision` — one bullet each: (a) **reuse `ISplitEngine.SplitAsync` / `SplitRequest` wholesale**, one kept-middle segment per row (`CutPoints=[introEnd(,outroStart)]`, `NamingPattern="{name}_trimmed{ext}"`); no new args-builder, no new engine method — cite the `PerSegment` `-ss`/`-c copy`/`-avoid_negative_ts make_zero`, `-to`=duration, EOF-omits-`-to` facts. (b) **the kept-index cure that shipped** (state the one that actually landed — `KeptSegmentSelector.ResolveKeptIndex` post-plan **or** direct single `PerSegment` bypassing `SelectedSegmentIndices` — with the `SplitPlanner` drop/merge/snap rationale for why the index isn't always 2). (c) **apply-to-all outro measured from END** (`Duration − outroStart`), intro absolute-from-start — so uneven-length series align; each target re-snaps + re-validates. (d) **collision default AutoSuffix** (`_trimmed_2/_3`) + per-run Overwrite; source never clobbered. (e) **sequential, failure-isolated batch**; cancel sweeps only the in-flight temp, done rows kept.
   - `## Consequences` — **Positive** (one copy-invariant choke-point; correctness inherited free; each row independent ⇒ failure isolation + mixed codecs fall out naturally); **Negative** (kept-index math is a real edge to test; aggregate `OperationViewModel` needed since taskbar/title bind one `CurrentOperation`; N-file keyframe-scan thundering-herd to throttle); **Forced follow-ons** (Bulk must resolve pending snaps before building requests else it cuts on identity times; apply-to-all must report, not silently drop, invalidated rows; `CoreIsUiFreeTests` stays green — new Core types reference no WPF).
   - Append the index row to `docs/adr/README.md`: `| [0015](0015-bulk-trim-reuses-split-single-segment.md) | Batch intro/outro trim reuses SplitEngine's single-segment path — no second ffmpeg code path | Accepted |` and update the "records 0001 through 0014" prose to "through 0015".

4. **`docs/USER_GUIDE.md`** — add `## Bulk Cut` after `## Join clips`, in the numbered-step Split voice:
   1. **Add videos** — multi-select or drag-drop; a scrollable list, one row per video; dedup by path; the empty-state hint + gold/blue legend.
   2. **Mark cut points per row** — gold intro-end handle (drop the intro) + optional blue outro-start handle (`[+ outro]` when unset ⇒ keep to end); the kept middle glows gold; hover shows a frame preview. `IN`/`OUT` readouts editable, keyframe-snapped on commit.
   3. **Apply to all** — copy one row's cut points to every other row; **the outro is measured from the end**, so same-series episodes of different lengths line up; rows where the copied time doesn't fit are flagged, not silently dropped.
   4. **Run** — trims all enabled rows one after another; per-row + overall progress on the taskbar/title; **one bad row never stops the batch** (it's reported at the end with a Retry-failed option); Cancel keeps finished files and rolls back only the one in progress.
   5. **Output** — `<name>_trimmed<ext>` in the **same folder as the source**; **originals are never touched**; a name collision auto-suffixes (`_trimmed_2`) unless you tick Overwrite.
   - Reuse/point to `### Why cuts snap to keyframes` for the snap caveat (intro/outro snap to the nearest keyframe; the snapped time is the real cut and is always shown) rather than restating it in full.
