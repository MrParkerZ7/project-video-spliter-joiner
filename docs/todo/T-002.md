## Concept
The single choke-point through which all ffmpeg/ffprobe execution flows: locate the bundled binaries, run a command, stream stdout/stderr, surface progress + exit status, and never leak a raw process detail to callers. Every engine (split/join/detect) is built on this.

## Design
- `IFfmpegRunner` / `FfmpegRunner` in `Core/Ffmpeg`. Wraps `System.Diagnostics.Process` with `RedirectStandardError = true` (ffmpeg writes progress/logs to stderr), async line reading, and a `CancellationToken` that kills the process tree.
- Binary resolution order: app-local `ffmpeg/` folder (bundled) → `PATH` fallback → clear "ffmpeg not found" error. Same for `ffprobe`.
- Progress parsing: parse `-progress pipe:` / `time=` tokens from stderr into a `0..1` fraction against a known total duration (duration passed in by caller from T-003).
- Result type `FfmpegResult { ExitCode, StdErrTail, Success }`; failures carry the last N stderr lines for T-009 to render.

## Detail
- `RunAsync(FfmpegArgs args, IProgress<double>? progress, CancellationToken ct)`.
- Argument building via a typed `FfmpegArgs` builder (no string concatenation of user paths — quote/escape safely; paths with spaces/unicode must work).
- Kill-on-cancel: terminate the whole process tree (ffmpeg spawns no children normally, but be safe on Windows).
- A `FfprobeRunner` sibling returning raw JSON (`-print_format json`) for T-003 to deserialize.

## Interfaces / contracts
- Produces: `IFfmpegRunner`, `IFfprobeRunner`, `FfmpegArgs`, `FfmpegResult` — consumed by T-003 (probe), T-004 (split), T-005 (join), T-006 (detect).
- Contract: never throws on non-zero exit — returns a `FfmpegResult` with the stderr tail; throws only on "binary not found" / cancellation.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Runs a bundled ffmpeg `-version` and returns success.
- [ ] Parses `time=` progress into a monotonic 0..1 fraction (unit-tested against captured stderr fixtures).
- [ ] Cancellation kills the process within ~1s; `RunAsync` returns cancelled.
- [ ] Missing-binary path returns a typed, friendly error (not an OS exception bubbling up).
- Matrix — Required-Success: valid command → exit 0 + parsed progress. Required-Fail: bad args → non-zero exit captured with stderr tail (no crash); missing binary → typed error. Optional-Fail: cancel mid-run → clean kill. Boundary: input path with spaces + non-ASCII chars; zero-duration input (progress stays 0..1 safe).

## Edge cases
Path with spaces/unicode; process that never emits `time=`; instant-exit command; cancel before start.

## Dependencies
T-001 (project graph). The actual ffmpeg binary is bundled/located here; the packaging of it is T-010.

## Risks
stderr progress format varies by ffmpeg build. Mitigation: prefer `-progress pipe:1` structured output; fixture-test the parser.

## Out of scope
Any split/join/detect logic (later tasks) — this only runs commands + parses.
