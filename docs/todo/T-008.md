## Concept
The join workflow surface: gather clips, order them, see a clear compatibility verdict before running, then join into one file — or get told exactly why the set can't be stream-copied together.

## Design
- WPF `JoinView` + `JoinViewModel` binding to `IJoinEngine` (T-005) + `IMediaProbe`.
- Ordered list (drag-drop add + reorder), per-item info chip (codec/res), and a live `CompatReport` banner (green = joinable, red = names the mismatch).

## Detail
- Add via picker/drag-drop; remove; reorder (drag or up/down).
- On list change, run the pre-flight compat check (T-005) and render the verdict; disable Run when incompatible.
- Output path picker + overwrite guard; Run → progress + cancel; on done, open-folder.

## Interfaces / contracts
- Consumes: `JoinEngine.JoinAsync` + its `CompatReport`, `MediaProbe`.
- Produces: hands an ordered `JoinRequest`; renders `JoinResult` or the refusal.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Add 3 compatible clips → green verdict → join → one playable output.
- [ ] Add an incompatible clip → red verdict naming it → Run disabled.
- [ ] Reorder changes output order.
- Matrix (action coverage) — controls (add, remove, reorder, choose-output, run, cancel, open-folder) each tested. Required-Fail: <2 files → Run disabled/prompted; incompatible set → refused with reason. Boundary: exactly 2 files; duplicate file added twice; single file (passthrough or blocked with note).

## Edge cases
Fewer than 2 files; incompatible set; duplicate entries; cancel mid-join.

## Dependencies
T-001 (shell), T-005 (join engine + compat).

## Risks
Users confused by refusal. Mitigation: the compat banner explains the exact mismatch + that v1 never re-encodes.

## Out of scope
Split screen (T-007); any force-recode path.
