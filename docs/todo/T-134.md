## Reported
> why run bulk cut is execute cut only one file? bulk is mean single or what? why it's execute only file?

## Root cause
Not a bug in Run — it cut every row that had a cut, and only one did (T-133). The defect is that **nothing
said so**. The information existed: the button reads `Run bulk cut (N)` and each excluded row carries an
`ExclusionReason` since T-127. It was not enough, from a real user, in the real UI.

T-133 removes the common cause. This ticket makes the remaining cases legible, so "it only cut one" can
never again be something the user discovers *afterwards*.

## Design
1. **State the count where the decision is made, not only on the button.** With N imported and fewer
   eligible, show a plain line near Run: *"Will cut 1 of 12 — 11 rows have no cut set."* Reuse the
   existing `ExclusionReason` groupings rather than inventing new wording.
2. **Make the shortfall visible, not just available.** A count that silently equals 1 when the list holds
   12 is the exact state that produced this report; it should read as a warning, not as neutral text.
3. Keep it truthful for the legitimate cases — a user who deliberately unticked ten rows should see a
   calm statement of the count, not an alarm.
4. **Decision on a confirm dialog: NO.** The shortfall is now stated where the button is, and the
   surprising case is visually weighted. A modal would interrupt every legitimate partial batch to
   guard against a case the line already answers — that is a dialog added by reflex, which this step
   existed to prevent.

## Acceptance criteria
- [x] With rows loaded and fewer eligible, the count and the reason are visible without hovering or
      opening anything.
- [x] The wording distinguishes "nothing to trim yet" from "you unticked these".
- [x] Nothing is claimed that the row data does not support — the summary is derived from
      `ExclusionReason`, never hard-coded.
- [x] Performance: the summary is O(N) over rows already in memory and recomputes on the same
      notifications `RunLabel` already uses — no new scan, no new probe.
- [x] SPEC-011 updated; rebuilt and relaunched.
- [ ] Verified by hand with a partly-eligible batch (yours).

## Out of scope
Auto-fixing the excluded rows. That is T-133's job, and doing it here would hide the very state this
ticket exists to surface.
