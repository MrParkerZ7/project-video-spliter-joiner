## Concept
One gesture to tick or untick every row, so a big import does not mean N clicks. The Split screen already
has this for its parts list; Bulk has nothing.

## Reported
> bulk cut should have select all/dis select all for item list

## Prior art in this codebase — match it, do not invent a second idiom
`SplitViewModel` already ships the pair, and the naming/enablement should mirror it:

```csharp
SelectAllSegmentsCommand = new RelayCommand(_ => SetAllSegmentsSelected(true),  _ => Segments.Count > 0);
SelectNoSegmentsCommand  = new RelayCommand(_ => SetAllSegmentsSelected(false), _ => Segments.Count > 0);
```

## Blocked by T-127 — deliberately
Select-all must set the **user-intent** property, not the computed `IsEnabled` getter. Building it before
T-127 separates the two would reproduce the same bug at batch scale: "select all" would appear to do
nothing on freshly imported rows, because every write of `true` hits the setter's `!=` short-circuit.

## Design
1. Two commands on `BulkCutViewModel` (`SelectAllItemsCommand` / `SelectNoItemsCommand`), each writing the
   T-127 intent property across `Items`, enabled while `Items.Count > 0 && !Operation.IsRunning`.
2. Place them on the item-list header near the count, consistent with the Split screen's placement.
3. Decide and document one rule: does "select all" tick rows the app has auto-excluded? Recommendation:
   **yes, set the intent** — intent and eligibility are separate after T-127, so an auto-excluded row
   simply stays excluded-with-a-reason until it has a real cut, and the user's intent is preserved for
   when it does. This also makes select-all + "apply profile to all" compose the way the user expects.
4. Raise the batch-level `CanRunBatch` / `RunLabel` / profile-command CanExecute notifications once for the
   bulk write rather than per row.

## Acceptance criteria
- [ ] Select all / deselect all act on every row in one gesture; "Run bulk cut (N)" updates once.
- [ ] Both commands disable on an empty list and during a run.
- [ ] The chosen auto-excluded-row rule is documented in SPEC-011 and covered by a `serves-spec` test.
- [ ] A performance assertion per the testing standard: the bulk write is O(N) with no per-row heavy work
      (no probe, no thumbnail grab, no re-scan triggered by select-all).
- [ ] Rebuilt + relaunched, and the gesture verified by hand.

## Out of scope
Range selection, shift-click, or a tri-state header checkbox.
