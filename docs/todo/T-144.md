## Reported
> on bulk cut I also want button delete all selected, target is to remove all original file to save more
> space, it should available only when bulk cut process done

## What this is

After trimming a batch, the originals are still on disk beside the `_trimmed` outputs — for a folder of
episodes that is roughly double the space, which is the whole reason for asking. One button to bin the
originals whose trim actually succeeded.

**This deletes the user's video files. It is the most destructive thing in the app**, so the design below
is mostly about what it must refuse to do.

## Reuse, do not reinvent
| need | exists |
|---|---|
| bin a file recoverably | `RecycleBinOriginalDisposer` / `IOriginalDisposer` (T-122) |
| know which rows succeeded | `RowState.Done` from `ApplyResult`, plus `OutputPath` and `SizeAfter` |
| counted confirmation | `ConfirmReplaceOriginals` — same shape, defaults to **No** |
| "no run in flight" gate | `Operation.IsRunning`, as `CanChangeSelection` uses |

## Safety rules — each one is a way this could destroy someone's footage

1. **Only `RowState.Done` rows.** Never a failed, skipped, cancelled, or not-started row.
2. **Verify the output at delete time, not from remembered state.** The output file must exist AND be
   non-empty *when the button is pressed*. State from the run is minutes old; the user may have moved or
   deleted the output in between.
3. **Never when the output IS the original.** Under `OutputMode.ReplaceOriginal` the original has already
   become the output — deleting it destroys the only copy. Skip any row whose resolved output path equals
   its input path.
4. **Recycle Bin, never `File.Delete`.** Recoverable is the difference between a mistake and a disaster.
5. **Counted confirmation, defaulting to No**, naming the file count and the space reclaimed, and saying
   the files go to the Recycle Bin.
6. **Disabled while a run is in flight**, and disabled when no row qualifies.
7. **A row whose original is gone must say so** and must not offer to re-cut — its source no longer exists.
8. **Per-row failure isolation.** One file that cannot be binned (locked, permission) must not abort the
   rest; report how many were binned and how many refused.

## Design
- `DeleteOriginalsCommand` + `CanDeleteOriginals` on `BulkCutViewModel`, gated by rules 1/2/3/6.
- `ConfirmDeleteOriginals` as a `Func<int, long, bool>` (count, bytes) set by the view, mirroring
  `ConfirmReplaceOriginals`.
- Deletion runs through `IOriginalDisposer`, which is already injected for the replace path.
- The button lives in the footer beside Run, since it is a post-run action — not in the profile bar.
- Label it for what it does and show the prize: e.g. **Delete originals (12 · 4.3 GB)**.

## Acceptance criteria
- [x] Disabled before any run, during a run, and when no row is `Done`.
- [x] Enabled after a completed batch with ≥1 successful row.
- [x] Bins only the originals of `Done` rows whose output exists and is non-empty **at press time**.
- [x] A row whose output is missing at press time is skipped — asserted with the output deleted between
      the run and the press.
- [x] Under `ReplaceOriginal`, nothing is deleted (the original *is* the output) — asserted.
- [x] Files go to the Recycle Bin via `IOriginalDisposer`, never `File.Delete`.
- [x] Declining the confirmation deletes nothing.
- [x] One un-binnable file does not stop the others; the report states binned vs refused.
- [x] Rows whose original is gone reflect it and cannot be re-run.
- [x] Performance: one disposer call per eligible row, no re-probe, no re-scan.
- [x] SPEC-011 updated; rebuilt and relaunched (PID 4012).
- [ ] Checked on screen by hand (yours — needs a real finished batch).

## Out of scope
Deleting outputs. Undo beyond the Recycle Bin. Auto-deleting without confirmation — that is never
appropriate for this.
