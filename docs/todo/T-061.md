## Concept
On every file load (drag or picker), set the split output directory to the loaded file's folder — always re-anchoring to the current file, while keeping it user-editable.

## Design
- **`SplitViewModel.LoadAsync`**: after a successful probe, set `OutputDir = Path.GetDirectoryName(path)` **unconditionally** (every load re-anchors — a manual change from a previous file is discarded). This replaces the current "prefer `LastOutputDir`" default (from T-038).
- **Configurable:** `OutputDir` stays a normal editable property (the output field + any "choose output" picker) — the reset only fires on a NEW load, not while working the current file.
- **T-038 interaction:** stop defaulting `OutputDir` from `Settings.LastOutputDir`. Keep `LastInputDir` (the file-picker `InitialDirectory`) as-is — that memory is separate + still wanted. Drop the output-default-from-settings (simplest; matches the ask) — or keep `LastOutputDir` written on split but NOT used as the load default; pick one, note it. Update the T-038 tests whose expectation was "output defaults to remembered last-output" to the new "output = loaded file's folder."
- Guard: `GetDirectoryName` null/empty (file at drive root / odd path) → fall back to the prior value or empty, no crash. Works for both drag-drop and picker (both go through `LoadCommand`/`LoadAsync`).

## Acceptance criteria + Case-Coverage Matrix
- [ ] Load a file from folder X → `OutputDir == X` (not the remembered last-output). Works via drag-drop AND the picker.
- [ ] After load, the user can edit `OutputDir` to Y; it stays Y while working the current file.
- [ ] Load a NEW file from folder Z → `OutputDir` RESETS to Z (the manual Y is discarded).
- [ ] Input-picker `InitialDirectory` memory (LastInputDir) still works (not regressed).
- [ ] Build 0-warning; prior tests green (T-038 output-dir test updated to the new expectation).
- Matrix — Required-Success: load → output = file folder; new load → re-anchor. Boundary: file at drive root (null dir → safe); unicode/UNC path; load same folder twice. Required-Fail: n/a.
