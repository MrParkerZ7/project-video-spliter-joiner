## Concept
The Bulk Cut tab ignores the app's vertical/horizontal layout toggle (Split adapts, Bulk doesn't). Make it mode-aware:
its **preview-pane ↔ row-list** split flips — stacked in one mode, side-by-side in the other — the natural Bulk analog of
Split's video ↔ tools split. Reuse `OrientedSplitPanel`.

## Grounding (real reuse)
- `BulkCutView.xaml` (T-101) currently a FIXED `Grid`: header (profiles) · preview pane · GridSplitter · row-list · footer.
  No `IsVertical`/`OrientedSplitPanel` binding today (grep confirms).
- **Split's pattern to copy** — `SplitView.xaml:51`: `<views:OrientedSplitPanel IsVertical="{Binding DataContext.IsVertical, RelativeSource={RelativeSource AncestorType=Window}}" HorizontalRatio="{Binding DataContext.HorizontalSplitRatio, …, Mode=TwoWay}" VerticalRatio="{Binding DataContext.VerticalSplitRatio, …, Mode=TwoWay}">` with `.FirstChild`/`.SecondChild`. Uses `conv:InverseBoolConverter` (`:11`) for the mode-aware nested case (T-091).
- `OrientedSplitPanel` (T-081, `src/App/Views/OrientedSplitPanel.cs`) — flips RowDefinitions↔ColumnDefinitions + splitter orientation on `IsVertical`; `FirstChild`/`SecondChild`/`HorizontalRatio`/`VerticalRatio`; owns the themed splitter + per-axis remembered ratios.
- `MainViewModel.IsVertical` (`:244`) + `ToggleLayoutCommand` (`:266`); `HorizontalSplitRatio`/`VerticalSplitRatio` persisted (AppSettings, SPEC-009).

## Design
1. **Wrap the preview-pane + row-list in an `OrientedSplitPanel`** (replace the current fixed pane/splitter/list Grid rows):
   - `FirstChild` = the **preview pane** (player + set-at-playhead, T-101); `SecondChild` = the **row list** (the ListBox of
     cards, T-097/G-038). The profiles bar (header) stays above and the footer (Run/lifecycle) below — unchanged, outside the split.
   - Bind `IsVertical` to `MainViewModel.IsVertical` (decide the natural direction: in **vertical** monitor mode the pane
     stacks ABOVE the list; in **horizontal** mode the pane sits BESIDE the list — pick whichever reads best and matches
     Split's convention; use `InverseBool` if the inverse gives the right flip). Two-way bind the per-axis ratios.
   - **Ratios:** reuse Split's `HorizontalSplitRatio`/`VerticalSplitRatio` if they don't fight Split's own use of them; if
     sharing causes cross-tab coupling, add a Bulk-specific ratio pair to `AppSettings` (same pattern) — decide + note.
2. **Both modes must keep every Bulk feature working** — the per-row dual-handle scrub bars, cut-point thumbnails, profile
   thumbnails, apply-to-all, the batch run, the lifecycle surfaces — all still function + fit in both orientations. Each
   region scrolls internally; the themed splitter drags in both modes.
3. **Don't disturb** the OUTER app chrome, Split/Join tabs, or the Bulk feature VMs — this is a View-layer re-parent (like
   T-091 for Split's markers/parts). No VM logic change beyond binding to the existing IsVertical/ratios.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Toggling the layout mode flips the Bulk preview-pane ↔ row-list arrangement live (stacked ↔ side-by-side), via `OrientedSplitPanel` bound to `MainViewModel.IsVertical`.
- [ ] The themed splitter drags in both modes; each region scrolls internally; the per-axis ratio is remembered (persists across restart).
- [ ] Every Bulk feature works in BOTH modes: scrub bars, cut-point + profile thumbnails, apply-to-all, batch run + progress, lifecycle surfaces, preview player.
- [ ] Split/Join tabs + the outer chrome undisturbed; VM stays WPF-free (View re-parent only).
- [ ] Build 0-warning; suite green (864) + a test if any binding-glue/ratio VM logic is added (the OrientedSplitPanel flip is covered by T-081/SPEC-015 I16/I17). `serves-spec: SPEC-011`.
- Matrix — Success: vertical mode → pane/list stacked; horizontal → side-by-side; toggle flips live. Boundary: many rows (list scrolls, pane fixed), a selected row playing while toggling (preview survives the re-parent), narrow width, ratio persisted. Required-Fail: none. (Look = app-run/user-verified.)

## Dependencies
Reuses `OrientedSplitPanel` (T-081) + `InverseBoolConverter` + `MainViewModel.IsVertical`/ratios + the AppSettings ratio
round-trip. Independent of T-111/T-113 (all share `BulkCutView` → built sequentially).

## Risks
The pane↔list split must not fight the OUTER OrientedSplitPanel Split uses (they're different tabs, so no nesting — but
verify the RelativeSource Window binding resolves correctly from the Bulk tab). Preview player survives a re-parent
(MediaElement re-host — verify no re-attach crash; the PlayerView attach-on-Loaded from T-101 should re-run). Ratio
sharing vs Bulk-specific — pick one, avoid cross-tab coupling surprises. Keep both orientations usable at realistic sizes.

## Out of scope
The apply-to-all fix (T-111); profiles redesign (T-113); new layout modes; Split/Join layout.
