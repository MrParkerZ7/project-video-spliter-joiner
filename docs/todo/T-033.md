## Concept
Make the playhead land and STAY where the user drags it. Stop stale `PositionChanged` echoes (from the async FFME seek and/or ongoing playback) from yanking the slider back off the user's target.

## Design
- **`PlayerViewModel` seek-target hold:** when the user seeks (the `Position` setter with `!_suppressSeek`, or `Scrub`/skip/jump), record `_seekTarget = T` and `_seeking = true` before issuing `_player.Seek(T)`. In `OnPositionChanged`, while `_seeking`: if the incoming player position is within a small tolerance of `_seekTarget` (seek landed) → clear `_seeking` and apply it; otherwise IGNORE it (don't move `Position`) so the slider stays pinned at T.
- **Deterministic clear (D3):** if `IMediaPlayer`/FFME can signal seek completion (a `Seeked`/`SeekCompleted` event, or awaiting the `Seek` Task) — extend the seam minimally (e.g. `IMediaPlayer.Seek` already fire-and-forget in `FfmeMediaPlayer`; add an internal completion callback that raises a `Seeked` event) and clear `_seeking` on it. Tolerance-matching is the fallback.
- **Drag gating (D2, `PlayerView`):** add `Thumb.DragStarted`/`DragCompleted` handlers (or an attached behavior) on the scrub `Slider` → set an `IsUserScrubbing` flag on the VM: while true, suppress echoes entirely; on `DragCompleted`, seek to the final value + start the seek-target hold. (Live-scrub-while-dragging is optional; seek-on-release is the safe default — pick the smoother, keep the video frame updating if cheap.)
- Keep `_suppressSeek` for its existing job (no re-seek on echo); the new `_seeking`/`IsUserScrubbing` is a separate concern (don't move the display).

## Detail
- Tolerance ~ one frame / ~250ms (enough to catch the settled seek without missing it). Don't freeze forever: also clear `_seeking` after a short timeout or on the next play tick past the target, so a seek that never exactly matches can't lock the slider.
- Skip/jump/frame-step call `Scrub` → they get the same hold (land + stay).
- While playing: after the seek settles at T, normal echo resumes so playback advances FROM T (not the old spot).

## Interfaces / contracts
- `PlayerViewModel` internal state + maybe a small `IMediaPlayer` seek-completion signal; `PlayerView` drag handlers. `SplitViewModel`/split/join unaffected. VM stays fake-testable.

## Acceptance criteria + Case-Coverage Matrix
- [ ] With the fake player: set `Position = T` (user seek), then raise `PositionChanged` with a STALE position P ≠ T → `Position` stays T (not popped to P). (This is the core regression test.)
- [ ] When `PositionChanged` arrives with ~T (seek settled) → `_seeking` clears and subsequent echoes update normally.
- [ ] `Scrub(T)` / skip / jump likewise hold at their target under a stale echo.
- [ ] The existing seek-feedback protection still holds (a player-driven echo never re-seeks).
- [ ] Timeout/settle-fallback: a seek whose echoes never exactly match still unfreezes (no permanently-stuck slider).
- [ ] Build 0-warning; prior tests green.
- Matrix — Required-Success: drag to T → stays at T (paused + playing). Boundary: seek to 0/end; rapid repeated seeks; seek during playback. Required-Fail: n/a.

## Dependencies
None.

## Risks
Over-suppressing → a stuck slider after seek → the settle/timeout clear + the tolerance test guard against it. Live UX (drag feel) verified via app-run.

## Out of scope
Thumbnails/keyboard scrubbing; docs (T-034).
