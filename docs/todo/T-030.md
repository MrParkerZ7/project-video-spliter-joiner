## Concept
Make load feel instant: after the fast metadata probe, immediately show the video + info instead of waiting for the whole keyframe scan. The keyframe index (needed only to snap cuts) builds in the background with a visible "indexing…" hint.

## Design
- Restructure `SplitViewModel.LoadAsync`: after `ProbeAsync` succeeds, set `Info` + `InputPath` + call `Player.Open(path)` + `Markers.Clear()`/`LastResult=null` RIGHT AWAY (the preview shows). Then kick off `GetKeyframesAsync` as a **background task** (not awaited inline in the load), storing the result into `Keyframes` + running `UpdateKeyframeWarning()` on completion.
- Add an observable `IsIndexingKeyframes` (bool) + optional `KeyframesReady` → the view shows a small "indexing keyframes…" hint near the marker/set-cut area while true. Clear when the index lands (or fails).
- Cancellation: if the user loads another file while an index is still running, cancel the stale background task (per-load CTS) so its result can't overwrite the newer file's.
- Keep the friendly-error path: `ProbeFailed` still surfaces via `Operation` exactly as today (the probe is the gating step now, not the keyframe scan).

## Detail
- The keyframe warning (`UpdateKeyframeWarning`, coarse-GOP) moves to "after the background index completes" — until then, no warning (or a neutral "indexing…").
- `Player.Open` no longer waits behind the scan → the FFME preview appears as soon as it opens.
- Snap dependency handled by T-030 + D3: `AddCutAt`/`SetCutAtPlayhead` must behave if the index isn't ready yet — see D3 (brief await on the now-fast scan, or "snapping pending"); implement the least-surprising: if `Keyframes` is empty because indexing is in flight, await the in-flight index task for that one action rather than snapping to nothing.

## Interfaces / contracts
- `SplitViewModel` load flow changes internally; the public split/marker/player surface is otherwise unchanged. Adds `IsIndexingKeyframes` (+ maybe `KeyframesReady`) bindable props.
- No `IMediaPlayer`/engine change.

## Acceptance criteria + Case-Coverage Matrix
- [ ] After load, `Info`/`InputPath` are set + `Player.Open` is called WITHOUT awaiting `GetKeyframesAsync` (verified with a fake probe whose GetKeyframesAsync is slow/controlled — the load completes + player opens before keyframes resolve).
- [ ] `IsIndexingKeyframes` is true while the background scan runs, false when it completes; `Keyframes` + coarse-GOP warning populate on completion.
- [ ] Loading file B while A is still indexing cancels A's stale index (B's keyframes win).
- [ ] A cut placed before the index is ready still snaps correctly once ready (no snap-to-empty, no crash).
- [ ] `ProbeFailed` still surfaces the friendly error; existing tests green.
- Matrix — Required-Success: load → preview instant, index fills in. Required-Fail: probe fails → friendly error (unchanged). Boundary: cut before index ready; rapid re-load; a file with a single keyframe.

## Dependencies
None (restructures existing load).

## Risks
Race between background index + a rapid re-load or an early cut → per-load CTS + await-in-flight-for-snap. Test with a controllable fake probe (slow GetKeyframesAsync).

## Out of scope
The scan-speed optimization itself (T-031); docs (T-032).
