## Concept
The user re-navigates to the same folders every time. Persist the last-used input file folder + last output directory so the pickers + defaults open there next session.

## Design
- A small settings store: `%APPDATA%/VideoSplitJoiner/settings.json` (e.g. `{ lastInputDir, lastOutputDir }`) via a `Core`/`App` `IAppSettings` service (System.Text.Json). Load on startup; save on change. Missing/corrupt file → defaults, never crash.
- **Input:** the Split/Join `OpenFileDialog` sets `InitialDirectory` from `lastInputDir`; on a successful load/add, update `lastInputDir` to the chosen file's folder.
- **Output:** the Split output-dir default reads `lastOutputDir` (falling back to today's "input file's folder" default only when unset); on a successful split, update `lastOutputDir`. Join output likewise if it has a dir.

## Detail
- Keep it minimal (just the two dirs for now; the structure allows more later — window size, last volume, etc. — out of scope now).
- Write is best-effort + atomic-ish (temp-then-rename); read tolerates absent/garbage.
- Don't store anything sensitive; it's just folder paths.

## Interfaces / contracts
- New `IAppSettings`/`AppSettings` (load/save `lastInputDir`/`lastOutputDir`), consumed by the views' pickers + `SplitViewModel`/`JoinViewModel` output defaults. Pure JSON store is unit-testable; the dialogs stay in code-behind.

## Acceptance criteria + Case-Coverage Matrix
- [ ] After loading a file from folder X, next session the input picker opens at X (persisted).
- [ ] After splitting to folder Y, the output dir defaults to Y next time (persisted).
- [ ] Missing/corrupt settings file → sane defaults, no crash (unit-tested).
- [ ] Build + tests green.
- Matrix — Required-Success: dirs persist + reload. Boundary: first run (no file) → defaults; deleted folder → falls back gracefully; corrupt JSON → defaults. Required-Fail: unwritable settings dir → in-memory only, no crash.

## Dependencies
None.

## Risks
Settings-file corruption/permissions → tolerant read + best-effort write.

## Out of scope
A preferences UI, remembering markers/window state, roaming sync; docs (T-039).
