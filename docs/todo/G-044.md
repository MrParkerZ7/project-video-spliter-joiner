## Why

User: *"bulk cut profile should be upload to change thumbnail able"*.

**This feature already ships.** `BulkCutView.xaml:369` has an "Upload image…" button wired to
`OnUploadThumbnailClicked` -> `BulkCutViewModel.UploadThumbnail`, with a "Clear" beside it, in the profile
panel under a "Thumbnail" heading. So the request is not "build this" — it is "this did not work for me",
which makes it one of three things, and the ticket's first job is to find out which:

1. **It silently failed.** `UploadThumbnail` is documented best-effort: *"a null profile, a blank/missing
   image, or a store copy-failure is a silent no-op"* (SPEC-007 I66). A user whose upload fails gets no
   image and no message — indistinguishable from a broken button.
2. **It was disabled.** The button is `IsEnabled="{Binding HasSelectedProfile}"`, so with no profile
   selected it is inert — possibly without that being obvious.
3. **It was not findable.** It sits inside the profile panel; the user may never have seen it.

All three are real product defects even though the code path exists. "Best-effort and silent" is the wrong
contract for a deliberate user gesture: best-effort is right for an auto-thumbnail on save, wrong for
"I picked this file".

## Out of scope
Thumbnail editing (crop/rotate). Per-row thumbnails — this is the profile picker's image only.
