## Concept
Update packaging so the distributable ships the ffmpeg SHARED build — the DLLs FFME loads for the preview AND the exes the split/join engine runs — resolving both at runtime from the packaged layout. Closes out G-004's packaging (was T-021).

## Design
- `packaging/package.ps1`: copy the shared build (`ffmpeg-shared/` → `*.dll` + `ffmpeg.exe`/`ffprobe.exe`) into the publish output as an app-local `ffmpeg/` folder so (a) `FfmpegBinaryLocator` finds the exes and (b) the App startup `Library.FFmpegDirectory` resolver (`<BaseDirectory>/ffmpeg`) finds the DLLs.
- `-FfmpegSource` param → the `ffmpeg-shared/` folder (or re-fetch via `packaging/fetch-ffmpeg-shared.*`).
- Update `THIRD-PARTY-NOTICES.md`: add FFME (its license) + the ffmpeg shared build (GPL — keep the GPL-vs-LGPL note; LGPL shared build = permissive-release path). Note the size increase (~+40MB DLLs).

## Detail
- Verify the packaged tree: `dist/publish/ffmpeg/` has both DLLs + exes; the app's `FFmpegDirectory` resolves to it (path (a) in the T-019 resolver).
- `dist/` + `ffmpeg-shared/` stay gitignored; no binaries committed.
