## Concept

T-189 stopped HEVC Exact cuts from writing corrupt files. Its adversarial review (2026-10-05) found the same class of
bug in **H.264 with open GOPs**: when the keyframe the head ends on (`HeadEnd`) is a non-IDR I-frame, the copied part
is not self-contained. Its frames reference the GOP before it, and `h264_mp4toannexb` inserts SPS/PPS only before IDR
slices, so the tail decodes against the head's parameter sets. The result is written silently and is corrupt.

Measured on synthetic fixtures (bundled ffmpeg n7.1.5), shipped engine:
- x264 `open-gop=1:keyint=50:min-keyint=50:scenecut=0`, 320x240, 25 fps, 12 s, cut at 3.4 s (only frame 0 is an
  IDR; the keyframes every 2 s are non-IDR I-frames flagged `K`): **2 decoder errors** (`co located POCs
  unavailable`, `mmco: unref short failure`) and **9 frames lost at the joint**.
- The same plus `cabac=0:8x8dct=0:ref=1 -bf 2`: **663 decoder errors**, 63 of 200 frames decoded, all wrong.

SPEC-001 I65 and ADR 0018 § (d) already name open-GOP H.264 as known to fail (written by T-189). This ticket makes it
safe.

## Design

Recommended (★): **fall back with a stated reason**, exactly like HEVC, when the plan's `HeadEnd` keyframe is not an
IDR: the row cuts losslessly at the snapped keyframe and says *"frame-exact cutting is not supported yet for this
video's keyframe type"* (copy finalised at build time under T-189's copy rule: no parentheses, no internal terms).
Detecting IDR-ness: read the NAL unit type of the keyframe packet at `HeadEnd` through `FfprobeRunner`
(`-read_intervals` around `HeadEnd`, `-show_packets` with packet data, or the `trace_headers` bitstream filter on a
window), cached per file. A source where every keyframe is an IDR (closed GOP, the common camera case and x264's
default) is unchanged.
Alternative, not chosen now: move `HeadEnd` to the next IDR and re-encode up to it (a longer head, possibly a whole
long GOP of re-encode); it can follow as a later ticket if a user needs frame-exact cuts on open-GOP sources.

## Detail

- The check runs where the plan is known (the engine) and, for the row's before-Run honesty, wherever T-189's per-row
  predicate (`ExactCutApplies` / `ExactUnavailableReason`) gets its input — so the row and the run agree.
- A probe failure in the IDR check is a fallback (never a crash, never an Exact cut on unknown ground).

## Interfaces / contracts

- SPEC-001 I65's open-GOP sentence becomes the fallback rule (next free id if a new invariant is clearer).
- The row predicate gains the open-GOP reason through the same path T-189 and T-190 use.

## Acceptance criteria + Case-Coverage Matrix

- [ ] **Repro first:** an integration test cuts the open-GOP recipe above at 3.4 s with Exact and asserts either
      `FellBack` with no output, or a final that passes `SmartCutJointIntegrity` (0 decoder errors, frames from the
      joint md5-identical, equal tail counts). It FAILS on the code as it stands when this ticket starts.
- [ ] After the fix: falls back with the reason, 0 ffmpeg runs for the Exact path; through `BulkTrimEngine` the
      lossless cut decodes with 0 errors.
- [ ] A closed-GOP H.264 source (x264 default) still gets a frame-exact cut that passes the joint check.
- [ ] The row shows the reason before Run (T-189's surface) and after it (or in the auto-clear summary).
- [ ] SPEC-001 / SPEC-011 / ADR 0018 updated in the same commit; full suite green, 0 skipped.

| case | expected |
|---|---|
| Required-Success: closed GOP H.264 | frame-exact, joint check passes |
| Required-Fail: open GOP H.264, shipped code | repro fails |
| Required-Success: open GOP H.264 after the fix | falls back with the reason, lossless output decodes clean |
| Boundary: open GOP source, cut start already on a keyframe | PureCopy path (no head), unchanged |
| Optional-Fail: the IDR probe fails | falls back, never an Exact cut |

## Edge cases

A source that mixes IDR and non-IDR keyframes (decide per `HeadEnd`, not per file); a stream with no keyframe after
the start (the whole range re-encoded — no tail, no joint, unaffected).

## Dependencies

After T-190 (the joint is rebuilt as one concat pass) and T-191 (the head's seek changes); both edit the same
SmartCut files.

## Risks

The IDR check adds a short probe per Exact row; keep it windowed and cached.

## Out of scope

Re-encoding up to the next IDR; HEVC (T-201); other codecs (T-202).
