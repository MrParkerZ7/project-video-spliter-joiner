## Concept
Turn the built app into something a user can download and run: a self-contained Windows build that bundles ffmpeg/ffprobe, launches fast, and honors ffmpeg's license — a single, clean distributable.

## Design
- `dotnet publish -r win-x64 -c Release --self-contained -p:PublishSingleFile=true` (ReadyToRun for fast startup); trim carefully (WPF trimming is limited — validate).
- Bundle a licensed ffmpeg/ffprobe build under an app-local `ffmpeg/` folder that `FfmpegRunner` (T-002) resolves first; include the ffmpeg `LICENSE`/`README` and attribution.
- App icon, product/version metadata, a portable `.zip` output (installer optional/out-of-scope v1).

## Detail
- Version stamped from a single source (Directory.Build.props).
- Smoke: on a clean Windows VM/user without .NET installed, the app launches and runs a real split + join + detect end-to-end.
- Document the download+run steps in README; note ffmpeg licensing (LGPL/GPL build choice).

## Interfaces / contracts
- Consumes: the whole built app (all prior tasks).
- Produces: a versioned `.zip` distributable + bundled-binary layout.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Single-file self-contained build runs on a machine without the .NET SDK/runtime.
- [ ] Bundled ffmpeg is found + used (not a system PATH dependency); real split/join/detect works from the packaged build.
- [ ] ffmpeg license/attribution included; version stamped.
- Matrix — Required-Success: packaged build launches + all three features work. Required-Fail: missing bundled binary → the T-002 friendly error (verify it still fires in packaged form). Boundary: path with spaces in install location; non-admin user.

## Dependencies
T-007, T-008, T-009 (a working app to package).

## Risks
WPF single-file/trim quirks; ffmpeg binary size + license. Mitigation: validate publish early; pick an LGPL ffmpeg build; document.

## Out of scope
Auto-update, code signing, an installer (.msi/Inno), cross-platform — candidates for a later release goal (see `release`/`release-local`).
