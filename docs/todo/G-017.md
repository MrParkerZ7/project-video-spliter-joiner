## Why / vision
The app currently uses default WPF chrome (light/grey). The user's redesign mockup (`docs/design/references/2026-07-18_redesign-standalone.html`) calls for a **premium dark theme with a gold accent** and rounded panels — a coherent, branded look. Do it as a **design-token system** so the whole app themes consistently and future screens inherit it.

## Design tokens extracted from the mockup preview
| token | value | use |
|---|---|---|
| `Bg` (window) | `#0d0f13` | app background |
| `Surface` | `#15181e` | panels/cards (rounded ~12–24px) |
| `Surface2` | `#1a1e25` | controls bar / secondary surface |
| `VideoBg` | `#000000` | video area |
| `Accent` (primary) | `#e0a83a` | primary buttons, cut pins, playhead, focus, play button |
| `AccentBorder` | `#e0a83a` @ ~25% | accent panel outline |
| `TextPrimary` / `TextMuted` | (to derive — light on dark, e.g. `#EDEDED` / `#9AA0A8`) | body / labels |
> NOTE: colors are from the mockup's **preview SVG** (the HTML is a self-extracting bundle). The **UI Designer** should render the HTML in a browser (or the user shares a screenshot) to confirm exact spacing/typography/component detail before finalizing the token scale.

## Decisions
- **D1 · Token-first (UI Designer lead)** — per the app-UI restyle rule, establish the visual-hierarchy + design-token system FIRST (a `Theme.xaml`/`Tokens.xaml` ResourceDictionary merged in `App.xaml`), THEN restyle views against it; the UX/UI Reviewer verifies compliance. Levels differentiated by ≥2 of form/size/weight/color-role/elevation — never a tint alone.
- **D2 · Dark theme, single palette** — one cohesive dark+gold palette (not a multi-theme switcher — out of scope). All brushes/radii/type as `StaticResource` keys; no hardcoded hex in views.
- **D3 · Confirm detail from a render** — the token VALUES are anchored, but exact layout/spacing/component shapes come from actually rendering the mockup (browser) — do that at the start of the build, don't guess the fine detail from the SVG alone.

## Plan


## Risks
- The full mockup detail is inside a JS bundle → render it first; the SVG palette is directional, not pixel-exact.
- WPF default control templates (Button/Slider/CheckBox/ComboBox/TabControl/ProgressBar) need restyling to look themed — that's the bulk of T-054; budget for it.
- Contrast/readability on dark (theme tokens, not black text — see the themed-text rule); verify with the UX/UI Reviewer.

## Out of scope
A light/dark theme SWITCHER, per-user theme settings, animation polish, a new icon set — later. This applies the ONE redesign theme.
