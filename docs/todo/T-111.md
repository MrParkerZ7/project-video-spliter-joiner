## Concept
"Apply → all" fires once, then doesn't re-apply as expected on a second use. Reproduce, root-cause, and fix so it works
every time — both the profile **Apply → all** and the per-row **⧉ apply-to-all** (whichever is broken).

## Grounding (2026-08-23 — suspects)
- `BulkCutViewModel.cs:147` — `ApplyToAllCommand = new RelayCommand(p => ApplyToAll(p as BulkItemViewModel), _ => Items.Count > 1)` (per-row ⧉).
- `:157` — `ApplyProfileToAllCommand = new RelayCommand(_ => ApplyProfileToAll(), _ => CanApplyProfileToAll)` where
  `:250 CanApplyProfileToAll => _selectedProfile is not null && Items.Any(i => i.IsCheckedByUser)`.
- Re-raise is via a **global requery** (`:917 SaveProfileCommand.RaiseCanExecuteChanged(); // re-evaluates every RelayCommand`).
- **Candidate causes (pin the real one):**
  1. **Selection lost on apply** — if `ApplyProfileToAll` / a Profiles refresh nulls `SelectedProfile`, `CanApplyProfileToAll`
     goes false → the button disables and never re-enables. (Check whether apply re-points/clears `SelectedProfile`.)
  2. **Idempotent no-op** — re-clicking sets each target's `CutMarkerViewModel.Requested` to the SAME value; the setter may
     early-return (no re-snap), so a genuine re-apply after the source changed doesn't propagate. (Check the Requested-setter
     equality guard + whether apply reads the CURRENT source each time.)
  3. **CanExecute stuck** — the RelayCommand's `CanExecuteChanged` isn't re-raised after the state that gates it changes
     (e.g. `IsCheckedByUser` toggles, or a row added) so the button doesn't reflect the new can-run.
  4. **`ApplyToAllReport` not reset** — a stale report/summary makes it LOOK like nothing happened on re-apply.

## Fix
1. **Reproduce first** (a VM test): apply-to-all once, then invoke it again (same + changed source) and assert the second
   invocation (a) is enabled/CanExecute-true and (b) actually propagates the current source's cut points to the targets.
2. **Root-cause + fix** the confirmed cause: ensure the command's `CanExecuteChanged` re-raises when its gate changes;
   ensure a re-apply reads the CURRENT source and propagates even when a target already holds an old value (don't let the
   Requested-setter equality guard swallow a genuine change — if needed, force a re-snap/re-apply path); if `SelectedProfile`
   is lost on apply, preserve it (or re-select the same profile after a Profiles refresh); reset `ApplyToAllReport` per apply.
3. Keep the existing apply semantics (outro-from-end, re-snap + re-validate per target, invalidated rows reported — SPEC-011).
