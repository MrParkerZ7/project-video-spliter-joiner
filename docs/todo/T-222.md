## Concept

A Split that exports every part goes through the single-pass segment muxer, whose output is an ffmpeg **numbered
pattern**: `SplitEngine.ExtractAllViaSegmentMuxer` builds `tempPattern = Path.Combine(tempDir, "part%03d" + ext)`
(`src/Core/Split/SplitEngine.cs:286`), and `tempDir` sits under the output folder. ffmpeg expands **every** `%` in
that string, not only `%03d`. So an output folder such as `D:\Videos\100% done\`, or any folder name with a `%`,
makes the pattern invalid and the split fails. Found by T-188's adversarial review (2026-10-05) on a synthetic file.
The per-segment path (one explicit output file per part) is not affected.

## Design

Escape `%` as `%%` in the folder part of the pattern only (the literal `part%03d` stays), in one small pure helper
next to the pattern build. The segment muxer then receives `D:\Videos\100%% done\.vsj-split-<guid>\part%03d.mp4`,
the temp files land in the real folder, and the finalize step (which uses real paths) is unchanged.
Rejected: writing the temp files under a folder with no `%` (that can leave the output volume and turn the final
rename into a cross-volume move, ADR 0003).

## Detail

- The helper takes the folder path and returns it with each `%` doubled; the pattern is
  `Path.Combine(EscapeSegmentPatternDir(tempDir), "part%03d" + ext)`.
- Every other use of `tempDir` (creating it, listing the parts, the finalize move, cleanup) keeps the real path.

## Interfaces / contracts

- A new internal pure function (for example `SplitArgsBuilder.EscapeSegmentPatternDir(string dir)`), unit-tested.
- SPEC-001 gains one invariant (next free id on disk; `_index.md` recounted): the segment-muxer output pattern
  escapes `%` in its folder part.

## Acceptance criteria + Case-Coverage Matrix

- [ ] **Repro first:** an integration test splits a synthetic clip into all parts with the output folder named
      `out 100% done`, and it FAILS on the shipped code.
- [ ] After the fix it passes: every part exists in that folder and starts on its planned keyframe (T-219's
      lossless-boundary checks), and no `.vsj-split-*` folder is left behind.
- [ ] Unit test of the helper: `%` becomes `%%` in the folder; a folder with no `%` is unchanged; a folder whose own
      name contains `%03d` is escaped, so it is not taken as the pattern.
- [ ] The SPEC-001 invariant is added and `_index.md` recounted; full suite green, 0 skipped.

| case | expected |
|---|---|
| Required-Success: output folder with `%` | all parts written there |
| Required-Success: output folder without `%` | unchanged behaviour (the existing split tests) |
| Required-Fail: shipped code with a `%` folder | the repro fails |
| Boundary: a folder named `%03d` | escaped, no clash with the pattern |
| Optional-Success: unicode plus `%` in the folder | parts written (UTF-8 path handling unchanged) |

## Edge cases

A `%` in the file's own name does not matter (the pattern uses `part%03d`); a UNC output folder with `%`.

## Dependencies

After T-219, which changes the segment-muxer cut times in the same method (a shared file, not a logic dependency).

## Risks

Escaping the literal `%03d` by mistake. Covered by the unit test.

## Out of scope

Other characters ffmpeg treats specially in file names; the per-segment path.
