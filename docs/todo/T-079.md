## Concept
Wire global unhandled-exception handlers so the app logs the full crash and (for recoverable UI errors) shows a message instead of silently vanishing. This both permanently stops silent death and CAPTURES the split→clear→load-new crash for T-080 to fix.

## Design
- In `App.xaml.cs` (`OnStartup`), subscribe:
  - **`DispatcherUnhandledException`** — log the full exception (type + message + stack) via the existing `ErrorLogWriter` to `%LOCALAPPDATA%/VideoSplitJoiner/logs/crash-<ts>.log`; show a friendly, **copyable** error (reuse the `UserFacingError`/`ErrorActions` copy+open-log affordance) with the log path; set `e.Handled = true` so a recoverable UI-thread exception does NOT kill the app.
  - **`AppDomain.CurrentDomain.UnhandledException`** — log (last-ditch; process is going down regardless — write the log synchronously/best-effort).
  - **`TaskScheduler.UnobservedTaskException`** — log + call `e.SetObserved()` so a faulted background task (keyframe index, thumbnail grab) never tears down the process.
- Reuse `ErrorLogWriter` (best-effort, never throws in the handler). Keep the handler code tiny + exception-safe (a throw inside the handler must not recurse).
- Do NOT change app behavior otherwise; this is purely additive.

## Acceptance criteria + Case-Coverage Matrix
- [ ] An unhandled UI-thread exception is logged to `%LOCALAPPDATA%/VideoSplitJoiner/logs/` and shows a copyable message; the app stays alive (`e.Handled=true`).
- [ ] A faulted background `Task` (unobserved) is logged + observed — does not crash the process.
- [ ] An `AppDomain` unhandled exception is logged before exit (best-effort).
- [ ] The handler itself never throws/recurses; logging failure is swallowed.
- [ ] Build 0-warning; suite green. (A unit test can cover the log-writing helper the handler calls; the handler wiring itself is app-run/user-verified.)
- Matrix — Required-Success: throw on UI thread → logged + survived; faulted task → logged + observed. Boundary: logging path unwritable (swallowed, no secondary crash). Required-Fail: none.

## Dependencies
None. Blocks T-080 (its log is the diagnostic input).

## Risks
Native/corrupted-state crashes may bypass managed handlers — this task logs what it CAN; T-080 fixes the actual fault. Keep the handler minimal + non-throwing.

## Out of scope
The actual load-after-clear root-cause fix (T-080); telemetry/crash-reporting service.
