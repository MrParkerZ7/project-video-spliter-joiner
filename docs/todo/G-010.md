## Why / vision
A real user hit a wall: splitting a `.ts` file at a Japanese path failed with `exit -28` and an error they couldn't even copy to report. Three things must be fixed: the split failure (+ the encoding bug behind it), the un-copyable error, and re-picking the same folder every time.

## Gap from current state (from the user's report)
```
ffmpeg split failed (exit -28). Last output:
[mpegts @ …] start time for stream 2 is not set in estimate_timings_from_pts
Input #0, mpegts, from 'F:\_Janpanese\Fumino Satsuki\2K U ç«‹xè¯xxé…'   ← mojibake path
```
- **exit -28 = AVERROR(ENOSPC)** ("no space left on device") — ffmpeg couldn't WRITE the output. Real causes to check: output disk actually full, OR (likely) the **non-ASCII output path is mangled** so ffmpeg can't create the file, OR mpegts timestamp/segment handling.
- **Mojibake** (`ç«‹xè¯xxé`) proves the process **stderr is captured with the wrong encoding** (Windows console codepage, not UTF-8) — errors with unicode paths are unreadable, and the path may be mishandled going IN too.
- **Un-copyable error:** the friendly-error "details" is a non-selectable TextBlock + only the last ~N stderr lines (a truncated tail), so the user can't copy the full log.
- **No remembered location:** the file picker + output dir don't persist across sessions.

## Decisions
- **D1 · Encoding first** — set `ProcessStartInfo.StandardOutputEncoding`/`StandardErrorEncoding = UTF8` in `FfmpegRunner`/`FfprobeRunner` (and `Console`/args as needed) so unicode paths + messages are correct. This likely un-mangles the path and may fix the write. Verify ffmpeg receives the correct path (ArgumentList already avoids quoting bugs, but confirm on a Japanese fixture).
- **D2 · .ts/mpegts robustness** — investigate exit -28 on the real file: check free disk on the output drive, output-path writability with unicode, and add mpegts-safe copy flags if needed (`-fflags +genpts`, `-avoid_negative_ts make_zero`, `-copyts`/`-muxpreload/-muxdelay` as appropriate). Map ffmpeg `ENOSPC`/exit -28 → a clear "no space / can't write output" `UserFacingError` (the current mapper shows the warning tail instead of the real cause).
- **D3 · Copyable + full log** — make the error details a read-only SELECTABLE control + a "Copy" button (copies the full log); keep the FULL stderr (write it to a per-run log file, e.g. `%LOCALAPPDATA%/VideoSplitJoiner/logs/…`, and surface its path) rather than only the tail.
- **D4 · Remember location** — persist last input folder + last output dir to a small settings file (`%APPDATA%/VideoSplitJoiner/settings.json`); the picker `InitialDirectory` + the default output dir read it; write it on successful load/split.

## Risks
- exit -28 has ≥3 candidate causes → **investigate to confirm** before "fixing" (don't guess); the real file (or a unicode-path .ts fixture) is needed to reproduce — may need the user's file or a synthesized equivalent.
- mpegts copy-split has genuine timestamp quirks → flags may vary; verify the output is playable, not just that ffmpeg exits 0.
- Settings persistence must be robust (missing/corrupt file → defaults, never crash).
