## Concept

T-195 (2026-10-05) added `-nofind_stream_info` to the MP4/MOV waveform run only (SPEC-006 I3/I24). The frame grab keeps
ffmpeg's stream-info pass on every input (SPEC-005 I27). Skipping that pass also leaves ffmpeg without the format
`start_time`, and an input `-ss` counts from that start time. So on an MP4/MOV whose start is not 0, a skipping grab
exits 0 with another frame, and no retry can tell.

Measured with the bundled ffmpeg-shared 7.1, comparing the decoded md5 of flagged and unflagged grabs:

| file | format start_time | -ss | flagged vs today |
|---|---|---|---|
| ffmpeg default MP4 (edit list) | 0 | 1, 3 | identical |
| first part of `SplitArgsBuilder.SegmentMuxer` on an H.264 `-bf 2` + AAC MP4 (cuts 4, 8 s) | 0.042993 s | 1 | today fe7c9dac..., flagged 5ffeb0d6... (one frame early) |
| same | 0.042993 s | 3 | today 0e38ac25..., flagged 4baf3750... |
| `-output_ts_offset 10` MOV | 9.976 s | 1, 3 | flagged = the first frame |
| `-use_editlist 0`, B-frames | 0.0667 s | 1, 3 | different |
| MPEG-TS content named `.mp4` | about 1.44 s | 3 | different |

The gain the grab is missing comes from T-195's builder bench, which timed the flagged grab (since reverted). It used
libx264 fixtures, 3 runs, before -> after (control):

- 4k hover kf 0.302 -> 0.198 (0.263); chip kf 0.287 -> 0.224 (0.269); profile kf 0.301 -> 0.210 (0.267); 1 s into GOP
  0.348 -> 0.281 (0.326);
- 10-bucket hover sweep 3.085 -> 2.611 (3.179);
- g10 hover kf 0.268 -> 0.220; HEVC gets nothing.

That is about 0.05-0.09 s per 4K H.264 grab, not the 2x first planned.

## Design

Recommended (star): flag the grab only when the extension is MP4/MOV (`StreamInfoSkip.IsIsoBmffExtension`) **and** the
probed format start time is exactly 0.

- Needs T-219's `MediaInfo.StartTime`. `MediaProbe.ProbeAsync` already asks for `-show_format` and has cached it since
  T-193, so the check costs no process.
- `FfmpegThumbnailService` takes an optional start-time source in its constructor, e.g. a
  `Func<string, CancellationToken, Task<TimeSpan?>>` or the shared `IMediaProbe`. `MainViewModel` wires the shared
  probe.
- `IThumbnailService` does not change.
- Unknown start time (no source, the probe failed or was cancelled): today's unflagged args.
- Retry like SPEC-006 I24: one unflagged retry when a flagged grab exits non-zero or writes no file or an empty one; a
  cancelled grab is never retried. Consider per-input failure memory, as T-195's original design had, because hover
  grabs repeat per input (and see T-229: a right-edge hover fails both runs on a healthy file, so a memory must not
  record that case).

Alternatives:

- Callers pass the start time through `IThumbnailService` (an interface change touching every caller).
- `-f mov` before `-i`. This catches only mislabelled files, not a genuine MP4 with a nonzero start, so it is rejected.
