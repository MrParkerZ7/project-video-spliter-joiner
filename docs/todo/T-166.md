## Found

While updating `_index.md` for SPEC-010 I71/I72 (the [[T-154]] trace follow-up), the file's own prose
turned out to describe this gap in the past tense:

> **Keep this headline and the TOTAL row in step.** They disagreed for two days (723 vs 751) because
> `SpecIndexFreshnessTests` only parses rows whose first cell is a linked `SPEC-NNN` — the TOTAL row
> and every line of prose here are invisible to it.

So the guard is doing its job precisely and narrowly: it recounts each per-spec row against the file on
disk and fails if one drifts. It has **nothing to say** about the `**TOTAL**` row or the
`Total documented invariants: **N**` headline — and those are the two numbers a human actually reads.
The 723-vs-751 disagreement lasted two days with the suite green throughout.

The workaround today is a paragraph in `_index.md` asking whoever edits it to keep them in step by hand.
That is the same hand-maintained-copy failure mode that produced the stale picker filter ([[T-158]]),
the `_GAPS.md` header saying 9 while its list held 13, and the ROADMAP's frozen "1111 tests" — all
found and fixed in this drive. A note asking for care is not a guard.

## Design
1. Extend `SpecIndexFreshnessTests` with two assertions:
   - the `**TOTAL**` row equals the **sum of the per-spec rows** it already parses;
   - the `Total documented invariants: **N**` headline equals that same total.
2. Parse the headline by regex against the literal prose shape, and fail with the two numbers named, so
   the message says which one to fix rather than "assertion failed".

## Acceptance criteria
- [x] Editing a per-spec count without updating TOTAL fails. Tested the way it actually
      happens — a 73rd invariant appended to SPEC-010 with the index untouched — which fired **all
      three** guards at once.
- [x] Editing TOTAL without updating the headline fails, and vice versa.
- [x] Mutation: TOTAL 762→761 alone killed **only** `TheTotalRowEqualsTheSumOfTheSpecRows`;
      headline 762→761 alone killed **only** `ThePlainEnglishHeadlineEqualsTheSameSum`. Each guard
      fires on its own number and stays quiet about the other.
- [x] The "keep this in step by hand" paragraph is gone. `_index.md` now names the two tests and
      says all three figures can only be wrong deliberately.

## Out of scope
Re-measuring the `Covered` / `Gaps` columns, which `_index.md` already says plainly are **not**
re-measured. That is a bigger job ([[T-140]]-shaped) and independent of these two numbers agreeing.

## Outcome — 2026-09-06

Both summary figures are enforced. The index no longer asks anyone to remember them.

### Checked against the rows, not against each other
The tempting shape is to assert `headline == TOTAL row`. That is a copy checked against a copy: both are
free to drift together, and the pair would still agree while both were wrong. Each is instead compared to
the **sum of the per-spec rows**, and those rows are already recounted from the spec files on disk — so
the chain terminates in something nobody types.

### The realistic mutation, not just the convenient one
Moving a number by hand proves a comparison fires. What actually happens is that someone documents an
invariant and updates nothing, so that case was tested too: a 73rd invariant appended to SPEC-010 turned
all three guards red simultaneously — the per-spec row, the TOTAL, and the headline. Then the same guards
immediately validated a **real** count change in the same session: SPEC-011 gained I151 from [[T-167]],
and 151 / 763 went green only once all three were updated.

### The paragraph it replaces
`_index.md` used to carry *"Keep this headline and the TOTAL row in step"* — a note asking a human for
care, which is what you write when you have no guard. It now names the two tests instead. Prose should
say what enforces a rule; asking the reader to enforce it is how the two figures spent two days 28 apart
with the suite green.

### Deliberately not fixed
The `Covered` / `Gaps` columns still read `?` where invariant counts moved, and `_index.md` still says
plainly that they are **not** re-measured. Establishing them needs another per-invariant audit and stays
its own ticket — a guessed coverage figure is worse than an honest `?`, which is the same reason this
ticket exists at all.
