## Concept
Reorder join clips by dragging a row to a new position — the direct-manipulation equivalent of the existing Up/Down buttons (which stay as the reliable fallback). Order matters for the joined output.

## Design
- **Testable move logic** — a pure `MoveItem(list, fromIndex, toIndex)` (or reuse the JoinViewModel's existing reorder path) so the reordering itself is unit-tested independent of drag events. If `JoinViewModel` already has `MoveUp/MoveDown`, add a `MoveTo(item, newIndex)` (or `Move(from,to)`) that the drag drop calls and that Up/Down can also delegate to — one reorder path.
- **JoinView code-behind** — WPF ListBox drag-reorder: on `PreviewMouseLeftButtonDown` capture the pressed item; on `MouseMove` past a threshold start `DragDrop.DoDragDrop` with the item; on `Drop` (within the list) compute the target index from the drop position and call `JoinViewModel.Move(from,to)`. Re-run the compat check after (the VM's reorder already does this — reuse).
- Keep it MVP: reorder within the same list only (no cross-control drag). This is DISTINCT from T-016's external file drop — an internal-move drag.

## Detail
- Guard: dragging when < 2 items → no-op. Dropping onto empty space → append/last.
- Visual: an insertion indicator is a nice-to-have; MVP may just reorder on drop.
- Ensure T-016's external FileDrop handler and this internal item-drag don't conflict (distinguish by `e.Data` format: `FileDrop` = external add; the item type = internal reorder).

## Interfaces / contracts
- Consumes: `JoinViewModel` Items + its compat re-check.
- Produces: `Move(from,to)` reorder entry (shared by drag + Up/Down).

## Acceptance criteria + Case-Coverage Matrix
- [ ] `JoinViewModel.Move(from,to)` reorders Items correctly + re-runs compat (unit-tested with fakes).
- [ ] MoveUp/MoveDown delegate to the same Move path (no duplicate reorder logic).
- [ ] Dragging row 3 above row 1 → order updates (VM-level test; the drag gesture itself is app-run-verified).
- [ ] External FileDrop (T-016) still adds files — the two drag paths don't clash.
- [ ] Build + all prior tests green.
- Matrix — Required-Success: move(2,0) → item moved to front. Boundary: move to same index (no-op); move first/last; <2 items (disabled). Required-Fail: invalid indices → clamped/ignored, no crash.

## Edge cases
Single item; move to same position; out-of-range index; interaction with the external file-drop handler.

## Dependencies
None unfinished (Join screen shipped). Serialized after T-016 on the shared tree (both touch JoinView).

## Risks
WPF ListBox drag-reorder is fiddly → MVP move-on-drop; Up/Down remain. Distinguish internal vs external drag by data format.

## Out of scope
Insertion-line animation, multi-select drag, cross-tab drag.
