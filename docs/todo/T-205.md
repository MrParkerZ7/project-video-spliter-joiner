## Concept

On a 4K load several readers hit the same file at once:
- the FFME preview;
- the keyframe scan;
- the waveform, which is a second whole-file read on MKV/TS;
- hover grabs.

None of them yields while an export runs:
- Bulk stops the preview when a run starts (`BulkCutViewModel.cs:2712`), but Split does not.
- Bulk row grabs and re-takes keep running during a batch.
- Best-effort ffmpeg and ffprobe runs use Normal priority and all cores.

Proposals:
- Split stops the preview at Run, through `IMediaPlayer`;
- Bulk holds row grabs and re-takes during a batch, and re-requests them afterwards (SPEC-011 I158);
- the waveform starts after the keyframe index;
- best-effort processes run at BelowNormal priority, set in the runners;
- a scan gate per physical drive.

## Why later

Every effect here is **inferred contention**, not measured: the HDDs were off-limits. After T-194, most MP4/MOV
contention disappears anyway.

## Trigger

A slow-disk bench measures it on synthetic data only: for example a VHD on an HDD created for the bench, or a
throttled read source. Never the user's files.
