## Concept
A coarse keyframe grid is exactly when snapping surprises the user — but the Bulk warning is gated on a
STRICT `gop > 4s`, so a file with a mean GOP of exactly 4.0s (the grid that best fits this bug report) is
warned about **not at all**. Worse, the planner already composes the precise sentence the user needed and it
is thrown away before the run.

## Grounding
- `src/App/ViewModels/BulkItemViewModel.cs:76` `CoarseGopThreshold = 4s`, `:421-424` strict `>` test.
- `src/Core/Split/SplitPlan.cs:124,158-162` — planner warns at `>2s` and builds "Cut at 6s moved 2s to the nearest keyframe…".
- `src/Core/Split/KeptSegmentSelector.cs:68-101` — discards `plan.Warnings`.
- `src/Core/Bulk/BulkTrimEngine.cs:148` → ledger → `BulkItemViewModel.cs:640-666` — warnings only reach the row AFTER the run.

## Fix
Warn on the **actual snap magnitude** rather than (only) the GOP average: flag the row when
`|IntroEnd.Delta|` (or the outro's) exceeds a small threshold (~0.5s, matching the planner's own rule), so the
warning tracks what really happened to THIS cut. Fix the boundary to `>=` as well. Keep it a soft advisory —
never block a run.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Mean GOP exactly 4.0s → row warns (the current blind spot closes).
- [ ] A cut that snapped >0.5s away warns even on a fine grid; a cut that snapped <0.5s does not (no nagging).
- [ ] The warning is pre-run and advisory; the run is never blocked by it.
- Matrix — Success: coarse grid + large snap warn. Boundary: exactly-4.0s GOP, exactly-0.5s delta, identity snap, keyframes-not-ready. Required-Fail: none. **Perf (no-I/O-on-path): the warning is derived from already-loaded keyframes — ZERO additional probe/ffprobe calls (assert on the recording fake).**

## Out of scope
Plumbing the full planner warning list through `KeptSegmentSelector` (larger refactor — note it if deferred).
