## Concept
Stand up the empty, buildable foundation everything else lands on: a .NET WPF desktop solution with an MVVM structure, a clean layering seam (UI ⇄ Services ⇄ ffmpeg), and a test project — so all later tasks have a home and a green build to extend.

## Design
- .NET (current LTS) WPF app. Solution: `VideoSplitJoiner.sln` with projects: `App` (WPF, MVVM — Views/ViewModels/Commands), `Core` (pure C# services: media, split, join, detect — no WPF refs), `Core.Tests` (xUnit + FluentAssertions).
- Layering: WPF depends on Core; Core depends on nothing UI. This keeps engines unit-testable headless.
- MVVM via lightweight `INotifyPropertyChanged` base + `RelayCommand` (or CommunityToolkit.Mvvm). No heavy framework.
- Single-file self-contained publish configured (win-x64) — validated fully in T-010.

## Detail
- Folders: `App/Views`, `App/ViewModels`, `App/Services` (thin UI-side glue), `Core/Media`, `Core/Split`, `Core/Join`, `Core/Detect`, `Core/Ffmpeg`.
- A `MainWindow` with an empty shell + tab/nav placeholder for Split | Join screens.
- `.editorconfig`, nullable enabled, warnings-as-errors on Core.
- README stub + `docs/` folder.

## Interfaces / contracts
- Produces: the solution/project graph + namespaces (`VideoSplitJoiner.Core.*`) every other task imports.
- No runtime contract yet; defines the DI/composition-root seam (App wires Core services) that T-002+ plug into.

## Acceptance criteria + Case-Coverage Matrix
- [ ] `dotnet build` is clean (0 warnings on Core); `dotnet test` runs (even if only a placeholder test) and passes.
- [ ] App launches to an empty MainWindow with Split/Join nav placeholders.
- [ ] Core has zero WPF/PresentationFramework references (enforced by build).
- Matrix — Required-Success: solution builds + app starts. Required-Fail: build breaks if Core references WPF (guard test/analyzer). Boundary: runs on a machine with only the .NET runtime.

## Edge cases
Missing .NET SDK (documented prereq); x86 vs x64 target fixed to win-x64.

## Dependencies
None — this is the root task.

## Risks
Over-engineering the skeleton. Mitigation: minimal MVVM, no premature abstractions.

## Out of scope
Any real ffmpeg call, any screen logic, packaging polish (T-010).
