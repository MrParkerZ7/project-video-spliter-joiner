## Concept
Turn the implicit "all parts between the cuts" into an explicit, selectable list, and write only the parts the user checks — saving time + disk when they want just a few.

## Design
- **Segment projection (`SplitViewModel`):** from the cut markers (their snapped times) + the clip Duration, compute the ordered parts: `[0..s1], [s1..s2], …, [sN..end]`. Expose an `ObservableCollection<SplitSegmentViewModel>` where each item has `Index`, `Start`, `End`, `Duration`, a `Display` (`Part 2 · 05:00–10:00 · 5:00`), and `IsSelected` (default true). Recompute when markers change.
- **Export only selected:** `RunSplitAsync` builds the request from the SELECTED segments only.
  - `SplitRequest`/`SplitEngine`: accept the explicit list of ranges to write (or a `SelectedIndices` set). If ALL are selected (contiguous full set) → keep the fast **segment-muxer** path (today's behavior). If a SUBSET → use the existing **per-segment `-ss <start> -to <end> -c copy`** extraction (from `SplitArgsBuilder`) for each selected range, writing only those files.
  - Preserve `-c copy` (assert no encoder tokens) + keyframe-snapped boundaries (use the markers' snapped times).
- **UI (`SplitView`):** a checkable list of the segments (checkbox + `Display`), a "select all / none" affordance, near the markers/Run area. Run's label/enable reflects the count ("Split 2 selected parts"); disabled when zero selected.
- **Naming:** decide part numbering for a subset (keep original 1..N indices, or renumber 1..k) — pick one, keep it consistent, note it in the report.

## Detail
- Segment list is derived (read-only projection of markers) except the `IsSelected` toggles.
- `SplitResult` already reports produced segments — reflect only the written (selected) ones.
- Zero markers → one part (the whole file); selecting it = today's "no cut" case (or disable if that's not meaningful).

## Interfaces / contracts
- `SplitViewModel` gains the segment projection + selection; `SplitRequest`/`SplitEngine` gain a selected-ranges/indices input (additive, default = all → unchanged behavior). `SplitEngine` routes full-set → segment muxer, subset → per-segment copy. Engine `-c copy` invariant preserved.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Markers at 5m & 10m on a 15m clip → 3 segments listed (`0–5`, `5–10`, `10–15`) with durations; all selected by default.
- [ ] Deselect parts 1 & 3, Run → only part 2 (`5–10`) is written; parts 1 & 3 are NOT created on disk (integration test on a fixture).
- [ ] All selected → identical result to today (segment muxer path).
- [ ] `-c copy` preserved on both paths (assert args); boundaries keyframe-snapped.
- [ ] Run disabled when zero segments selected.
- [ ] Build 0-warning; prior tests green; unit tests for the segment projection + subset-vs-full routing.
- Matrix — Required-Success: subset selection → only those files written. Boundary: select one middle part; select all (== today); select none (Run disabled); adjacent selected parts. Required-Fail: n/a.

## Dependencies
None (builds on the existing SplitEngine per-segment path + markers).

## Risks
Per-segment `-ss/-to -c copy` start accuracy → use the snapped keyframe times so a selected part starts on a keyframe (same boundaries as the muxer). Verify outputs are playable (re-probe).

## Out of scope
Merging selected parts (that's join), reordering, per-part rename; docs (T-050).
