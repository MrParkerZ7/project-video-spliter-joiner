## Concept

The foundation of Bulk Cut (D-004). A bulk trim **is a Split that keeps exactly ONE middle segment** `[introEnd → outroStart | EOF]`. This task adds the Core capability to extract that one kept segment via the **existing** `SplitEngine` path — stream-copy only, no new ffmpeg builder, no second orchestration path.

The one real problem to solve is the **"kept index is not always 2" risk**: `SplitPlanner.Plan` drops/merges/snaps cuts, so a naïve `SelectedSegmentIndices=[2]` throws or selects the wrong part when intro snaps to ~0 (its cut is dropped → kept becomes index **1**) or outro snaps to ~EOF (its cut is dropped → kept stays index **2** but as `[introEnd..EOF]`).

**Decision (recommended + justified): a pure `KeptSegmentSelector.ResolveKeptIndex(...)` that DEFERS to `SplitPlanner.Plan` and reuses `SplitEngine.SplitAsync` with `SelectedSegmentIndices=[keptIndex]` — NOT a direct single-`PerSegment` emission.** Rationale:
- **Preserves the core insight literally.** The engine's existing `ExtractSelectedPerSegment` already emits **exactly one** `SplitArgsBuilder.PerSegment([introEnd..outro|EOF])` when the selection is the single kept part (`-ss` before `-i`, `-c copy`, `-avoid_negative_ts make_zero`, `-to` = duration, final part omits `-to`). Reusing it means we inherit — for free and unforked — temp-then-move cancel-safety, `AssertCopyInvariant`, disk pre-flight, and `FfmpegErrorMapper`. A direct-`PerSegment` path would **re-implement all of that** (a second orchestration path), contradicting "add NO second ffmpeg path."
- **Zero drift.** `ResolveKeptIndex` runs the **real** `SplitPlanner.Plan` and reads back which planned segment is the kept middle, so it can never disagree with what the engine will actually plan. Re-deriving the drop/merge/snap rules by hand would rot the moment the planner changes.
- **Pure + trivially unit-testable** with the existing `FakeProbe`/`RecordingFakeRunner`, WPF-free.

Deliverables: `KeptSegmentSelector` (Core, pure) with `ResolveKeptIndex` + a thin `BuildKeptMiddleRequest` factory that assembles the single-segment `SplitRequest` (naming `{name}_trimmed{ext}`, output dir = source dir), and a `KeptSegmentSelectorTests` suite proving index correctness + that the built request runs as one `-c copy` `PerSegment` (with the EOF omit-`-to` path).

## Design (step-by-step)

1. **New file `src/Core/Split/KeptSegmentSelector.cs`** — `public static class KeptSegmentSelector` in `namespace VideoSplitJoiner.Core.Split`. Pure, no I/O, no WPF, no ffmpeg.

2. **`ResolveKeptIndex`** — signature mirrors the engine's own `Plan` call site (SplitEngine.cs:100–106):
   ```csharp
   public static int ResolveKeptIndex(
       TimeSpan duration,
       IReadOnlyList<TimeSpan> keyframes,
       Func<IReadOnlyList<TimeSpan>, TimeSpan, KeyframeSnap> snap,
       TimeSpan averageGop,
       TimeSpan introEnd,
       TimeSpan? outroStart)
   ```
   Body:
   a. Build `requestedCuts = outroStart is { } o ? new[]{ introEnd, o } : new[]{ introEnd }`.
   b. `var plan = SplitPlanner.Plan(duration, requestedCuts, keyframes, snap, averageGop, static _ => "unused");` — the throwaway `pathFor` returns a constant (index math only; path is never used here). If both cuts collapse the planner **throws `SplitException`** — let it propagate (the trim is a no-op; the VM gates this upstream, but Core stays honest).
   c. Compute the expected kept-start boundary: `var introSnap = keyframes.Count == 0 ? introEnd : snap(keyframes, introEnd).Snapped;` then `if (introSnap <= TimeSpan.Zero || introSnap >= duration) introSnap = TimeSpan.Zero;` (an intro cut that snaps to ~0 is dropped by the planner ⇒ the kept part begins at file start).
   d. Return the **1-based** index of the plan segment whose `SnappedStart` is nearest `introSnap` (linear scan, `(seg.SnappedStart - introSnap).Duration()` minimal). Because segments are contiguous with distinct snapped starts, this is an exact match; it correctly yields **1** when intro was dropped (segment `[0..outro]`) and **2** when intro survived.

3. **`BuildKeptMiddleRequest`** — thin factory producing the single-kept-segment request:
   ```csharp
   public const string TrimmedNamingPattern = "{name}_trimmed{ext}";
   public static SplitRequest BuildKeptMiddleRequest(
       string inputPath, TimeSpan introEnd, TimeSpan? outroStart, int keptIndex, bool overwrite = false)
   ```
   Sets `OutputDir = Path.GetDirectoryName(Path.GetFullPath(inputPath))!` (same-folder rule), `CutPoints` per step 2a, `NamingPattern = TrimmedNamingPattern`, `SelectedSegmentIndices = new[]{ keptIndex }`, `Overwrite = overwrite`. (The `_trimmed` pattern has no `{index}` token, so every planned segment resolves to the same `{name}_trimmed{ext}` path — safe **because exactly one** part is ever selected/written; the engine's collision check only inspects SELECTED outputs, SplitEngine.cs:118–128. See Risks.)

4. **Caller contract (documented in XML doc, exercised by tests):** resolve `keptIndex` from the shared probe's already-scanned keyframes, build the request, hand it to the shared `SplitEngine.SplitAsync`. The engine's subset path emits one `PerSegment`: interior kept (`outroStart` present, not final) → explicit `-to` = `(outroStartSnapped − introEndSnapped)`; kept-to-EOF (`outroStart` null, or outro dropped to EOF ⇒ kept is the final part) → omits `-to`.

5. **No changes to `SplitEngine`, `SplitPlanner`, `SplitArgsBuilder`, or `SplitRequest`** — this task is purely additive Core (one new file + one new test file). VM wiring, `BulkItemViewModel`, naming-collision `AutoSuffix`, disk pre-flight across the batch, and the batch runner are later D-004 tickets.

6. **New test file `tests/Core.Tests/KeptSegmentSelectorTests.cs`** — pure index tests over `FakeProbe` (pass `probe.SnapToNearestKeyframe`, `probe.AverageGop(keyframes)`) + end-to-end extraction tests running `BuildKeptMiddleRequest` through a real `SplitEngine(RecordingFakeRunner, FakeProbe)` in a temp dir (copy the temp-dir setup/teardown idiom from `SplitEngineUnitTests`). Fixture: 10s file, keyframes at every integer second (`Enumerable.Range(0,11).Select(i => TimeSpan.FromSeconds(i))`).

## Acceptance criteria + Case-Coverage Matrix

- [ ] `KeptSegmentSelector.ResolveKeptIndex` returns the correct **1-based** kept index across all planner outcomes: intro+outro interior ⇒ **2**; no outro ⇒ **2** (`[introEnd..EOF]`); intro snaps to ~0 **with** outro ⇒ **1** (`[0..outro]`); outro snaps to ~EOF ⇒ **2** (`[introEnd..EOF]`).
- [ ] `ResolveKeptIndex` **propagates `SplitException`** when both boundaries collapse (intro ~0 + no outro) — no bogus index returned.
- [ ] `BuildKeptMiddleRequest` produces a `SplitRequest` with `OutputDir` = source dir, `NamingPattern = "{name}_trimmed{ext}"`, `SelectedSegmentIndices` = `[keptIndex]`, `CutPoints` = `[introEnd(,outroStart)]`.
- [ ] Running the built request through `SplitEngine.SplitAsync` yields **exactly ONE** ffmpeg command (recorded), on the **per-segment path** (`-ss` + `-map 0 -c copy`, no `segment`/`-segment_times`).
- [ ] Interior kept (outro present) command **contains `-to`**; kept-to-EOF (no outro) command **omits `-to`**.
- [ ] `SplitArgsBuilder.SatisfiesCopyInvariant(tokens)` is `true` and **none** of `ForbiddenEncoderTokens` appear in the built command.
- [ ] Produced output file is `{name}_trimmed{ext}`; the **source file is untouched** (still present, unmodified).
- [ ] Core stays WPF-free — `CoreIsUiFreeTests` green; new type lives in `VideoSplitJoiner.Core`.
- [ ] **Build is 0-warning and the full suite (`dotnet build` + `dotnet test`) is green.**
- [ ] New tests added in `tests/Core.Tests/KeptSegmentSelectorTests.cs`: `ResolveKeptIndex_IntroAndOutro_ReturnsIndex2`, `ResolveKeptIndex_NoOutro_ReturnsFinalIndex2`, `ResolveKeptIndex_IntroSnapsToZero_WithOutro_ReturnsIndex1`, `ResolveKeptIndex_OutroSnapsToEof_ReturnsIndex2`, `ResolveKeptIndex_BothCollapse_Throws`, `BuildKeptMiddleRequest_SetsSameDir_TrimmedName_SingleSelectedIndex`, `Build_ThenSplit_Interior_RunsSinglePerSegmentCopy_WithTo`, `Build_ThenSplit_NoOutro_EofPath_OmitsTo`, `Build_ThenSplit_NoEncoderTokens_SourceUntouched`.

**Matrix —** Success: {intro+outro interior→idx2 + one `-to` `-c copy` run}, {no-outro→idx2 EOF, `-to` omitted}, {intro~0+outro→idx1 keep `[0..outro]`}. Boundary: {outro snaps to ~EOF ⇒ dropped ⇒ kept `[introEnd..EOF]` idx2, `-to` omitted}, {empty keyframes ⇒ raw times, index still resolves}, {`_trimmed` pattern lacks `{index}` yet single-select writes one file with no false collision}. Required-Fail: {both boundaries collapse (intro~0, no outro) ⇒ planner `SplitException` propagates, no index, no ffmpeg run}, {copy-invariant assertion would reject any non-`copy` command — guaranteed by reused `AssertCopyInvariant`}.

## Dependencies

- Existing, sealed: `SplitEngine`/`ISplitEngine`, `SplitPlanner`, `SplitArgsBuilder`, `SplitRequest`, `IMediaProbe`, `KeyframeSnap` — all in `VideoSplitJoiner.Core` (no changes needed).
- Test-only: `FakeProbe`, `RecordingFakeRunner`, `NoopFakeRunner` in `SplitEngineUnitTests.cs` (reuse in-place; they are `internal` to the test assembly — same assembly, directly usable).
- No new NuGet packages. No VM/App/XAML dependency (those are downstream D-004 tickets).

## Risks

- **`_trimmed` naming has no `{index}` token** ⇒ all planned segments' `OutputPath` collapse to one string. Correctness relies on selecting **exactly one** part (the engine writes/collision-checks only SELECTED outputs, SplitEngine.cs:118–128, 438). Mitigation: `BuildKeptMiddleRequest` always sets a single-element `SelectedSegmentIndices`; a test asserts single-output. If a future ticket ever selects >1 kept part, it MUST reintroduce `{index}` — call this out in the XML doc.
- **`ResolveKeptIndex` index math must match the engine's plan exactly.** Mitigation is structural: it calls the *same* `SplitPlanner.Plan` rather than re-deriving rules, so it cannot drift. The only local logic (intro-snap→0 clamp) mirrors the planner's own drop rule (`SplitPlan.cs:96,148`) and is covered by the intro~0 test.
- **No-op propagation:** relying on `SplitPlanner.Plan` throwing for the both-collapse case couples the selector to a planner exception. Acceptable — it is the planner's documented contract (`SplitPlan.cs:113,165`); the test pins it.
