## Concept
The Bulk row's IN/OUT time TextBox is editable, bound **OneWay to `Snapped`**, with
`LostFocus="OnCutTimeLostFocus"`. `CommitCutTime` runs on EVERY focus loss — even when the user never typed —
parsing the *displayed* text back into `Requested`. Because the display is the **snapped** time truncated to
0.1s, merely clicking away silently replaces the user's real request (5s/6s) with `4.0`, permanently pins the
row at the snapped value, zeroes the tooltip delta (the only evidence a snap happened), and sends the
truncated value to the engine (`BuildBulkTrimItem` passes `Requested`).

## Grounding
- `src/App/Views/BulkCutView.xaml:708-713` — editable TextBox, `Text={Binding IntroEnd.Snapped, Mode=OneWay}`, `LostFocus`.
- `src/App/Views/BulkCutView.xaml.cs:164-194` — `OnCutTimeLostFocus` → `CommitCutTime` unconditional; writes `row.IntroEnd.Requested = t` at `:184`.
- `src/App/ViewModels/CutMarkerViewModel.cs:157-164` — `FormatClock` = `MM:SS.f`, truncating tenths.
- `src/App/ViewModels/BulkItemViewModel.cs:506` — the engine gets `Requested`.

## Fix
Only commit when the user actually EDITED the field: track the text at focus-gain (`GotFocus`) and no-op in
`CommitCutTime` when the current text is unchanged (or when it round-trips to the same displayed value). Do
not write `Requested` from a value the VM itself rendered. Keep explicit typed edits + commit-on-Enter working.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Focus in and out of the IN field WITHOUT typing → `Requested` is byte-identical to before (5s stays 5s), `Delta` still non-zero, engine still receives the true request.
- [ ] Typing a new time + Enter/blur still commits (existing behaviour preserved).
- [ ] Typing an unparseable value → rejected, `Requested` unchanged, field reverts to the displayed value.
- [ ] Boundary: a request whose snap is identity (Snapped == Requested) still round-trips safely; sub-0.1s precision is never lost by a focus pass.
- Matrix — Required-Success: edited-commit works. Required-Fail: unparsed input rejected without mutating state. **Perf (no-I/O-on-path): a no-op focus pass performs ZERO writes — assert the marker raises no PropertyChanged and no re-snap occurs.**
