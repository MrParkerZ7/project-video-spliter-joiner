## Concept
Add a way to unload the current video / empty the join list and return the screen to its clean empty state, without restarting the app.

## Design
- **`SplitViewModel.ClearCommand`** → reset to empty: `InputPath=null`, `Info=null`, `Keyframes=[]`, `Markers.Clear()`, `Timeline` reset (no ticks/playhead), `LastResult=null`, `KeyframeWarning=null`; cancel the background keyframe index + `IsIndexingKeyframes=false`; `Operation.Reset()`; **unload the player** (see below). Raise all the derived `CanExecute`s (`CanRunSplit`, `CanSetCutAtPlayhead`, etc.). `CanExecute` = `HasFile` (and not `Operation.IsRunning` — disable or cancel-first during a running split).
- **Player unload:** add `void Unload()` (or `Close()`) to `IMediaPlayer` → `FfmeMediaPlayer` calls FFME `Close()` and/or clears `Source` so the video surface goes blank + resets Position/Duration/IsPlaying; `NullMediaPlayer` no-op; the test fake records it. `PlayerViewModel` gets a matching reset (Duration=null, IsReady=false, Position=0, PreviewFailed=false). Clear calls `Player.Unload()`.
- **`JoinViewModel.ClearCommand`** → `Items.Clear()` + reset the compat report / verdict, `OutputPath` (leave or clear — pick), `LastResult=null`, `Operation.Reset()`. `CanExecute` = `Items.Count > 0` (and not running).
- **UI:** a "Clear" button on `SplitView` (near Load) enabled on `HasFile`; a "Clear all" button on `JoinView` (near Add files) enabled when the list is non-empty.

## Detail
- Guard against clearing during a running op (disable, or cancel then clear).
- After clear, the screen matches a fresh start (Run disabled, no markers, blank player).
- Don't clear the remembered last-folders settings (that persists — G-010/T-038).

## Interfaces / contracts
- New `IMediaPlayer.Unload()` (additive → update `FfmeMediaPlayer`, `NullMediaPlayer`, all test fakes). `SplitViewModel.ClearCommand`, `JoinViewModel.ClearCommand`, `PlayerViewModel` reset. Engines unchanged.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Split Clear: with a file loaded + markers, Clear → `HasFile` false, `Markers` empty, `Info`/`Keyframes` cleared, timeline empty, `Player.Unload()` called, Run disabled (fake-tested).
- [ ] Clear `CanExecute` false when no file; true with a file; disabled (or cancels) during a running split.
- [ ] Join Clear all: with items, Clear → `Items` empty, compat/result reset; `CanExecute` false when empty.
- [ ] Background keyframe index is cancelled on clear (no stale write-back after).
- [ ] Build 0-warning; prior tests green.
- Matrix — Required-Success: clear returns to empty state. Boundary: clear right after load (index still running → cancelled); clear with no markers; clear an empty join list (disabled). Required-Fail: clear during a running split → disabled/cancel-first, no half state.

## Dependencies
None.

## Risks
Player surface not actually blanking → verify FFME `Close()`/source-clear live (app-run). Stale index write-back after clear → cancel the CTS + guard on HasFile.

## Out of scope
Confirmation prompt / undo; docs (T-048).
