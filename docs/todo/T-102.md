## Concept
A reusable **cut profile** — a named `{ intro-from-start, optional outro-from-end }` — that can be saved once and applied
to any row/batch, so same-series videos share their intro/outro trim in one click. This task is the MODEL + PERSISTENCE +
apply/save LOGIC (no UI — that's T-103). Supersedes the deferred `DefaultIntroSeconds` (a profile is the general form).

## Grounding (real signatures)
- `AppSettings : IAppSettings` (`src/App/Settings/AppSettings.cs:25`) — JSON persistence via a `SettingsDto` (`:170`
  Deserialize, round-trip), with existing typed props (`LastInputDir`, `HorizontalSplitRatio` w/ `ClampRatio`, etc.) each
  mirrored in the DTO. The established pattern: add a field to `IAppSettings` + `AppSettings` + `SettingsDto`, guard the
  setter (dirty-check), and round-trip in Load/Save. Older files must round-trip (missing field → default/empty).
- Cut points are `TimeSpan`; the apply-to-all convention (T-096) applies **intro as absolute from start**, **outro as
  time-from-END** (`Duration − outroStart`). A profile stores those two offsets directly.
- `BulkItemViewModel.IntroEnd`/`OutroStart` (CutMarkerViewModel, `Requested` setter re-snaps) + `AddOutro`/`ClearOutro` —
  applying a profile writes these per row (each re-snaps + re-validates against its own keyframes/duration).

## Design
1. **`CutProfile` record** (Core or App — prefer **Core** `src/Core/...` if it stays pure, else App; it's plain data):
   `record CutProfile(string Name, TimeSpan IntroFromStart, TimeSpan? OutroFromEnd)`. Serializable (store as seconds
   `double` in the DTO for stable JSON). Validation: non-empty name, non-negative offsets.
2. **Persistence** — add `IReadOnlyList<CutProfile> CutProfiles { get; }` + `SaveProfile(CutProfile)` / `DeleteProfile(name)`
   (upsert by name) to `IAppSettings` + `AppSettings`; mirror in `SettingsDto` as `List<CutProfileDto>` (Name +
   IntroSeconds + OutroSeconds?). Round-trip through Load/Save; missing/empty → empty list (older files safe). Dedup by name
   (case-insensitive).
3. **Apply logic** — a pure/testable method (on `BulkCutViewModel` or a small helper) `ApplyProfile(CutProfile, targets)`:
   for each target row set `IntroEnd.Requested = profile.IntroFromStart` (clamped), and if `OutroFromEnd is {} tail` set the
   outro at `target.Duration − tail` (via `AddOutro`/`OutroStart.Requested`, from END) else `ClearOutro()`. Each target
   re-snaps + re-validates against ITS OWN keyframes/duration; rows the profile invalidates (offset ≥ duration etc.) are
   **reported, not dropped** — reuse the `ApplyToAllReport { AppliedCount, InvalidatedRows }` shape from T-096.
4. **Save-current** — a method to build a `CutProfile` from a row's CURRENT cut: `IntroFromStart = row.IntroEnd.Requested`,
   `OutroFromEnd = row.HasOutro ? row.Duration − row.OutroStart.Requested : null`.

## Acceptance criteria + Case-Coverage Matrix
- [ ] `CutProfile(Name, IntroFromStart, OutroFromEnd?)` exists + validates; `IAppSettings.CutProfiles`/`SaveProfile`/`DeleteProfile` persist through a JSON round-trip (Save→Load returns the same list; upsert-by-name; delete works).
- [ ] Older settings files (no CutProfiles field) load cleanly → empty list (no crash / no data loss of other fields).
- [ ] `ApplyProfile(profile, rows)` sets intro-absolute + outro-from-end per row, re-snaps + re-validates per file, and reports invalidated rows (not silently dropped); `BuildProfileFromRow(row)` produces the inverse.
- [ ] WPF-free where it lives (CutProfile pure; if apply logic sits on the VM it stays ObservableObject/RelayCommand); `CoreIsUiFreeTests` green if CutProfile lands in Core.
- [ ] Build 0-warning; suite green + tests: round-trip persistence, upsert/delete/dedup-by-name, older-file-loads-empty, ApplyProfile (equal-length + shorter-target-invalidated + no-outro clears), BuildProfileFromRow.
- Matrix — Success: save a profile, reload, apply → rows get the cut. Boundary: profile outro on a shorter video (from-end still valid or invalidated+reported), no-outro profile clears a row's outro, duplicate name (upsert), corrupt/missing field (empty). Required-Fail: none.

## Dependencies
Reuses AppSettings DTO pattern + the T-096 apply-to-all re-snap/re-validate/report shape + CutMarkerViewModel.Requested.
Consumed by **T-103** (profile UI). Independent of T-100/T-101 (no player).

## Risks
JSON schema migration — add the field additively; never fail Load on a missing/old field. Store offsets as seconds
(double) not `TimeSpan` ticks for readable/stable JSON. Keep `ApplyProfile` re-validating per file (a profile valid on a
long episode may not fit a short one) — mirror apply-to-all exactly so behavior is consistent.

## Out of scope
The profile UI / dropdown / save button (T-103); pre-seeding new rows from a "last used" profile (a T-103 nicety);
profiles storing anything beyond the two offsets.
