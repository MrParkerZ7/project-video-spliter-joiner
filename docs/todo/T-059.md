## Concept
Relayout the screens to match the sample's UX — not just recolor, but adopt its structure: a header with tagline + format badge, file-info cards, labelled sections, mono DIR/NAME/FILE readouts, and the Join "Estimated result" panel.

## Design (from the extracted sample layout — confirm against a render first)
- **★ Two-column body (the sample's core layout — user-requested):** split the working area into **LEFT = the video/preview + timeline/scrubber** (the large visual area) and **RIGHT = a fixed-width tool panel/tab holding everything from Load/Clear downward** — Load, Clear, file-info card, Cut markers, Parts to export, Output DIR/NAME, and the Run (Split/Join) button. Today these controls sit **below** the video in one column; move them into a right-side panel beside the video, matching the sample. The right panel is a vertical stack (scrollable if tall); the left video area flexes to fill remaining width. The existing resizable-pane behavior (G-006) should govern the left/right split (draggable divider), or a sensible fixed right width if simpler — panel stays usable at small window sizes.
- **Header** (top, above/around the tabs): app name "VideoSplitJoiner" + tagline "lossless · no re-encode" (muted) + a format/status badge (e.g. "HEVC · MKV") — mono, small, gold accent mark.
- **Split screen:**
  - A **file-info card**: file name + a mono meta line "matroska · 10:00 · 1.4 GB" (container · duration · size — bind from `Info`), with a **Clear** affordance.
  - **Timeline** + **Position** labelled (mono), the player above.
  - A **"Cut markers"** section header over the marker list.
  - A **"Parts to export"** section with **All / None** chips over the segment-select list.
  - **Output** as mono **DIR** / **NAME** labelled fields.
  - Primary **"Split into N parts"** button (gold, count-aware — reuse the existing `RunLabel`).
- **Join screen:**
  - Clip list; **"Overwrite existing output"** checkbox; output **FILE** ("joined.mkv") mono.
  - An **"Estimated result"** panel — **Total duration** + **Approx. size** (compute from the selected clips' probed durations/sizes; label mono).
  - Primary **"Join N clips"** button (gold).
- Apply the token scale (surfaces for layering, mono labels, gold accents, tight radii) throughout. Keep all existing bindings/commands — wrap/relabel, don't rewire.
- **UX/UI Reviewer pass** comparing to the sample: typography (mono), spacing/density, the card/section/panel structure, gold accent usage, contrast. Fix findings.

## Detail
- New small computed bits: the file-info meta line (container·duration·size) and Join's estimated total-duration/approx-size — derive from existing `MediaInfo`/segment data (pure, unit-testable helpers).
- Preserve every command/binding (Load, markers, segments, Run, Clear, join add/reorder, etc.).
- Verify against a RENDER of the sample (browser/screenshot) for exact arrangement — the extracted labels give the structure; the render confirms spacing/order.

## Acceptance criteria + Case-Coverage Matrix
- [ ] **Two-column layout:** video/preview + timeline on the LEFT, all tool controls (Load, Clear, and everything below) in a RIGHT-side panel — matching the sample. Left flexes; right panel stays usable when the window is narrowed.
- [ ] Header with app name + "lossless · no re-encode" tagline + format badge.
- [ ] Split: file-info card (container·duration·size), "Cut markers" + "Parts to export (All/None)" sections, mono DIR/NAME output, count-aware gold Split button.
- [ ] Join: "Estimated result" panel (total duration + approx size), "Overwrite" toggle, mono FILE, gold Join button.
- [ ] Mono typography (IBM Plex Mono) on labels/readouts; token surfaces/accents/radii applied; readable contrast.
- [ ] All bindings/commands intact; build 0-warning; prior tests green + unit tests for the new compute helpers (meta line, estimated size/duration).
- [ ] UX/UI review vs the sample done; findings fixed.
- Matrix — Required-Success: screens read like the sample (structure + type + color). Boundary: no file loaded (empty states); long file names; many parts. (Exact look = app-run/user-verified against the render.)
