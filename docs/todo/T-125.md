## Concept
Let the user choose precision per batch, and make the trade-off legible BEFORE the run rather than
discovered after it. The default stays lossless — nobody pays a re-encode they did not ask for.

## Design
- A two-option choice near the output controls:
  - **Lossless (default)** — "cuts snap to the nearest keyframe; instant, no quality loss"
  - **Exact** — "cuts exactly where you set them; re-encodes about a second of video per cut"
- The per-row snap readout (T-119's `SnapNote`) becomes mode-aware: under Exact it shows the cut landing
  ON the requested time (no delta), so the row stops advertising an offset that will not happen.
- The `Set intro-end here` tooltip currently promises "(snaps to the nearest keyframe)" — it must state
  the ACTIVE mode instead of a hard-coded half-truth.
- Under Exact, surface the expected cost honestly (a short per-file re-encode) so a 200-file batch does
  not surprise anyone.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Default is Lossless; existing behaviour and speed are untouched for anyone who ignores this.
- [ ] Selecting Exact: the row readout stops showing a snap delta, the tooltip updates, the cost is stated.
- [ ] The chosen mode reaches the engine (assert on the recording fake), and is reflected per row in the result.
- [ ] Both layout modes; on-theme; survives a settings round-trip if persisted.
- Matrix — Required-Success: Exact selected → engine receives it. Required-Fail: a source that cannot be
  exact-cut reports the fallback in its row, not a silent wrong result. Boundary: 0 rows, mixed sources where
  some fall back. **Perf (no-I/O-on-path): switching mode performs zero probe/ffmpeg work.**

## Out of scope
Per-row precision (batch-level only for v1).
