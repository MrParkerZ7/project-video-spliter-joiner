## Concept
The UI for profile thumbnails (store from T-106): when saving a profile, capture a **default thumbnail = the source row's
intro-end frame**, let the user **Upload image…** to override or **Clear**, and **show the thumbnail beside the name** in
the profile ComboBox + wherever profiles are listed — so reuse is by sight.

## Grounding
- **T-106** provides: `CutProfile.ThumbnailPath`, `ProfileThumbnailStore.Save/Delete`, persistence.
- Profiles UI (T-103): `BulkCutView.xaml` profiles bar — the `ComboBox` (`ItemsSource={Binding Profiles}`) + the
  **Save popup** (`SaveProfileButton`/`OnSaveProfileClicked`/`SaveProfilePopup`, `CanSaveProfile`) + Save/Apply/Delete
  commands on `BulkCutViewModel` (grep `SaveProfileCommand`/`Profiles`/`SelectedProfile`).
- `IThumbnailService.GetThumbnailAsync(inputPath, TimeSpan time, int width, ct) → string? (temp jpg path)` —
  `src/Core/Thumbnails/IThumbnailService.cs:31`. The Bulk tab already holds the shared instance (T-101/G-037).
- `BulkCut.SelectedItem` (T-100) = the source row for the auto-default capture; its `IntroEnd.Snapped` = the frame time.

## Design
1. **Auto-default on Save** — when "Save current as…" fires: grab the source row's intro-end frame via
   `IThumbnailService.GetThumbnailAsync(SelectedItem.Path, SelectedItem.IntroEnd.Snapped, thumbW, ct)`, pass that jpg to
   `ProfileThumbnailStore.Save(name, framePath)`, and set the new profile's `ThumbnailPath`. Best-effort: if the grab
   fails (no file / probe pending), save the profile with a null thumbnail (a placeholder shows).
2. **Upload / Clear** — in the Save popup (and/or a small profile-manage affordance): an **Upload image…** button
   (`OpenFileDialog`, image filter) → `ProfileThumbnailStore.Save(name, chosenImage)` → sets `ThumbnailPath`; a **Clear**
   → `ProfileThumbnailStore.Delete` + null the path. A tiny preview of the current/pending thumbnail in the popup.
3. **Show in the picker** — the profile `ComboBox` `ItemTemplate` becomes `[thumb 24–32px] Name` (an `Image` bound to
   `ThumbnailPath` via a path→ImageSource converter that's null-safe → a placeholder chip when null). Same treatment
   wherever the selected profile is shown / applied. Keep it compact + on-theme (tokens).
4. **VM glue** (WPF-free) — `BulkCutViewModel` save flow calls the store + sets `ThumbnailPath`; a `SelectedProfile`
   thumbnail is exposed for binding; delete cascades (already in T-106). No new Core.

## Acceptance criteria + Case-Coverage Matrix
- [ ] "Save current as…" auto-captures the source row's intro-end frame as the profile's default thumbnail (best-effort; null if the grab fails).
- [ ] Upload image… overrides the thumbnail (stored via T-106); Clear removes it → placeholder; a preview shows in the popup.
- [ ] The profile ComboBox shows `[thumb] Name` (null-safe placeholder when no thumbnail); on-theme, compact.
- [ ] View + thin WPF-free VM glue (commands delegate to T-106 store + persistence); path→ImageSource binding is null-safe (no crash on a missing file).
- [ ] Build 0-warning; suite green + a VM test for the save-with-auto-default + upload/clear paths (fake IThumbnailService + store).
- Matrix — Success: save "Anime OP" → its intro-end frame becomes the thumb → shows in the picker; reload → still there. Boundary: grab fails (null thumb + placeholder), upload overrides, clear → placeholder, a profile whose thumbnail file was deleted externally (placeholder, no crash), apply-to-all unaffected. Required-Fail: none. (Look = app-run.)

## Dependencies
Needs **T-106** (model/store/persistence) + reuses `IThumbnailService` + `BulkCut.SelectedItem` (T-100). Sits alongside T-108.

## Risks
Path→ImageSource binding must be null-safe + not lock the file (load with `BitmapCacheOption.OnLoad` so the file isn't
held open — else Clear/overwrite fails). Keep the picker compact (thumbnails small). The auto-default grab is best-effort
+ off the UI thread — never block Save on it.

## Out of scope
The model/store (T-106); per-row cut-point thumbnails (T-108); cropping/editing the uploaded image.
