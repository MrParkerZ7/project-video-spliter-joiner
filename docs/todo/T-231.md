## Concept

xUnit1031 checks only the bodies of test methods. The same blocking wait T-221 removed or scoped in six places is still used through private helpers:

- `tests/App.Tests/BulkItemThumbnailTests.cs`: `Settle(row, pump)` and `SettleRequests(row)`, about 38 call sites. Some are in `async Task` tests after an await, for example `KeyframesResolve_GrabsIntroFrame_AtSnappedTime`.
- `tests/App.Tests/ExactFallbackRowTests.cs:79-80`: `Settle(row)`.
- `tests/App.Tests/ThumbnailPreviewViewModelTests.cs:218-223`: `WaitForGrab(vm)`.
- `tests/App.Tests/StaViewHarness.cs:103`: `done.Task.Wait(60s)`. This one is STA-bound and probably correct as it is.

The suite is green and these waits are bounded deadlock guards (T-137). But a blocking wait inside an async test holds a test thread that the runner's limited-concurrency context could otherwise use, and the analyzer cannot see them.

## Design

- For helpers used only by tests that need no pump on the test thread, add an async twin (for example `SettleRequestsAsync => row.InFlightGrabs.WaitAsync(30s)`) and switch the async tests to it.
- Keep the synchronous helper for pump-bound tests and the STA harness, each with a one-line comment saying why it blocks (the T-221 rule).
- Do not change the 30 s deadlock-guard semantics. Never assert wall-clock time (T-137).

## Acceptance criteria

- [ ] Every async test that only needs the grab finished awaits it rather than blocking on it.
- [ ] Pump-bound and STA call sites keep the synchronous wait and say why.
- [ ] Full suite green, 0 skipped, run twice at solution level with no new flake.
- [ ] `dotnet build -c Release --no-incremental` still has 0 warnings.

## Case coverage

| case | expected |
|---|---|
| Required-Success: converted async helper | tests pass as before |
| Required-Fail: a grab that never completes | the converted test fails with TimeoutException within the guard |
| Boundary: pump-bound helper | stays synchronous, commented |

## Out of scope

Changing `InFlightGrabs` or `InFlightGrab` in production code; the PumpContext design.
