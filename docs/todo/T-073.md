## Concept
Make the operation lifecycle unmistakable: Running shows an active progress state; Completed shows a clear ✓ success confirmation (with what was produced + open folder); Cancelled and Failed have their own clear surfaces. Fix the current behavior where the running UI silently vanishes on completion.

## Design
### VM (`OperationViewModel`)
- Add `bool IsCompleted => State == Completed`, `bool IsCancelled => State == Cancelled` (raise on `State` change alongside `IsRunning`).
- Add a `ResultSummary` string set on success — e.g. "Split into 3 parts" / "Joined 4 clips → joined.mkv". The producing VM (Split/Join) supplies the summary text (it knows part/clip counts + output); `OperationViewModel` exposes it. Clear it on `Reset()`/next run.
- Keep `Error` (Failed), `CanCancel`, `Progress`, `StatusText`, `EtaText`.

### View (`SplitView.xaml` + `JoinView.xaml`)
- Replace the `IsRunning`-only progress block with a state-driven panel:
  - **Running** — the gold progress bar + StatusText + ETA + Cancel (as today, visible on `IsRunning`).
  - **Completed** — a success row visible on `IsCompleted`: ✓ glyph in `OkBrush` (green) + `ResultSummary` + an **Open folder** button (reuse `OpenFolderCommand`). Persists until the next load/run/clear.
  - **Cancelled** — a muted row visible on `IsCancelled`: "Cancelled" in `TextMutedBrush` (neutral, not red).
  - **Failed** — keep the existing red `Operation.Error` block (Copy error / Open log).
- Use per-state `Visibility` bindings (or a small `OperationStateToVisibility` converter) — clean, no overlap between states.
- Ensure switching files / starting a new run / Clear resets the surface (no stale "done").

## Acceptance criteria + Case-Coverage Matrix
- [ ] Running: gold progress bar + status + ETA + Cancel (unchanged).
- [ ] Completed: ✓ green + result summary ("Split into N parts") + Open folder; stays visible after the run until next action.
- [ ] Cancelled: a clear muted "Cancelled" note (not error-red).
- [ ] Failed: red error block intact (copy/open log).
- [ ] Only ONE state surface shows at a time; a new run/load/Clear resets it (no stale done/cancel).
- [ ] Applied to BOTH Split and Join.
- [ ] `IsCompleted`/`IsCancelled`/`ResultSummary` unit-tested (state transitions Idle→Running→Completed/Cancelled/Failed, Reset clears). Build 0-warning; suite green.
- Matrix — Required-Success: finish a split → ✓ + summary; cancel → Cancelled note; fail → error block. Boundary: back-to-back runs (surface resets); load a new file after done (clears). Required-Fail: none.

## Dependencies
None (complements G-025 taskbar/per-part; independent).

## Risks
Stale Completed/Cancelled surface across runs — tie strictly to state transitions + Reset. Don't regress Failed/Cancel. Keep the summary text accurate (counts/output path).

## Out of scope
Toasts/sound; taskbar (G-025); scrollbar (T-072).
