## Reported
> I want button snapt-shot current play video into thumnail of profile thumnail

Play the preview to a frame that represents the profile, press a button, and that frame becomes the
profile's picture.

## Why this is small — every piece already exists

| need | already there |
|---|---|
| grab a frame at a time | `IThumbnailService.GetThumbnailAsync(path, time, width, ct)` — the same call the auto-thumbnail uses |
| the size profiles use | `ProfileThumbnailWidth = 96` (SPEC-007 I61) |
| store it + fold onto the profile | `TryAttachThumbnail(name, imagePath, out detail)` — classified outcomes since T-129 |
| the frame the user is looking at | `Player.Position` |
| the file it came from | `_selectedItem.Path` |

So this is a third entry point onto an existing path, not new machinery. Today there are two:
**auto** (grabs at `IntroEnd.Snapped` when a profile is saved — deliberately silent on failure, SPEC-007
I66) and **upload** (user picks an image file — reports failure, T-129). This adds **snapshot**, which is
a deliberate gesture and therefore **reports** like upload, not like auto.

## Design
1. `SetProfileThumbnailFromPlayheadAsync()` on `BulkCutViewModel`, behind a
   `SnapshotProfileThumbnailCommand`, guarded by a `CanSnapshotProfileThumbnail` =
   *a profile is selected* AND *a row is selected* AND `Player.IsReady`.
2. Grab at `Player.Position` from `_selectedItem.Path` at `ProfileThumbnailWidth`, then hand the frame to
   `TryAttachThumbnail` — reuse, do not re-derive. A failed grab and a refused store both surface on the
   screen's existing error surface, exactly as the upload path does (`ReportThumbnailUploadFailure`).
3. Button sits in the profile bar next to **Thumbnail…** (the T-129 upload), since they do the same job
   from different sources. Label it for what it does — e.g. **📷 Use current frame**.
4. Disabled state must be legible: with no profile selected it should say why, not just be inert — that
   was G-044's finding about the upload button and it applies identically here.

## Acceptance criteria
- [x] With a profile selected and the preview parked on a frame, the button replaces that profile's
      thumbnail with that frame, and it survives a restart.
- [x] The frame captured is the one at the playhead — asserted against the time handed to the service,
      not merely "a grab happened".
- [x] The grab uses the profile thumbnail width, so the stored picture matches the auto path's.
- [x] A failed grab and a refused store are REPORTED (deliberate gesture), and leave the profile's
      existing thumbnail untouched.
- [x] The command is disabled without a selected profile / row / ready player, and the reason is legible.
- [x] Performance: exactly one frame grab per press — no re-probe, no re-scan, and no grab at all when
      the command is disabled.
- [x] SPEC-007 gains the invariant (a third entry point onto the attach path, reporting like upload).
- [x] Rebuilt and relaunched.
- [x] `SnapshotProfileThumbnailTests` covers the gesture end to end at VM level (capture, store,
      failure reporting, and the disabled-reason). Shipped in v1.1.0.

## Out of scope
Cropping or editing the captured frame. Snapshotting into anything other than the selected profile —
per-row thumbnails already come from the cut points (T-108).
