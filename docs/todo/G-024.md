## Why / vision
The app's own csproj Description says "Split and join video files with a **bundled** ffmpeg," but a clean Release build does **not** bundle it — `FfmpegBinaryLocator` looks for an app-local `ffmpeg/` folder or PATH, and neither exists in a fresh build output. This surfaced 2026-07-18: launching the Release exe directly failed with "The ffmpeg tool could not be found" / "Could not locate 'ffprobe'"; it only worked because `app-run` had ffmpeg on PATH. Patched by hand for that build; the durable fix is a build-time copy so every build self-bundles.

## Grounding (2026-07-18)
- `FfmpegBinaryLocator` resolution order: (a) explicit override, (b) app-local `ffmpeg/` folder next to the assembly, (c) PATH. It does NOT walk up to the repo `ffmpeg-shared/`.
- The repo root has `ffmpeg-shared/` (gitignored, populated by `packaging/fetch-ffmpeg-shared.ps1`) with ffmpeg.exe, ffprobe.exe + the shared DLLs (avcodec-61, avformat-61, …). FFME's preview finds these by walking up from BaseDirectory (App.xaml.cs) — so preview works; only the CLI locator has the gap.
- `src/App/VideoSplitJoiner.App.csproj` has no ffmpeg copy step today.

## Decisions
- **D1 · MSBuild copy target** — add a `Target` (AfterTargets="Build") to the App csproj that copies `../../ffmpeg-shared/*.{exe,dll}` into `$(OutDir)ffmpeg/`. That app-local `ffmpeg/` is exactly where `FfmpegBinaryLocator` looks — fixes the CLI locator for every Debug/Release build.
- **D2 · Graceful when absent** — a fresh clone lacks `ffmpeg-shared/` until the fetch script runs; the target emits an MSBuild `Warning` (not an error) and skips, so `dotnet build`/`test` still succeed without ffmpeg present.
- **D3 · Publish is separate** — bundling into `dotnet publish` single-file output is a T-010 packaging concern; this goal fixes the plain build (which is what broke). Extend to Publish only if trivial.

## Plan
```
T-067 add the ffmpeg-shared → $(OutDir)ffmpeg/ copy target (graceful-when-absent) to App.csproj; verify a clean Release build bundles it
```

## Risks
- Path assumption (`../../ffmpeg-shared`) — the App csproj is at `src/App/`, repo root is two up; verify the relative path resolves.
- Don't fail the build when ffmpeg-shared is missing (Warning, not Error) — CI / fresh clones must still build.

## Out of scope
Publish/single-file bundling (T-010); teaching FfmpegBinaryLocator to walk up (the copy target is cleaner); fetching ffmpeg itself (that's the existing fetch script).
