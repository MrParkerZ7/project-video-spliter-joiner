## Why / vision
Bulk Cut lets you mark intro/outro cuts per row, but today you mark them blind (a scrub bar + hover thumbnail, no
playback). The Split tab already has a real preview player with jog controls; Bulk Cut should reuse it so you can **watch
the video, jog to the exact intro end / outro start, and set the cut from the playhead** — then, because same-series
videos share an intro, **save that intro/outro as a reusable profile** and apply it across the batch in one click.

## Design decisions (chosen — flag if you'd prefer otherwise)
- **ONE shared preview player bound to the SELECTED row** — NOT a player per row (dozens of FFME decoders is infeasible).
  BulkCutViewModel gains a `SelectedItem`; selecting a row opens its file in the single shared `Player` (reusing
  `MediaReopenGuard`/T-080 for a safe re-open on selection change). The preview pane sits above the row list.
- **The preview pane reuses Split's transport wholesale** — `PlayerView` + `TimelineView` + the `SkipCommand` jog buttons
  (the ±1s/5s/10s/20s/1m set already exists). Plus two new buttons wiring the playhead → the selected row's cut points.
- **A cut PROFILE = `{ Name, IntroFromStart: TimeSpan, OutroFromEnd: TimeSpan? }`** (outro measured from END to match
  apply-to-all), persisted as a list in `AppSettings` (JSON DTO). Apply-to-selected or apply-to-all re-snaps + re-validates
  per file (same rules as the existing apply-to-all). This **supersedes the deferred `DefaultIntroSeconds`** (a profile is
  the general form; a "last used" profile can pre-seed new rows).
- The **per-row dual-handle scrub bar (T-097) stays** — quick marking; the preview pane is for precise/played marking.
