## Why / vision
Bulk Cut has grown into a rich tab (batch trim · preview player · profiles · thumbnails) but three rough edges remain:
its layout ignores the app's vertical/horizontal mode (Split adapts, Bulk doesn't), the profiles controls are a flat
inline strip, and "Apply → all" only fires the first time. This epic polishes all three.

## Design decisions (chosen — flag if you'd prefer otherwise)
- **Layout:** reuse `OrientedSplitPanel` (as Split does) for the **preview-pane ↔ row-list** split — the natural Bulk
  analog of Split's video ↔ tools. Flip on `MainViewModel.IsVertical` (or its inverse where the natural arrangement
  wants it), with `HorizontalSplitRatio`/`VerticalSplitRatio` remembered (a Bulk-specific ratio pair if reusing Split's
  would fight it — decide at build).
- **Profiles UI:** a compact bordered "Profiles" group/card (not a flat strip) — the thumbnail-aware ComboBox prominent,
  Save/Apply/Delete grouped with clear affordances; keep it unobtrusive when empty. Exact treatment = UI Designer lens.
- **Apply-to-all fix:** whichever button is broken, the fix makes re-invocation reliable (re-raise CanExecute + ensure a
  re-apply actually propagates / doesn't lose the selected profile) — root-caused, not patched blind.

## Out of scope (this epic)
New profile features; new layout modes beyond the existing vertical/horizontal toggle; Split/Join layout changes;
auto intro/outro detection.
