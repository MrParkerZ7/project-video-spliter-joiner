## Concept
A UI-free Core service that extracts a single video frame at a given time to a temp image file (via the ffmpeg CLI), with a time-bucketed cache, request coalescing, cancellation, and best-effort (never throws) semantics — the data source for the scrub-bar hover thumbnail.

## Design
- **`IThumbnailService` / `FfmpegThumbnailService` in `src/Core/Media/` (or `Thumbnails/`):**
  - `Task<string?> GetThumbnailAsync(string inputPath, TimeSpan time, int width, CancellationToken ct)` — returns the temp file path, or `null` on any failure (best-effort; catch + return null, never throw).
  - Args via `FfmpegArgs.ForFfmpeg()`: **fast seek** `-ss <time>` BEFORE `-i <input>`, then `-frames:v 1 -vf scale=<width>:-1 -y <tempPath>` (use `.Raw(...)` for the flags + `.Input`/`.Output`). Keyframe-accurate fast seek (fine for preview).
  - **Cache:** key = (inputPath + rounded time bucket, e.g. `TimeSpan` floored to 1s OR nearest keyframe if a keyframe list is passed) → temp path. Repeat requests in the same bucket return the cached file without re-running ffmpeg. Bound the cache (LRU or max entries/size); evict oldest.
  - **Coalesce/cancel:** at most one extraction in flight per service; a newer request supersedes an older pending one (cancel or drop the stale). Model it so the caller (VM) can fire on every debounced hover and only the latest resolves — mirror the scrub coalescing contract.
  - **Temp location:** a dedicated cache dir under `%LOCALAPPDATA%/VideoSplitJoiner/thumb-cache/<hash-of-input>/<bucket>.jpg`. A `Clear(inputPath)` / `ClearAll()` deletes the dir (called on new load/Clear/unload). Best-effort deletion (never throw).
  - Inject `IFfmpegBinaryLocator`/`IFfmpegRunner` the same way the split/join engines do; keep Core UI-free (no WPF, no ImageSource — return a PATH, the App layer loads the image).
- Reuse the `-c copy` / typed-args discipline: no string concatenation; go through `FfmpegArgs`.

## Acceptance criteria + Case-Coverage Matrix
- [ ] `GetThumbnailAsync` produces a temp jpg for a valid (file, time) and returns its path; the ffmpeg args are `-ss` (pre-input) + `-frames:v 1` + `scale=W:-1`.
- [ ] Same time-bucket twice → second call hits the cache (no second ffmpeg run) — assert via a fake runner's call count.
- [ ] A superseded/cancelled request doesn't clobber a newer one; cancellation is honored.
- [ ] ffmpeg failure / missing file → returns null, does NOT throw.
- [ ] `Clear`/`ClearAll` removes temp files; best-effort (missing dir = no-op, no throw).
- [ ] Core stays UI-free (`CoreIsUiFreeTests` green). Build 0-warning; suite green + new service tests (with a fake `IFfmpegRunner` recording args/counts).
- Matrix — Required-Success: grab at T → path returned + correct args. Boundary: T=0, T=end, same bucket cached, tiny width; missing/corrupt input → null. Required-Fail: throws → not allowed (must be null).

## Dependencies
None (Core-only). Blocks T-078 (the hover UI consumes this).

## Risks
Binary-output pitfall avoided by writing a temp file (don't pipe to the UTF-8 stdout runner). Cache growth → bound it. Coalescing correctness → unit-test supersede/cancel.

## Out of scope
The hover UI/Popup (T-078); sprite sheets; frame-exact seek.
