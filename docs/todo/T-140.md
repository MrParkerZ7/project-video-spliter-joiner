## Found
While verifying a running app, the user's real settings file
(`%APPDATA%\VideoSplitJoiner\settings.json`) contained:

```json
{ "lastInputDir": "C:\videos", "lastOutputDir": "C:\out", "layoutMode": "Vertical" }
```

`C:\videos` and `C:\out` are **unit-test fixture paths** (`BulkRowIntentTests`, `SetAtPlayheadScopeTests`,
`SplitViewModelNonBlockingLoadTests`, and others). They are not paths a user would have.

## Cause
`SplitViewModel` and `JoinViewModel` default their settings dependency to a REAL store:

```csharp
_settings = settings ?? new AppSettings();     // SplitViewModel.cs:103, JoinViewModel.cs:49
```

`AppSettings()` with no path resolves `DefaultFilePath()` = `%APPDATA%\VideoSplitJoiner\settings.json` —
the user's actual file. Roughly fifteen tests construct these view models WITHOUT injecting settings
(`new SplitViewModel(probe, engine)`, `new JoinViewModel(engine, probe)`), then load a fixture path, which
sets `LastInputDir`, whose setter calls `Save()`. The suite therefore writes the user's real settings on
every run.

## Why it matters beyond tidiness
- It silently resets a real user's last-used folders — a small but genuine data loss they would experience
  as "it keeps forgetting where my videos are".
- It couples test runs to machine state: a test could in principle read back what a previous test wrote.
- It writes to the user's profile from CI or any machine that runs the suite.

## Design
1. **A guard that cannot be forgotten.** A module initializer in the test assembly points
   `AppSettings`'s default path at a per-run temp directory, so even a test that forgets to inject can
   never touch the user's file. Fixing only the call sites leaves the trap armed for the next test.
2. Then fix the call sites anyway — a test that depends on real settings is a test with a hidden input.
3. Consider whether the `?? new AppSettings()` fallback earns its place at all; a composition root that
   must pass settings explicitly is harder to get wrong.

## Acceptance criteria
- [x] Running the full suite leaves `%APPDATA%\VideoSplitJoiner\settings.json` byte-identical.
- [x] A test asserts that — reading the real default path and failing if the suite wrote to it.
- [x] The guard works even for a view model constructed without injected settings.
- [x] The user's current file is repaired (the test paths removed) as part of the fix.

## Out of scope
Redesigning settings persistence.
