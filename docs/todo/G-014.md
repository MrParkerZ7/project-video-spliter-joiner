## Why / vision
Once you load a file there's no way to unload it / start over except opening a different one — and the Join list can't be emptied. A "Clear" resets the screen so you can begin fresh without restarting the app.

## Gap from current state
`SplitViewModel` has `LoadAsync` (which resets state on a NEW load) but no explicit clear/unload — no way to return to the empty state while keeping the app open. `JoinViewModel` has add/remove per item but no "clear all". The player has no unload path exposed for a clear.

## Decisions
- **D1 · Split "Clear"** — a `ClearCommand` on `SplitViewModel` that returns it to the empty state: `InputPath=null`, `Info=null`, `Keyframes` empty, `Markers.Clear()`, timeline reset, `LastResult=null`, `KeyframeWarning=null`, `IsIndexingKeyframes=false` (cancel the background index), `Operation.Reset()`, and **unload the player** (stop + clear source). Enabled only when `HasFile`.
- **D2 · Join "Clear all"** — a `ClearCommand` on `JoinViewModel`: `Items.Clear()` + reset compat/`OutputPath`(optional)/`LastResult`/`Operation`. Enabled only when `Items.Count > 0`.
- **D3 · Player unload** — expose an unload on `IMediaPlayer` (e.g. `Close()`/`Unload()` mapping to FFME `Close()` / clear `Source`); `NullMediaPlayer` no-op; fake records it. Or reuse `Stop` + a source-clear — pick the clean seam so the video surface goes blank on clear.

## Risks
- Clearing mid-operation (a split running) → disable Clear while `Operation.IsRunning`, or cancel first; don't leave a half state.
- Player unload must actually blank the FFME surface (verify live via app-run).
