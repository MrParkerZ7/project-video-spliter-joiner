## Why / vision
Today "split" always writes every part between the cut points. If you have a 2-hour recording and only want one 10-minute part, you still get all the surrounding parts written to disk. Letting you SELECT which parts to keep — and writing only those — saves time and disk, which is exactly what the user expects.

## Gap from current state
- `SplitEngine.SplitAsync` takes cut points and produces ALL contiguous segments `[0..s1][s1..s2]…[sN..end]` via the segment muxer (one pass, all-or-nothing). No per-part selection; the UI has cut markers but no segment list.
- **BUT** `SplitArgsBuilder` already has a **per-segment `-ss/-to -c copy` extraction path** (the fallback) — extracting an arbitrary subset of ranges is a natural fit for it (write only the selected ranges).

## Decisions
- **D1 · Derive + show segments** — from the cut markers, compute the N parts (each `[start,end]` with duration); show them in the Split screen as a **checkable list** (part #, `MM:SS–MM:SS`, duration), all checked by default. Recomputed as markers change.
- **D2 · Export only selected** — Run writes only the checked parts. For a full/contiguous set, keep the fast segment-muxer path; for a SUBSET, use the existing **per-segment `-ss/-to -c copy`** path to write only the selected ranges (so unselected parts cost no disk/time). `SplitRequest` gains the selected-segment set (or the engine takes explicit ranges).
- **D3 · Still lossless** — every path stays `-c copy` (invariant preserved); segment boundaries remain keyframe-snapped as today.

## Risks
- Per-segment `-ss/-to -c copy` boundary accuracy (keyframe start) — reuse the snapped keyframe times so a selected part starts cleanly (same as the segment muxer's boundaries).
- "Select none" → Run disabled; "select all" → same result as today.
- Naming: output part numbers should reflect the selection (e.g. keep original part indices, or renumber — pick one, document it).

## Out of scope
Merging selected parts into one output (that's join), re-ordering parts, per-part rename UI — later.
