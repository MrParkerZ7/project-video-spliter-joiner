## Concept
The Bulk Cut UI for cut profiles (model + persistence from T-102): **save the current cut as a named profile**, and
**apply a saved profile** to the selected row or to all rows (one click for same-series batches). Plus light manage
(rename/delete).

## Grounding
- **T-102** provides: `IAppSettings.CutProfiles`/`SaveProfile`/`DeleteProfile`, `ApplyProfile(profile, targets)` (re-snap +
  re-validate + `ApplyToAllReport`), `BuildProfileFromRow(row)`.
- **T-100** provides `BulkCut.SelectedItem` (the source for "save current" + the target for "apply to selected").
- The existing apply-to-all UI (T-097 — the `⧉` per-row button + `ApplyToAllReport` surfacing) is the visual precedent for
  reporting invalidated rows.
- Tokens + the themed `ComboBox`/`Button` styles in `Controls.xaml`; the `HeroButton`/`AccentButton` for primary actions.

## Design
1. **Profiles bar** — a compact control in the Bulk tab header/toolbar: a **profile `ComboBox`** (lists `CutProfiles` by
   name) + **[Apply → selected]** and **[Apply → all]** buttons + a **[Save current as…]** button (prompts for a name via a
   small inline textbox / themed dialog) + a **[Delete]** for the selected profile. Keep it out of the way when no profiles
   exist (a subtle "Save a cut profile" affordance).
2. **Save current** — from `SelectedItem` (or the last-edited row): `BuildProfileFromRow` → prompt name → `SaveProfile`
   (upsert). Disabled when no valid source row.
3. **Apply** — `[Apply → selected]` calls `ApplyProfile(profile, [SelectedItem])`; `[Apply → all]` calls it over all
   enabled rows. Surface the returned `ApplyToAllReport` (`AppliedCount` + `InvalidatedRows`) the same way T-097 does
   (a brief inline note / the invalidated rows keep their chip) — reported, not silent.
4. **Optional nicety** — pre-seed each newly-added row's intro from a "default profile" (a pinned/last-used profile), the
   graceful replacement for the deferred `DefaultIntroSeconds`. Keep it opt-in/simple; skip if it bloats scope.
5. **Naming UX** — validate non-empty/unique name (upsert on collision with a confirm); trim.

## Acceptance criteria + Case-Coverage Matrix
- [ ] A profiles bar in the Bulk tab: ComboBox of saved profiles + Save-current-as + Apply-to-selected + Apply-to-all + Delete.
- [ ] Save current builds a profile from the selected row's cut and persists it (survives app restart via T-102); apply writes the cut to the target(s), re-snapped/re-validated, with invalidated rows reported.
- [ ] Empty-profiles state is unobtrusive; naming validated; delete works; all on-theme (tokens, themed ComboBox/buttons).
- [ ] View + thin VM glue only (commands delegate to T-102's ApplyProfile/SaveProfile); WPF-free VM discipline held.
- [ ] Build 0-warning; suite green + a VM test for the save/apply commands (using a fake IAppSettings + rows).
- Matrix — Success: save "Anime OP" from ep01, apply-to-all → every row trimmed; reload app → profile still there. Boundary: apply a profile to a shorter video (invalidated + reported), duplicate name (upsert confirm), no selection (Save disabled), delete the applied profile. Required-Fail: none. (Look = app-run.)

## Dependencies
Needs **T-102** (model/persistence/apply) + **T-100** (SelectedItem). Sits alongside T-101's preview pane (independent but
complementary — set cuts via the pane, then save as a profile).

## Risks
Don't clutter the Bulk toolbar (it already has Add/Clear/Apply-to-all + Run) — a compact profiles ComboBox group, maybe
collapsible. The name-prompt should be a themed inline input, not a raw WPF dialog. Keep apply consistent with apply-to-all
(same re-snap/report semantics) so users aren't surprised.

## Out of scope
The player/pane (T-101); profile import/export/sharing; profiles with more than intro/outro; auto-detect.
