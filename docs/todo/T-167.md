## Found

[[T-164]] discovered that Split's whole delete-original feature was **inert in the shipped app**: every
view-model test passed, every invariant was documented, and `MainViewModel` simply never passed
`SplitViewModel` an `IOriginalDisposer`. The feature worked perfectly in the suite and did nothing when
a user clicked it. It was caught by reading a doc claim against the code, not by a test.

The fix added `TheCompositionRootWiresADisposerIntoSplit` (`SplitDeleteOriginalTests.cs:340`), which
constructs the real `MainViewModel` and asserts the wiring survives. **Bulk Cut has no equivalent** —
`grep` finds exactly one composition-root test in the suite, and it names Split.

Bulk Cut's disposer is wired correctly today. That is the point: so was every unit test on Split's, right
up until the day it shipped doing nothing. The class of bug is "the seam is tested, the plug is not", and
one screen currently has the guard while the other, which has the same seam and the same destructive
consequence, does not.

## Design
Mirror the Split test for Bulk Cut: construct the real `MainViewModel`, reach the `BulkCutViewModel` it
built, and assert a non-null `IOriginalDisposer` of the shipped type. Keep it in the Bulk Cut delete
tests beside the behaviour it protects, not in a separate wiring file — the Split one is placed that way
deliberately, so the guard is read by whoever next touches the feature.

Consider whether the two should share one parameterised test over the screens that own a disposer. Prefer
that only if it stays as loud on failure: this test's whole value is naming which screen shipped inert.

## Acceptance criteria
- [ ] A test constructs the real composition root and asserts Bulk Cut receives a disposer.
- [ ] Mutation: removing `originalDisposer:` from the `BulkCutViewModel` construction in
      `MainViewModel` fails **that** test, and no view-model test notices — demonstrating the gap this
      closes rather than asserting it.
- [ ] The Split guard still passes unchanged.

## Out of scope
Auditing every other constructor argument in the composition root. Worth doing, much larger, and the
disposers earn priority because their failure mode is silent and destructive-adjacent (the user believes
files were cleaned up).
