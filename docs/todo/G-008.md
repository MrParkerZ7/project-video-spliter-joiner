## Why / vision
Dropping/opening a video feels slow because the whole load blocks on building the keyframe index. The video should appear immediately (like any player); the keyframe index — only needed when you actually place a cut — can build in the background and be faster besides.

## Gap from current state (diagnosed, not guessed)
`SplitViewModel.LoadAsync` (src/App/ViewModels/SplitViewModel.cs:249):
- L266 `await ProbeAsync` (fast metadata) ✓
- **L270 `await GetKeyframesAsync` — the load BLOCKS on the full keyframe scan**
- **L301 `Player.Open(path)` — the preview only opens AFTER the scan finishes**
So on a long/4K file you wait for the entire index before seeing anything.
And the scan (`MediaProbe.GetKeyframesAsync`, MediaProbe.cs:152) uses `ffprobe -skip_frame nokey -show_entries frame=pts_time,…` — a **frame-level decode-side scan**, which is the slow part.

## Decisions
- **D1 · Decouple load from the scan** — after `ProbeAsync`, immediately set info + `InputPath` + `Player.Open(path)` so the preview shows; run `GetKeyframesAsync` as a background task. Expose an `IsIndexingKeyframes` / "keyframes ready" state (a small "indexing…" hint); update the coarse-GOP warning when it completes.
- **D2 · Faster scan** — replace `-skip_frame nokey` frame scan with a **packet-level** read: `ffprobe -select_streams v:0 -show_packets -show_entries packet=pts_time:packet_flags -print_format json` → keep packets whose `flags` contain `K` (keyframe). Demux-only, no frame decoding → substantially faster. Same sorted-distinct `TimeSpan` output + cache + snap contract preserved.
- **D3 · Snap-before-ready** — if the user places a cut before the index is ready, don't block the app: either await the (now-fast) index just for that action, or mark the cut "snapping…" and finalize its snapped time when the index lands. Pick the least-surprising (a brief await on the fast scan is likely fine).

## Risks
- Snap depends on the index → D3 must handle "cut placed before index ready" cleanly (don't crash / don't silently mis-snap).
- Packet-flags format varies slightly by container → parse the `K` flag robustly; keep a fallback to the frame scan if packets yield nothing.
- Background task + cancellation on rapid re-load (load B while A still indexing) → cancel the stale index.

## Out of scope
Partial/windowed keyframe indexing (only near the playhead), a persistent on-disk index cache, GPU-accelerated probing — later if still slow.
