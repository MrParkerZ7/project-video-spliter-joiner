## Reported
> set intro/outro-end here button suppose to set to all, or just have an option to set all

## Root cause
`BulkCutViewModel.SetIntroAtPlayhead` / `SetOutroAtPlayhead` write `_selectedItem` only. Every other row
keeps intro 0 / no outro, stays a no-op trim, and is auto-excluded from the batch — which is the whole of
T-134's "why did Run cut one file".

The capability already exists as `ApplyToAllCommand` (the ⧉ button in the row template), including the
non-obvious-but-correct rule that **the outro is measured from the END of each file** so one gesture fits
episodes of different lengths. This ticket does not reimplement that — it puts it behind the gesture the
user actually reaches for.

## Design
1. **An explicit, persistent choice next to the two playhead buttons** — a checkbox/toggle reading
   *"Apply to all selected rows"*, bound to a new VM property, **defaulting to ON** (the tab is called
   Bulk Cut; the surprising default is the current one).
2. When on, `SetIntroAtPlayhead` / `SetOutroAtPlayhead` write the selected row and then fan out to every
   **`IsCheckedByUser`** row — the raw intent, matching `ApplyToAll` / `ApplyProfileToAll` targeting
   (SPEC-011 I56), so a row excluded only because it has no cut yet is included and becomes eligible.
3. **Reuse `ApplyToAll`'s semantics, do not duplicate them**: re-snap against each row's own keyframes,
   measure the outro from the end of each file, and report rows the copy invalidated via
   `ApplyToAllReport` rather than dropping them silently.
4. When off, behaviour is exactly as today (selected row only). One user-visible setting, no hidden modes.
5. Persist the choice in `AppSettings` like the other Bulk Cut preferences, so it is not re-decided every
   session.

## Acceptance criteria
- [x] With the toggle on, one "Set intro-end here" gives every selected row a cut, and `Run bulk cut (N)`
      counts them all.
- [x] The outro fans out measured from each file's END — a 20-minute and a 45-minute episode both keep the
      right tail. Asserted, since this is the clause most likely to be reimplemented wrongly.
- [x] Rows the copy invalidates are reported, not silently dropped.
- [x] With the toggle off, only the selected row changes.
- [x] Unchecked rows are never written to, on or off.
- [x] The choice survives a restart.
- [x] Performance: the fan-out is O(N) pure VM state — no re-probe, no thumbnail re-grab, and the batch
      projection refreshes once for the whole write (the T-128 suspend-guard idiom).
- [x] SPEC-011 updated; rebuilt and relaunched.
- [ ] Gesture verified by hand (yours — the app is running with it).

## Out of scope
Removing the per-row ⧉ button — it stays for the copy-one-row-onto-the-rest case.
