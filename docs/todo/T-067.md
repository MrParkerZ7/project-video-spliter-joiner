## Concept
Make every build self-bundle ffmpeg: an MSBuild target copies the repo-root `ffmpeg-shared/` binaries into an app-local `ffmpeg/` folder in the build output — where `FfmpegBinaryLocator` looks — so the built exe splits/joins without ffmpeg on PATH. Graceful (Warning, not Error) when `ffmpeg-shared/` is absent.

## Design
- In `src/App/VideoSplitJoiner.App.csproj`, add a `Target Name="CopyBundledFfmpeg" AfterTargets="Build"` that copies `$(MSBuildProjectDirectory)\..\..\ffmpeg-shared\*.exe` + `*.dll` → `$(OutDir)ffmpeg\`, `SkipUnchangedFiles="true"`.
- Guard: glob into an item; if empty, emit `<Warning>` and skip the copy (fresh clone before `packaging/fetch-ffmpeg-shared.ps1`).

## Acceptance criteria
- [ ] `dotnet build -c Release` (clean) → `bin/Release/net8.0-windows/ffmpeg/` contains ffmpeg.exe, ffprobe.exe, + the shared DLLs.
- [ ] Same for Debug output.
- [ ] With `ffmpeg-shared/` present, build is 0-warning about ffmpeg; with it absent, build succeeds with a single explanatory Warning (not an Error).
- [ ] Launching the built exe directly (no PATH ffmpeg) can probe/split/join.
- [ ] Existing tests green.

## Dependencies
None.

## Risks
Relative path `..\..\ffmpeg-shared` from `src/App/`. Don't fail the build when absent.

## Out of scope
Publish/single-file bundling (T-010).
