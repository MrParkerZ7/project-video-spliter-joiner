## Concept

`SmartCutArgsBuilder.VideoEncoders` (`SmartCutArgsBuilder.cs:18-30`) maps these codecs:
- vp9 → libvpx-vp9;
- vp8 → libvpx;
- av1 → libsvtav1;
- mpeg4 → mpeg4;
- mpeg2video → mpeg2video.

None of them has ever been decoded across the head/tail joint. HEVC's corruption (T-189) shows the joint must be
proven per codec: the concat output takes the head's codec configuration, and only H.264 gets its parameter sets
converted in-band.

Run T-189's `SmartCutJointIntegrity` and T-190's joint-timing check on a synthetic fixture of each codec, in a
container that holds it. A codec that fails falls back with a stated reason, as HEVC does.

## Why later

- It is outside the 4K performance scope of G-059.
- These codecs are rare in 4K camera footage.
- They were unverified before G-059 too. T-190 changes their bytes, not their verification status.

## Trigger

- Any report of an Exact cut on one of these codecs.
- A correctness sweep before the next release.
