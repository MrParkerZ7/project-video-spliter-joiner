## Concept
Show the running split/join progress on the Windows taskbar button (a live fill), and surface the ETA + overall % via the window title so it's readable from the taskbar (the button can't render text).

## Design
- **`MainWindow.xaml`:** add `<Window.TaskbarItemInfo><TaskbarItemInfo ProgressState="{Binding ...}" ProgressValue="{Binding ...}" /></Window.TaskbarItemInfo>`. The DataContext must reach the `OperationViewModel` — bind through the same VM the Split/Join screens use (check MainViewModel wiring; the operation may be per-screen, so bind to the active screen's Operation, or expose a top-level "current operation" on MainViewModel).
- **`OperationViewModel`:** add a computed `System.Windows.Shell.TaskbarItemProgressState TaskbarProgressState` — `None` when `!IsRunning`; `Indeterminate` when `IsIndeterminate`; `Error` when the last run failed/cancelled; else `Normal`. Raise `OnPropertyChanged` for it wherever `IsRunning`/`Progress`/`State` change. `ProgressValue` binds to the existing `Progress` (0..1). Keep Core UI-free — `TaskbarItemProgressState` lives in `PresentationFramework`, which the App VM can reference (it already is a WPF assembly), NOT Core.
- **ETA in the window title (`MainViewModel` or MainWindow):** while running, set the Window `Title` to e.g. `"Splitting 45% · ~1m 20s — Video Split / Join"` (compose from `Operation.StatusText` short verb + `Progress` % + `EtaText`); revert to `"Video Split / Join"` when idle. Implement as a bound `WindowTitle` property (preferred, testable) or update in the VM. Ensure it doesn't fight the caption-row title text (the caption shows the app name; the OS Title can differ).

## Acceptance criteria + Case-Coverage Matrix
- [ ] During a split/join the taskbar button shows a green progress fill tracking `Operation.Progress`.
- [ ] While "Preparing" (indeterminate) the taskbar shows the indeterminate state; a real fraction flips it to Normal.
- [ ] On failure/cancel the taskbar shows Error (red); on completion/reset it clears to None (no stuck bar).
- [ ] The window title shows overall % + ETA while running and reverts to the plain title when idle.
- [ ] `TaskbarProgressState` is unit-tested (idle→None, indeterminate→Indeterminate, running→Normal, failed→Error); build 0-warning; suite green.
- Matrix — Required-Success: run → taskbar fills + title shows ETA. Boundary: instant/tiny op (fill appears+clears cleanly); cancel mid-run (Error then None). Required-Fail: none.

## Dependencies
None (App-layer only; Core untouched).

## Risks
DataContext to the active Operation (per-screen vs top-level). Stuck taskbar state if None isn't set on end/reset. Title vs caption interplay.

## Out of scope
Per-part progress (T-069); taskbar thumbnail buttons.
