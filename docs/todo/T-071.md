## Concept
Make the "Cut markers" list display in ascending time order regardless of add order, staying correct through the T-041 pending→resolved snap and marker removal. No change to the split output.

## Design
- Implement D1 from G-026 — pick (a) sorted-insert into `Markers` OR (b) a live-sorted `ICollectionView` over `Markers`. Note which and why.
  - **(a) sorted insert:** replace the two `Markers.Add(marker)` calls (`AddSnappedMarker` ~:758, `AddPendingMarker` ~:702) with an insert at the sorted index (key: `Snapped` if resolved else `Requested`). In the `Snapped`-resolved handler (`ResolvePendingMarkerAsync` / the `:972` PropertyChanged path), re-position the marker (remove + sorted-insert) so it settles — guard against the existing staleness/removed-by-user checks.
  - **(b) live-sorted view:** expose `MarkersView` = a `CollectionViewSource` over `Markers` with `SortDescriptions { new(nameof(CutMarkerViewModel.Snapped), Ascending) }` and `IsLiveSortingRequested = true` (+ `LiveSortingProperties` includes `Snapped`/`Requested`); bind the list to `MarkersView`. Use `Requested` as a fallback in the sort if `Snapped` is default while pending.
- Keep dedupe on `Snapped` unchanged. Keep the timeline ticks + the "Parts to export" segments list as-is (already time-ordered).

## Acceptance criteria + Case-Coverage Matrix
- [ ] Add cuts at 5:00 then 2:00 → the markers list shows 2:00 above 5:00.
- [ ] Add a cut out of order while the keyframe scan is still running (pending, T-041) → once it snaps, it settles into the correct time position in the list.
- [ ] Remove a marker → remaining list stays correctly ordered.
- [ ] The produced split parts are unchanged (byte-identical) vs before — only the list order differs.
- [ ] Unit test: add markers out of order → assert the collection/view enumerates ascending by time; pending-then-resolved lands in order.
- [ ] Build 0-warning; full suite green.
- Matrix — Required-Success: out-of-order adds → sorted list. Boundary: pending re-order on resolve; duplicate snap (deduped); single marker; remove middle marker. Required-Fail: none.
