## Concept

The **WPF-free App view-model layer** for the Bulk Cut tab (D-004). A bulk trim *is a Split that keeps exactly one
middle segment* `[intro-end → outro-start | EOF]`, so this task adds **no ffmpeg path and no batch orchestration** — it
adds the two view-models that sit on top of the Core work already built in **T-094** (kept-index math + request factory)
and **T-095** (`BulkTrimEngine`: the sequential, failure-isolated batch runner that owns the loop, collision policy,
disk pre-flight, cancel, and the result ledger).

The critic's decomposition fix is honored literally: **`BulkCutViewModel.RunBatchAsync` DELEGATES to
`IBulkTrimEngine.RunAsync` — it does not re-implement the loop, failure isolation, collision resolution, disk pre-flight,
or cancel-sweep.** The VM owns only:

- **`BulkItemViewModel`** — one video row: Join-item shape + two `CutMarkerViewModel` handles (intro-end required,
  outro-start optional/from-end) + per-file background keyframes + computed `KeptDuration`/`IsValidCut`/`RowState` +
  its own per-row `OperationViewModel` + `OutputPath` + `BuildRequest()` (the per-row T-094 request builder).
- **`BulkCutViewModel`** — the tab VM: the `ObservableCollection` list (mirrors `JoinViewModel`), `AddFilesAsync`
  (dedup + probe + **throttled** background keyframe scan), apply-to-all (outro measured **from END**, each target
  re-snapped + re-validated, invalidated rows reported not dropped), the **aggregate** `OperationViewModel`
  (overall bar/taskbar/title), `CanRunBatch` gating, and `RunBatchAsync` which builds each enabled+valid row's batch
  input and **awaits `_bulkTrimEngine.RunAsync(...)`**, then fans the returned per-item + overall progress and the
  `BatchResult` ledger back onto the rows + the aggregate op.

Plus the critic's newly-surfaced gap: a **bounded keyframe-scan throttle** so N added files do not fire N concurrent
`ffprobe` scans (`GetKeyframesAsync` in-flight-dedup only collapses repeats of the *same* path, not distinct paths).

## Design

### 1. `BulkItemViewModel` (one row) — `src/App/ViewModels/BulkItemViewModel.cs`

Constructor: `BulkItemViewModel(string path, IMediaProbe probe, SemaphoreSlim scanGate, TimeSpan? defaultIntro = null)`.
`Path`/`FileName` (`Path.GetFileName`), dedup key = normalized `Path.GetFullPath`. WPF-free (`ObservableObject`).

1. **Shape + probe (set by the tab VM after add):** `Duration` (`TimeSpan?`, from `ProbeAsync`), `SizeBefore` (`long`, via
   `SafeFileSize`), `SizeAfter` (`long?`, filled from the ledger). `OutputPath` computed = `<dir>/<name>_trimmed<ext>` from
   `Path` (the collision-adjusted *actual* written path comes back on `BulkTrimItemResult.OutputPath`).
2. **Two handles.** `IntroEnd` (required) `= new CutMarkerViewModel(probe, () => Keyframes, defaultIntro ?? TimeSpan.Zero, snapPending: true)`.
   `OutroStart` (`CutMarkerViewModel?`, nullable) + `HasOutro => OutroStart is not null`. `AddOutro(TimeSpan requested)` /
   `ClearOutro()` create/drop the second handle (both `snapPending: true`). Both handles re-snap automatically when their
   `Requested` is set; the row calls `IntroEnd.ResolveSnap()` + `OutroStart?.ResolveSnap()` when the scan finishes.
3. **Background keyframes (throttled — see §3).** `Keyframes` (`IReadOnlyList<TimeSpan>`, default empty),
   `IsIndexingKeyframes`, `KeyframesReady => Duration is not null && !IsIndexingKeyframes`. `StartKeyframeScanAsync()`
   models `SplitViewModel.StartKeyframeIndex`: swap a **per-row `CancellationTokenSource`** (`_scanCts`), `IsIndexingKeyframes = true`,
   then a captured-context continuation with the stale-CTS guard commits `Keyframes`, flips the flag, resolves both handle
   snaps, and recomputes validity. The scan body is wrapped in the shared `scanGate` (§3).
4. **Computed state (recompute on any handle `Snapped`/`Requested` change + on `KeyframesReady`):**
   - `KeptDuration => KeyframesReady ? (OutroStartSnapped ?? Duration) − IntroEndSnapped : null` where
     `OutroStartSnapped = HasOutro ? OutroStart!.Snapped : (TimeSpan?)null`, `IntroEndSnapped = IntroEnd.Snapped`.
   - `MinKeptSpan` = `max(1s, 1 GOP)` from `probe.AverageGop(Keyframes)` (D-004 open-decision 4).
   - `IsValidCut => KeyframesReady && IntroEndSnapped < (OutroStartSnapped ?? Duration) − MinKeptSpan && in-range`.
   - `IsNoOpTrim => KeyframesReady && !HasOutro && IntroEndSnapped ≈ 0` **or** (outro present but snaps to ≥ EOF) — net
     full-file copy (D-004 matrix #3/#5); auto-excluded from the batch.
   - `RowState` (`enum RowState { Loading, Ready, Invalid, NoOpTrim, LoadFailed, Queued, Running, Done, Failed, Skipped, Cancelled }`)
     derived: `LoadFailed` when probe failed; `Loading` while `!KeyframesReady`; then `Invalid`/`NoOpTrim`/`Ready`. Batch
     phases (`Queued`→`Running`→`Done`/`Failed`/`Skipped`/`Cancelled`) are driven from the ledger/progress (§4).
   - `Warning` (`string?`): coarse-GOP ("cuts may move ~Xs"), "nothing trimmed from the tail" (outro→EOF), "very short keep
     (~Xs)" (`KeptDuration < MinKeptSpan` but > epsilon). Folded with `SplitResult.Warnings` surfaced from the ledger.
   - `IsEnabled` (`bool`, default true, row-in-batch checkbox) — auto-forced false when `Invalid`/`NoOpTrim`/`LoadFailed`.
5. **Per-row op.** `Operation` = its own `OperationViewModel` (row progress bar/state/cancel-less; the aggregate op owns the
   real cancel). Progress + terminal state are pushed in from §4.
6. **`BuildRequest()` → `SplitRequest`.** `var idx = KeptSegmentSelector.ResolveKeptIndex(Duration!.Value, Keyframes, probe.SnapToNearestKeyframe, probe.AverageGop(Keyframes), IntroEnd.Requested, HasOutro ? OutroStart!.Requested : null);`
   then `return KeptSegmentSelector.BuildKeptMiddleRequest(Path, IntroEnd.Requested, HasOutro ? OutroStart!.Requested : null, idx, overwrite);`
   Powers the `OutputPath`/`KeptDuration` preview + validity cross-check and is directly unit-testable (row → one `-c copy`
   `PerSegment` request). At run time the engine's `KeptMiddleRequestBuilder` rebuilds the authoritative request through the
   **same** T-094 path (identical kept-segment shape; the engine additionally applies the collision-resolved output name).
   `BuildBulkTrimItem() => new BulkTrimItem(Path, IntroEnd.Requested, HasOutro ? OutroStart!.Requested : null, OutputPath, Tag: this)`.

### 2. `BulkCutViewModel` (the tab VM) — `src/App/ViewModels/BulkCutViewModel.cs`

Constructor: `BulkCutViewModel(IMediaProbe probe, ISplitEngine splitEngine, IThumbnailService thumbnails, IAppSettings settings, IBulkTrimEngine? bulkTrimEngine = null)`.
Default-constructs `_bulkTrimEngine ??= new BulkTrimEngine(splitEngine, new KeptMiddleRequestBuilder(probe))` (sharing the
same `ISplitEngine`/`IMediaProbe` the other tabs use); tests inject a fake. Mirror `JoinViewModel` throughout.

1. **List.** `ObservableCollection<BulkItemViewModel> Items`; `Items.CollectionChanged → recompute counts + CanRunBatch`.
   `LastInputDir` memory via `settings.LastInputDir` (like `JoinViewModel:252`). `RemoveCommand` (cancels that row's
   `_scanCts`, drops the row). `ClearCommand` guarded `CanClear => Items.Count > 0 && !Operation.IsRunning` (cancels every
   row's scan, resets the aggregate op).
2. **`AddFilesAsync(IEnumerable<string>? paths)`.** Dedup by normalized `Path.GetFullPath` against existing `Items` (D-004
   matrix #11 — never a 2nd row per source). For each new path: construct `BulkItemViewModel(path, probe, _scanGate)`,
   `ProbeAsync` → `Duration`/`SizeBefore` (best-effort; probe-fail → `RowState = LoadFailed`, excluded), then
   `_ = item.StartKeyframeScanAsync()` (the **throttled** background scan, §3). Update `LastInputDir`. Never throws for a bad
   path.
3. **`ApplyToAllCommand` (source = the row the gesture came from).** Copy the source's **requested** cut points to every
   **other enabled** row; each target **re-snaps + re-validates against ITS OWN keyframes/duration**:
   - `var introReq = source.IntroEnd.Requested;` (absolute time-from-start — applied verbatim).
   - `var tail = source.HasOutro ? source.Duration!.Value − source.OutroStart!.Requested : (TimeSpan?)null;` (the **tail
     length**). For each target: `target.IntroEnd.Requested = introReq;` and if `tail is {} t` → set/create the target's outro
     at **`target.Duration!.Value − t`** (time-from-END, so uneven-length episodes align — D-004 open-decision 1); if `tail`
     is null → `target.ClearOutro()` (mirror the source's no-outro shape).
   - Setting `.Requested` re-snaps automatically; after the copy, recompute each target's `IsValidCut`/`RowState`. Collect
     targets the copied time **invalidated** (intro ≥ `target.Duration − MinKeptSpan`, or tail overshoots the file) → mark
     `Invalid` and return/surface `ApplyToAllReport { AppliedCount, InvalidatedRows }` (**reported, not silently dropped** —
     D-004 matrix #17). Guard: no-op if the source itself is not `Ready`/keyframes not ready.
4. **`RunBatchAsync` — DELEGATES to T-095 (see §4).** `CanRunBatch => Items.Any(i => i.IsEnabled && i.IsValidCut) && !Operation.IsRunning && Items.Where(i => i.IsEnabled).All(i => i.KeyframesReady)`.
   `RunLabel => $"Run bulk cut ({Items.Count(i => i.IsEnabled && i.IsValidCut)})"`. `BatchState`
   (`enum BulkBatchState { Idle, Preparing, Running, Completed, CompletedWithFailures, Cancelled, Blocked }`) mirrors
   `BatchOutcome` + Preparing/Running. `CollisionPolicy` (`AutoSuffix` default) + a per-run `Overwrite` toggle feed
   `BulkTrimOptions`. `Operation` = the **aggregate** `OperationViewModel` (overall bar + taskbar/title + the batch
   `CancelCommand`).

### 3. Bounded keyframe-scan throttle (the critic's gap)

**Chosen: a single shared `SemaphoreSlim(initialCount: 3, maxCount: 3)` owned by `BulkCutViewModel`, passed into every
`BulkItemViewModel`, wrapping the per-row `GetKeyframesAsync` call.** Each row's `StartKeyframeScanAsync` does:

```
await _scanGate.WaitAsync(_scanCts.Token).ConfigureAwait(true);
try     { kf = await _probe.GetKeyframesAsync(Path, _scanCts.Token).ConfigureAwait(true); }
finally { _scanGate.Release(); }
```

wrapped in the `SplitViewModel.StartKeyframeIndex` stale-CTS + captured-scheduler pattern (a superseded/removed row's
result is dropped; the per-row `_scanCts` cancels its queued-or-running scan on `RemoveCommand`/`ClearCommand`).

**Why the semaphore, not lazy-scan-on-first-touch:** `CanRunBatch` requires **all enabled rows `KeyframesReady`**, and
`ApplyToAllCommand` re-snaps **every** target against its own keyframes — both need keyframes front-loaded, not deferred to
a hover the user may never make; lazy-scan would leave rows un-snapped and the batch un-runnable. `MediaProbe.GetKeyframesAsync`
already in-flight-dedups the **same** path (T-093) but not **distinct** paths — the semaphore is exactly the missing
distinct-path bound. Max 3 concurrent scans saturates disk I/O without a thundering herd on a 20-episode drop. All BCL
(`SemaphoreSlim`/`CancellationTokenSource`/`Progress<T>`) → stays WPF-free. A row may sit queued (`IsIndexingKeyframes = true`)
before its scan starts — fine, `KeyframesReady` stays false and `CanRunBatch` already gates on it.

### 4. `RunBatchAsync` — delegation, progress fan-out, ledger fan-out

1. `BatchState = Preparing`. Build the runnable list **in input order** and its index→row map:
   `var rows = Items.Where(i => i.IsEnabled && i.IsValidCut).ToList(); var items = rows.Select(r => r.BuildBulkTrimItem()).ToList();`
   Mark those rows `Queued`. `Operation.SeedEstimatedDuration(TimeSpan.FromSeconds(rows.Sum(r => r.KeptDuration!.Value.TotalSeconds)))`.
2. Run the whole batch **through the aggregate op** so it gets Running/Completed/Cancelled/Failed + taskbar + ETA for free:

```
BatchResult? batch = null;
await Operation.RunWithResultAsync(
    work: async (overallProgress, ct) =>
    {
        BatchState = BulkBatchState.Running;
        var engineProgress = new Progress<BulkTrimProgress>(p => OnBatchProgress(p, rows, overallProgress));
        batch = await _bulkTrimEngine.RunAsync(items, new BulkTrimOptions(CollisionPolicy), engineProgress, ct)
                                     .ConfigureAwait(true);
        ApplyLedger(batch, rows);                 // set terminal RowState/Warning/OutputPath/SizeAfter per row
        if (batch.Outcome == BatchOutcome.Cancelled) ct.ThrowIfCancellationRequested();  // → aggregate op Cancelled
        return batch;
    },
    failureSelector: b => b!.Outcome == BatchOutcome.Blocked
        ? new UserFacingError(ErrorCategory.DiskFull, "Not enough space to trim these videos.", …)
        : null,                                   // Completed / CompletedWithFailures are NOT op-failures
    runningStatus: "Trimming…").ConfigureAwait(true);
BatchState = MapOutcome(batch, Operation.State); // Completed / CompletedWithFailures / Cancelled / Blocked
```

3. **Progress fan-out (`OnBatchProgress`):** `p.ItemIndex → rows[k]` (input order) → set that row's `Operation.Progress =
   p.ItemFraction`, `RowState = Running`. **Aggregate bar is VM-computed + weighted** (D-004 risk "monotonic overall"):
   `overall = Σ(wᵢ · fᵢ) / Σ wᵢ` with `wᵢ = rows[i].KeptDuration.TotalSeconds` (fallback `SizeBefore`), `fᵢ` = 1 for rows the
   ledger/phase already marked done, `p.ItemFraction` for the current row, else 0; clamp monotonic (never decrease), then
   `overallProgress.Report(overall)`. (The engine's own `p.OverallFraction` is row-count-weighted and kept only as a sanity
   fallback — the weighted rollup is smooth across heterogeneous durations.)
4. **Ledger fan-out (`ApplyLedger`):** iterate `batch.Items` (one per submitted item, input order), cast `.Item.Tag →
   BulkItemViewModel`, set `RowState` from `ItemOutcome` (`Done`/`Failed`/`Skipped`/`Cancelled`; `NotStarted → Ready`,
   re-runnable), `Warning` (fold `result.Warnings`), `OutputPath = result.OutputPath ?? OutputPath`, `SizeAfter`, and the
   row `Operation.Error` from `result.Error`. Surface `CompletedWithFailures` as `Operation.ResultSummary = "Trimmed {DoneCount},
   {FailedCount} failed"` + expose `FailedItems` for the `Retry failed (N)` relabel (T-097 renders it).
5. **Cancel** flows through the aggregate `Operation.CancelCommand` (cancels the token `RunWithResultAsync` created); the
   engine observes `ct`, sweeps the in-flight temp (its own `finally`), returns `BatchResult(Cancelled)`; the `work` lambda
   re-throws via `ct.ThrowIfCancellationRequested()` so the aggregate op lands in `Cancelled` **after** `ApplyLedger` set the
   per-row Cancelled/NotStarted states. **No loop/collision/pre-flight/cancel-sweep code lives in the VM** — all inherited
   from T-095.

**Optional seam note:** the App MAY instead inject an `IBulkTrimRequestBuilder` that delegates to the correlated row's
`BuildRequest(effectiveOutputPath, overwrite)` (via `Tag`), making `BulkItemViewModel.BuildRequest` the single request-building
body. Default is the shared `KeptMiddleRequestBuilder` (simpler, equally correct — both funnel through T-094).

## Acceptance criteria + Case-Coverage Matrix

- [ ] Aggregate `OperationViewModel` overall bar is monotonic non-decreasing, weighted by kept-duration, reaches 1.0; per-row
      `OperationViewModel` fractions forwarded; taskbar/title follow the aggregate op.

      `BatchState` maps `BatchOutcome` (+ Preparing/Running).
- [ ] Ledger fan-out: each `BulkTrimItemResult` routes by `Tag` to its row (terminal RowState/Warning/OutputPath/SizeAfter/Error);

  - `RunBatch_Delegates_CallsBulkEngineOnce_WithOneItemPerEnabledValidRow_NeverCallsSplitEngine`
  - `RunBatch_AggregateProgress_Weighted_Monotonic_ReachesOne`
  - `RunBatch_Ledger_RoutesOutcomesByTag_SetsRowStates` (Done/Failed/Skipped/Cancelled + Warning + OutputPath)
  - `RunBatch_Blocked_SetsAggregateFailed_DiskFull`; `RunBatch_Cancelled_SetsAggregateCancelled_RowsCancelledOrNotStarted`
  - `AddFiles_DedupsByFullPath`; `BoundedScan_MaxThreeConcurrentGetKeyframes` (gated `FakeProbe` records peak concurrency ≤ 3)

**Matrix —** **Success:** all-valid batch → every row `Done`, `BatchState = Completed`, weighted overall reaches 1.0, outputs
`<name>_trimmed<ext>`; apply-to-all across equal-length rows lands identical cuts. **Boundary:** apply-to-all across **uneven**
lengths (outro-from-end aligns; shorter target invalidated + reported); no-outro row (`KeptDuration = Duration − introEnd`);
`NoOpTrim` auto-excluded; row still indexing → `CanRunBatch` false; `CompletedWithFailures` (some Failed) → op Completed + Retry-failed(N);
6 files added → ≤3 concurrent scans; `AutoSuffix` collision surfaced via ledger `OutputPath`. **Required-Fail:** `RunBatchAsync`
must delegate — a test injecting a `ThrowingFakeSplitEngine` fails if the VM calls `SplitAsync` directly (proves no reimplementation);
`Blocked` pre-flight → aggregate op Failed (DiskFull), zero row-Done; cancel mid-batch → in-flight row `Cancelled`, done rows kept,
not-started `NotStarted→Ready`, aggregate op `Cancelled`.

## Risks

- **Delegation drift** — the temptation to grow a loop in the VM. Mitigation: `RunBatchAsync` only builds `BulkTrimItem`s and
  awaits `RunAsync`; the `ThrowingFakeSplitEngine` test fails on any direct `SplitAsync` call.
- **Two request-build paths (`BuildRequest` vs `KeptMiddleRequestBuilder`)** could theoretically disagree. Mitigation: both call
  the same T-094 `ResolveKeptIndex` + factory; they differ only in output-path handling (VM = base `_trimmed`, engine = collision-resolved),
  which is the intended division of labor. The optional VM-injected `IBulkTrimRequestBuilder` seam collapses them to one body if ever needed.
- **Progress/ledger correlation** by `ItemIndex`/`Tag` — brittle if the runnable list and submitted `items` diverge. Mitigation:
  build both from the same ordered `rows` list once; correlate by index into that list and by `Tag` reference identity.
- **Weighted-overall monotonicity** across heterogeneous durations — a naïve `Σwf/Σw` can dip when the current row's fraction
  resets. Mitigation: clamp to `max(previous, computed)`; treat ledger-completed rows as `f = 1`.
- **Optimistic snap timing** — apply-to-all / `IsValidCut` read `Snapped`, provisional until `ResolveSnap`. Mitigation:
  `CanRunBatch` gates on all-enabled `KeyframesReady`, so the batch never runs on unresolved snaps; apply-to-all guards the source's readiness.
- **Scan-gate starvation** if a row's scan hangs — mitigated by per-row CTS (Remove/Clear cancels) and `Release()` in `finally`;
  the gate bounds, never blocks, the UI thread (scans run on background continuations).
- **WPF-free discipline** isn't enforced by `CoreIsUiFreeTests` (App layer) — keep the VMs to BCL + Core types by review; a stray
  `using System.Windows` is the classic slip.

- **The kept-index math + single-segment request factory — T-094** (`KeptSegmentSelector`). The VM only calls them.
- **`BulkCutView` XAML, the per-row dual-handle scrub Canvas, hover-thumbnail rendering, `DropScrimBrush` token, the 3rd
  `TabItem`, `MainViewModel` 3-way tab routing, and `MainWindow.xaml(.cs)` wiring — all T-097.**

- Parallel/concurrent batch execution, multi-segment-per-video, >1 row per source, custom output folders, codec conversion,
  output-name templates (suffix fixed `_trimmed`), auto intro/outro detection, editing rows mid-run / auto-requeue of failures.
