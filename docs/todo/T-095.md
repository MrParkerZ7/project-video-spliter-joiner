## Concept

A bulk trim **is a Split that keeps exactly one middle segment** (`[intro-end → outro-start | EOF]`), so there is **no second ffmpeg path** — every row is one `ISplitEngine.SplitAsync` call, already `-c copy`, keyframe-snapped, temp-then-move, disk-pre-flighted, copy-invariant-asserted.

T-095 is the **thin, UI-free Core orchestrator** that runs *many* such single-kept-segment trims **sequentially** and **failure-isolated**: given a list of items `(input, introEnd, outroStart?, desiredOutputPath)` it resolves each output per a collision policy, disk-pre-flights the whole batch, then runs each item head-to-tail. One bad row is caught, mapped, and recorded — **the loop continues**. Cancel tears down the in-flight ffmpeg (the engine sweeps its own temp; a partial is never moved) and stops before the next row, keeping already-`Done` rows. It surfaces per-item + overall progress and returns a `BatchResult` ledger with one entry per item.

T-095 does **not** re-derive cut-point / kept-index math — that is T-094's "kept path". T-095 owns only: the batch loop, failure isolation, cancel semantics, collision policy, batch disk pre-flight, progress rollup, and the result ledger. All new types live in Core (`VideoSplitJoiner.Core.Bulk`) with zero WPF references.

## Design

New folder **`src/Core/Bulk/`**, namespace `VideoSplitJoiner.Core.Bulk`. All types WPF-free.

**1. Input + option types**

- `public sealed record BulkTrimItem(string InputPath, TimeSpan IntroEnd, TimeSpan? OutroStart, string DesiredOutputPath, object? Tag = null)` — `DesiredOutputPath` is the base `<dir>/<name>_trimmed<ext>` computed upstream; `Tag` lets the App VM correlate a result back to its row (opaque to Core).
- `public enum CollisionPolicy { AutoSuffix, Skip, Overwrite }` (default `AutoSuffix`).
- `public sealed record BulkTrimOptions(CollisionPolicy Collision = CollisionPolicy.AutoSuffix)`.

**2. Result / ledger types**

- `public enum ItemOutcome { Done, Failed, Skipped, Cancelled, NotStarted }`.
- `public enum BatchOutcome { Completed, CompletedWithFailures, Cancelled, Blocked }`.
- `public sealed record BulkTrimItemResult(BulkTrimItem Item, ItemOutcome Outcome, string? OutputPath, UserFacingError? Error, IReadOnlyList<string> Warnings)`.
- `public sealed record BatchResult(BatchOutcome Outcome, IReadOnlyList<BulkTrimItemResult> Items)` — **exactly one result per input item, in input order** (invariant). Convenience: `DoneCount`, `FailedCount`, `SkippedCount` computed props; `FailedItems` for the `Retry failed (N)` UI relabel.

**3. Progress type + the T-094 seam**

- `public readonly record struct BulkTrimProgress(int ItemIndex, int ItemCount, string CurrentFileName, double ItemFraction, double OverallFraction, BulkTrimPhase Phase)` with `enum BulkTrimPhase { Preflight, Running, Item }`.
- **T-094 seam** — request construction is delegated so the batch loop stays thin and probe-free at test time:
  `public interface IBulkTrimRequestBuilder { Task<SplitRequest> BuildAsync(BulkTrimItem item, string effectiveOutputPath, bool overwrite, CancellationToken ct); }`.
  Ship a default impl `KeptMiddleRequestBuilder(IMediaProbe probe)`: `CutPoints = OutroStart is null ? [IntroEnd] : [IntroEnd, OutroStart]`; `OutputDir = Path.GetDirectoryName(effectiveOutputPath)`; `NamingPattern = literal Path.GetFileName(effectiveOutputPath)` (no `{index}` token → `SplitEngine.ApplyNamingPattern` returns it verbatim); `Overwrite = overwrite`; `SelectedSegmentIndices = [ KeptSegmentSelector.ResolveKeptIndex(duration, keyframes, IntroEnd, OutroStart) ]` — **`KeptSegmentSelector` is T-094's pure helper** (cures the index-not-always-2 risk). The builder shares the passed `IMediaProbe` instance (cached/deduped scan). If T-094 already ships a builder, `KeptMiddleRequestBuilder` delegates to it; the interface is the stable adapter point.

**4. `IBulkTrimEngine` + `BulkTrimEngine`**

```
public interface IBulkTrimEngine {
    Task<BatchResult> RunAsync(
        IReadOnlyList<BulkTrimItem> items,
        BulkTrimOptions options,
        IProgress<BulkTrimProgress>? progress = null,
        CancellationToken ct = default);
}
public sealed class BulkTrimEngine : IBulkTrimEngine {
    public BulkTrimEngine(ISplitEngine splitEngine, IBulkTrimRequestBuilder requestBuilder) { … }
}
```

Loop algorithm:

1. **Guard** — null/empty `items` → return `BatchResult(Completed, [])` (no-op; the VM's `CanRunBatch` already gates zero rows). Null `options` → default.
2. **Collision pre-resolve** (per item, before any run) — compute `effectiveOutputPath`:
   - `Overwrite` → keep `DesiredOutputPath`, `overwrite = true`.
   - `Skip` → if `File.Exists(DesiredOutputPath)` mark the item `Skipped` (no engine call); else keep path, `overwrite = false`.
   - `AutoSuffix` (default) → if `DesiredOutputPath` free, use it; else append `_2`, `_3`, … to the `_trimmed` stem (`<name>_trimmed_2<ext>`) until a free path is found. `overwrite = false`.
   - **Source-safety guard (all policies):** assert `Path.GetFullPath(effectiveOutputPath) != Path.GetFullPath(InputPath)`; if they'd collide, force AutoSuffix regardless of policy — **the source is never a write target.**
3. **Batch disk pre-flight** — group the not-skipped items by output **drive root** (`Path.GetPathRoot(Path.GetFullPath(effectiveOutputPath))`); per root, `required = Σ FileInfo(InputPath).Length + 16 MB margin` (source size is a safe **upper bound** — trimming only removes bytes, mirroring `SplitEngine.EnsureEnoughFreeSpace`); if any ready `DriveInfo.AvailableFreeSpace < required` → **block the whole batch**: return `BatchResult(Blocked, items.Select(NotStarted with a DiskFull UserFacingError))`, **zero engine calls**. Best-effort: any measurement failure (unknown/UNC drive, exception) **skips** that root's check (never a false-positive block). Report `Phase.Preflight` once at start.
4. **Sequential run** — for each item in order (skip the ones marked `Skipped` in step 2):
   - `ct.ThrowIfCancellationRequested()` **before** starting the row; if already cancelled, mark this and all remaining `NotStarted` and break to step 5.
   - `var req = await requestBuilder.BuildAsync(item, effectiveOutputPath, overwrite, ct);`
   - Wrap an `IProgress<double>` that maps the row's local fraction → `OverallFraction = (completed + local) / runnableCount` and reports `BulkTrimProgress(index, count, fileName, local, overall, Phase.Item)`.
   - `await splitEngine.SplitAsync(req, wrappedProgress, ct);` (the engine asserts `-c copy`, does temp-then-move, sweeps its own temp on throw/cancel).
   - **On success** → `Done`, `OutputPath = effectiveOutputPath`, `Warnings = result.Warnings`; advance completed; report overall `= completed/runnableCount`.
   - **On `OperationCanceledException`/`ct` cancelled** → the current row is `Cancelled` (engine already swept its temp — assert no partial move); remaining not-started rows → `NotStarted`; break to step 5 with `BatchOutcome.Cancelled`.
   - **On `SplitException`** → map to `UserFacingError`: if `ex.FullStdErr` present, `FfmpegErrorMapper.Map(splitStderrTail, exitCode-if-known)`; else construct a `UserFacingError(ErrorCategory.Unknown/CorruptInput, ex.Message, …, LogFilePath: ex.LogFilePath)`. Record `Failed`. **`continue` the loop** (failure isolation — a mid-run ENOSPC on one large file is isolated per row; a smaller later file may still fit).
   - **On any other exception** → wrap into a `UserFacingError(ErrorCategory.Unknown, ex.Message)`, record `Failed`, **continue**. (Defensive: an `IOException`/`UnauthorizedAccessException` from a builder or collision race must not abort the batch.)
5. **Finalize** — assemble the ledger (one entry per original item, input order). `BatchOutcome`: `Cancelled` if a cancel occurred; else `CompletedWithFailures` if any `Failed`/`Skipped`; else `Completed`. Report a terminal `BulkTrimProgress` at `OverallFraction = 1.0`.

Cancellation & temp-safety are **inherited** from `SplitEngine` (its `finally` sweeps `.vsj-split-<guid>` and the move happens only after ffmpeg succeeds) — T-095 adds no temp management of its own; it only threads `ct` and stops the loop.

**5. Integration note (out of this task's code, in scope for wiring later — T-096+):** the App `BulkCutViewModel` constructs `new BulkTrimEngine(splitEngine, new KeptMiddleRequestBuilder(probe))` sharing the existing `ISplitEngine` + `IMediaProbe`. Not built here.

## Acceptance criteria + Case-Coverage Matrix

- [ ] `src/Core/Bulk/` created with `BulkTrimItem`, `CollisionPolicy`, `BulkTrimOptions`, `ItemOutcome`, `BatchOutcome`, `BulkTrimItemResult`, `BatchResult`, `BulkTrimProgress`+`BulkTrimPhase`, `IBulkTrimRequestBuilder`, `KeptMiddleRequestBuilder`, `IBulkTrimEngine`, `BulkTrimEngine` — all in `namespace VideoSplitJoiner.Core.Bulk`, zero WPF usings.
- [ ] Every row is executed via `ISplitEngine.SplitAsync` — **no new ffmpeg command path, no second engine** (the `-c copy` invariant is enforced inside the engine; T-095 never bypasses it).
- [ ] `BatchResult.Items.Count == items.Count`, in input order, one entry per item (ledger completeness invariant).
- [ ] Failure isolation: an exception on one row is caught, mapped to a `UserFacingError`, recorded `Failed`, and the loop **continues**.
- [ ] Cancel: the in-flight row ends `Cancelled` with **no partial output moved into place**; already-`Done` rows are kept; not-started rows are `NotStarted`; `BatchOutcome.Cancelled`.
- [ ] Collision policy honored: `AutoSuffix` → `_trimmed_2/_3`; `Skip` → `Skipped`, no engine call; `Overwrite` → `SplitRequest.Overwrite == true`, base name kept. **Source path is never a write target under any policy.**
- [ ] Batch disk pre-flight blocks the whole batch **before any run** on a knowable shortfall (`BatchOutcome.Blocked`, zero engine calls); unmeasurable drives skip the check; mid-run ENOSPC is isolated per row (`DiskFull` on that row, batch continues).
- [ ] Progress: `OverallFraction` is monotonic non-decreasing and reaches `1.0`; per-item fraction forwarded from the engine.
- [ ] **Build is 0-warning and the full suite is green** (`dotnet build -warnaserror` clean; `dotnet test` all pass).
- [ ] New tests added in **`tests/Core.Tests/BulkTrimEngineTests.cs`** using a new `FakeSplitEngine : ISplitEngine` (per-input behavior: succeed → create the resolved output file to prove the "Done" path + return `SplitResult`; throw a designated `SplitException`; honor `ct` → throw `OperationCanceledException`; records the `SplitRequest`s it received) and a trivial `FakeRequestBuilder : IBulkTrimRequestBuilder` (echoes a canned `SplitRequest` — **no probe needed**), covering:

  - `Batch_Cancel_DuringRow2_Row1Kept_Row2Cancelled_Row3NotStarted_NoPartialMoved`
  - `Collision_AutoSuffix_ExistingTrimmed_ResolvesTo_trimmed_2`
  - `Collision_Skip_ExistingOutput_ItemSkipped_NoEngineCall`
  - `Collision_Overwrite_PassesOverwriteTrue_KeepsBaseName`
  - `Collision_NeverTargetsSourcePath` (output == input guard)
  - `Preflight_Shortfall_BlocksBatch_ZeroEngineCalls_Outcome_Blocked`
  - `MidRun_DiskFull_IsolatedPerRow_BatchContinues`
  - `Ledger_HasOneEntryPerItem_InInputOrder`
  - `Progress_OverallFraction_MonotonicAndReachesOne`

**Matrix — Success:** all-valid batch → every row `Done`, `Completed`; per-item + overall progress reach 1.0; outputs land at `<name>_trimmed<ext>`. **Boundary:** empty/all-skipped batch (no-op); `AutoSuffix` increment (`_trimmed_2`); cancel exactly between rows vs mid-row; unmeasurable drive skips pre-flight; `SplitResult.Warnings` (coarse-GOP / no-keyframe) surfaced on a `Done` row; output-path == source-path forced to AutoSuffix. **Required-Fail:** row-2 throws `SplitException` → isolated, rows 1&3 `Done`, `CompletedWithFailures`; batch pre-flight shortfall → `Blocked`, zero engine calls; mid-run ENOSPC → that row `DiskFull`/`Failed`, batch continues; `Skip` policy on existing output → `Skipped` with no engine call; cancelled in-flight row → `Cancelled` with no partial file moved.

## Risks

- **Kept-index correctness** — mitigated by delegating to T-094's `KeptSegmentSelector`; the builder never hard-codes index 2. Verify with a builder test that a dropped-colliding-snap case still selects the true middle.
- **Double-probe cost** — the builder probes and the engine re-probes; both hit `MediaProbe`'s `(path,mtime,length)` cache + in-flight dedup, so the scan runs once. Share the **same** `IMediaProbe` instance (wired at App level, T-096).
- **Disk pre-flight precision** — using source size as the output upper bound may over-estimate (block a batch that would just fit). Acceptable: it never lets a genuine ENOSPC slip past pre-flight, and the mid-run per-row ENOSPC path is isolated. Best-effort skip on unmeasurable drives avoids false blocks on UNC/removable media.
- **Cancel vs "already done" race** — the engine's move-after-success guarantee means a row is either fully `Done` or fully absent; the runner must classify a row that finished the `await` before observing cancellation as `Done`, not `Cancelled` (order the `ct` check + result capture accordingly).
- **Non-ffmpeg exceptions** (builder `IOException`, collision race) must not abort the batch — the catch-all `Failed`+continue arm covers this; ensure it does not swallow `OperationCanceledException` (that arm must be checked first).
