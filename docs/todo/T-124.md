## Concept
Make a cut land on an arbitrary time instead of only on a keyframe, without re-encoding the whole file.
Given a requested start `R` that falls between keyframes `K0 <= R < K1`:

```
part A   R -> K1     re-encoded  (matched to the source's codec/params)  ~1 GOP, ~1-2s
part B   K1 -> end   stream copy (-c copy, untouched)
out      concat(A, B)
```

Everything after the first GOP is byte-identical to today's output. This is the only way to honour
"cut at 5s" while keeping the operation fast.

## Design
- New Core service (e.g. `SmartCutEngine`) behind an interface, sitting beside `SplitEngine` — NOT a
  modification of it. `SplitEngine` keeps its `-c copy` invariant and its SPEC-001 guarantees intact;
  `SatisfiesCopyInvariant` must stay true for the copy leg.
- **Match the source parameters** when encoding part A (codec, profile/level, pixel format, resolution,
  frame rate, and crucially the audio codec/sample rate) — read them from the existing `MediaProbe`
  output so the concat demuxer will accept A and B as compatible. A mismatch here is the main failure
  mode and must be detected, not discovered at concat time.
- Reuse the existing concat machinery (`JoinArgsBuilder.ConcatCopy`) for the final join rather than a
  second implementation.
- Temp-then-move + cancel-safety exactly as `SplitEngine` does — a cancelled smart cut leaves nothing
  behind, and (with G-041's `ReplaceOriginal`) never touches the original.
- **Honest fallback:** if the source's parameters cannot be matched well enough to concat safely, do NOT
  silently produce a corrupt file — fall back to the lossless keyframe cut and report clearly that exact
  cutting was unavailable for that file.

## Acceptance criteria + Case-Coverage Matrix
- [ ] A requested cut at 5s on a 4s-GOP source yields an output whose content starts at 5s (±1 frame).
- [ ] Requesting 6s yields a different output than 5s (the reported symptom is gone at the engine level).
- [ ] Only the head fragment is re-encoded: the remainder is byte-identical to the stream-copy result.
- [ ] A request that already sits ON a keyframe takes the pure-copy path (zero re-encode).
- [ ] Cancel mid-run leaves no partial output; failure leaves the source untouched.
- [ ] Parameter-mismatch → clean fallback to the keyframe cut with a stated reason, never a corrupt concat.
- Matrix — Required-Success: mid-GOP request cuts exactly. Required-Fail: unmatched params fall back, not corrupt.
  Boundary: request on a keyframe, request before the first keyframe, request inside the LAST GOP, 1-frame
  fragment, audio-only / no-audio sources. **Perf (bounded heavy-op): exactly ONE re-encode pass + one copy
  pass + one concat — assert the recording runner sees 3 invocations, never one-per-GOP.**
