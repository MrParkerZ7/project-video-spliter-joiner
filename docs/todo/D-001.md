## Concept
Add a **vertical (portrait) layout mode** to the app, switchable via a button, so the UI suits a
vertical monitor instead of only the current horizontal/landscape two-column design.

## Decisions (clarify round 1 — resolved)
- **D1 · Trigger:** manual **toggle button in the title bar** (caption row). No auto-detect.
- **D2 · Vertical arrangement:** **video + timeline top (full width), tool panel stacked below** (scrollable).
- **D3 · Scope:** **both Split and Join** — one toggle flips both.
- **D4 · Persistence:** **remembered across launches** in `settings.json` (`AppSettings`).
- **D5 · Toggle icon:** shows the mode it will switch **to** (+ matching tooltip). *(sealed)*
- **D6 · Split-ratio memory:** remembered **per-axis** (horizontal + vertical keep independent ratios). *(sealed)*

Full model, layout diagram, component seams, and edge cases: **[docs/design/D-001-vertical-monitor-mode.md](../design/D-001-vertical-monitor-mode.md)**.

## Current state (verified)
- `SplitView.xaml` / `JoinView.xaml` use a 3-**column** Grid: `video (* , MinWidth 320)` | `GridSplitter (6)` |
  `tool panel (360, MinWidth 300, MaxWidth 520)` — i.e. video/timeline LEFT, tools RIGHT (G-019/T-059).
- Optimized for a **landscape** monitor; on a portrait monitor the video is cramped and the tall space is wasted.
- A caption row + app header exist in `MainWindow.xaml` (app name + "lossless · no re-encode" tagline + format badge) —
  candidate homes for the mode toggle.

## Design direction (to be confirmed in clarify)
Vertical mode most naturally = flip the column Grid to a **row** Grid: video + timeline on TOP (full width,
gets the wide portrait width), the tool panel STACKED below (scrollable). A toggle button flips
`Horizontal ⇄ Vertical`. Details (trigger, arrangement, scope, persistence, toggle location) resolved below.

## Out of scope (initial)
Re-flowing individual controls beyond the layout axis; a fully responsive breakpoint system; per-screen
different modes. This is one horizontal⇄vertical toggle.
