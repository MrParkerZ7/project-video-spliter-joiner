## Concept
Exact cut and Replace originals are mutually exclusive today because the exact path cannot overwrite a
source safely. Make it able to, and lift the refusal.

## Why this exists
Found 2026-08-30 while auditing docs against code, in the release that had just shipped. Under
`OutputMode.ReplaceOriginal` the resolved destination IS the input (SPEC-002 I40). `SmartCutEngine`
finishes with:

```csharp
private static void MoveIntoPlace(string tempFile, string destination)
{
    var dest = Path.GetFullPath(destination);
    if (File.Exists(dest)) File.Delete(dest);   // <- the user's original
    File.Move(tempFile, dest);
}
```

so the combination hard-deleted the original: no `.vsj-original` backup, no `IOriginalDisposer` (i.e. no
Recycle Bin), no restore-on-failure — and if `File.Move` then failed, the file was gone entirely. Nothing
in the ViewModel or Core coupled the two options, so both checkboxes were freely combinable.

**Stopgap already shipped** (`BulkTrimEngine`, SPEC-002 I54/I55): Exact is refused under
`ReplaceOriginal`, the row falls back to the lossless cut and says so. That is safe but it denies a
combination users will reasonably want.

## Design
1. Extract `SplitEngine.ReplaceOriginalInPlace` (currently `private`) into a shared Core helper beside
   `IOriginalDisposer` in `src/Core/Io/` — File.Replace with backup, rename-aside fallback for volumes
   that lack it, restore-on-failure, disposer decides the backup's fate. `SplitEngine` delegates to it
   so there is exactly one implementation.
2. Give `BulkTrimEngine` (or `SmartCutEngine`) access to it, and on the Exact + ReplaceOriginal path:
   smart-cut to a temp file beside the source, verify, then hand it to the shared replacer.
3. Remove the I54 refusal and the I55 warning; update SPEC-002, the USER_GUIDE passage that currently
   says the two do not combine, and ADR-0018.

## Acceptance criteria
- [ ] Exact + Replace originals produces a frame-exact result AND sends the original to the Recycle Bin.
- [ ] A failure at any point leaves the original byte-identical — asserted by a test that forces the
      move to fail after the temp is produced.
- [ ] One implementation of the safe replace, not two.
- [ ] The stopgap refusal and its row warning are gone from code, spec and guide.

## Out of scope
Changing what the lossless replace path already guarantees. Real-media validation of Exact cut (separate).
