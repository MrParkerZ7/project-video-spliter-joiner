## Found

While closing [[T-154]]'s Split/Join half, a review pointed out that every screen has **two** doors for
getting files in — drag-and-drop and the file picker — and T-154 only ever fixed one of them. So each
screen now answers the same question two different ways.

## The two halves

**1. The picker's filter is stale.** All three pickers still carry the pre-T-154 list:

```csharp
Filter = "Video files|*.mp4;*.mkv;*.mov;*.avi;*.webm;*.m4v;*.ts|All files|*.*"
```
`SplitView.xaml.cs:52` · `JoinView.xaml.cs:146` · `BulkCutView.xaml.cs:179`

`VideoFileFilter` accepts **26** extensions. So an `.m2ts` — the exact format whose absence produced the
original report — is **invisible** under "Video files", even though *dropping* one now works. The user who
gives up on dragging and reaches for the button gets the old bug back.

**2. Under "All files" the picker applies no filter at all and says nothing.** Split hands
`dialog.FileName` straight to `LoadCommand`; Join and Bulk hand `dialog.FileNames` straight to
`AddFilesCommand`. Neither routes through the counting entry point T-154 added, so picking a `.txt`
adds it as a row (Join/Bulk) or attempts to load it (Split) with **no refusal message** — the same
silence, through the other door.

## Design

1. Widen the three `Filter` strings to the live allowlist. Generate it from
   `VideoFileFilter.VideoExtensions` rather than re-typing it, so the two can never drift again — the
   hand-maintained copy is exactly how this got stale.
2. Route the picker result through the same `AddDroppedFilesAsync` entry point the drop path uses, so both
   doors count refusals identically and there is one place for the rule to live.

## Acceptance criteria
- [ ] The picker's "Video files" filter offers every extension the app accepts, derived from
      `VideoFileFilter` rather than duplicated.
- [ ] A file chosen under "All files" that the app cannot use is **refused with a reason**, exactly as a
      dropped one is.
- [ ] A test that fails today: assert the picker filter string covers every entry in
      `VideoFileFilter.VideoExtensions`.
- [ ] Mutation: removing an extension from the allowlist without updating the picker fails that test.

## Out of scope
Replacing the extension allowlist with probe-based acceptance ([[T-154]] § Design 4) — still open on its
own merits, and it would supersede the filter string entirely rather than fix it.
