## Concept

The packet scan asks for JSON of every packet and reads it into one string before parsing (`MediaProbe.cs:253-283`).
On a 1-hour 60 fps file that allocated about 183 MB. Two changes were measured:

- `-nofind_stream_info`: an identical list, 0.554 s against 0.793 s on 4K.
- CSV output: no time gain (0.708 s against 0.736 s), but much less memory if it is streamed. That needs a
  line-callback overload on `IFfprobeRunner`.

**Built after T-194.** It changes the packet-scan args and parsing (`-nofind_stream_info`, CSV streamed through
a new `IFfprobeRunner` overload), and T-194's anchor windows reuse *"the existing packet-scan args plus
`-read_intervals` and `-nofind_stream_info`"*. Its MKV/TS trigger can fire during the drain while T-194 is still
being built.

## Why later

After T-194 the packet scan is the fallback for MP4/MOV, and the main path only for MKV/TS.

## Trigger

T-199 is not built and MKV/TS scans matter, or memory on very long files becomes a problem.
