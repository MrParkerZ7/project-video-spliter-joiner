## Why / vision

A **fast, no-nonsense Windows tool** that does exactly two things well — split a video and join videos — **without ever re-encoding**. Every existing "video editor" re-renders (slow, quality loss, huge). This app treats video as a container to be cut and glued at the stream level, so operations are **near-instant and lossless**. The headline convenience feature: **auto-detect split points** by finding black/white frames and hard scene cuts, so the user doesn't scrub the timeline hunting for boundaries.

Target user: someone who records long captures (screen recordings, camera dumps, streams) and wants to chop them at natural boundaries or stitch clips — quickly, at original quality.

## Gap from current state

The target is an **empty git repo** (`.git/` only). Everything is gap: no app skeleton, no ffmpeg integration, no split/join engines, no detection, no UI, no packaging. Greenfield build.

## Decisions (locked at plan time — user-confirmed)

- **D1 · Tech stack = .NET / C# (WPF).** Native Windows, fast startup, single self-contained `.exe`, first-class `System.Diagnostics.Process` interop for driving bundled `ffmpeg.exe`/`ffprobe.exe`.
- **D2 · Cut behavior = keyframe-snap, zero re-encode (`-c copy`).** Cuts are lossless and instant; the cut point **snaps to the nearest keyframe** and may differ from the exact requested moment by up to the GOP interval. This is the deliberate trade of "no re-render." The UI must make the snap visible (show the actual snapped time). Frame-exact "smart-cut" was explicitly rejected.
- **D3 · Auto-detect scope = black + white + hard scene cuts.** `blackdetect` + a white-luma threshold (via `signalstats`/`blackframe` inversion) + `scdet` scene score. Detection is **decode-only** (reads frames, never re-encodes) — consistent with D2. Output is a **ranked** candidate list (may over-detect on busy footage — ranking + user review is the mitigation).

## Risks

- **Keyframe granularity surprises users** — if a source has sparse keyframes, "snap" can move a cut by many seconds. Mitigation: show the snapped time + keyframe density up front (T-003/T-007).
- **Join compatibility** — concat `-c copy` needs matching codec/params; mismatches fail cryptically. Mitigation: pre-flight compat check + friendly refusal (T-005).
- **ffmpeg bundling/licensing + size** — must bundle a build and honor its license in distribution (T-010).
- **scdet over-detection** on busy footage — ranking + user-accept gate (T-006/T-007).

## Out of scope (v1.0)

Any re-encode/transcode, format conversion, trimming to frame-exact points, filters/effects, audio-only editing, timeline multi-track editing, cross-platform (Windows-only), cloud/upload.
