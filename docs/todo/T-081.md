## Concept
Implement D-001: a title-bar toggle flips both Split and Join between the current horizontal two-column layout
and a vertical stacked layout (video+timeline top, tools below), persisted across launches.

## Design (from docs/design/D-001-vertical-monitor-mode.md — decisions D1–D6)
- **`AppSettings.LayoutMode`** (`Horizontal`|`Vertical`, default Horizontal) persisted to settings.json like the
  window size / last folders (robust load/save, never throws). Restored on startup.
- **`MainViewModel`**: `bool IsVertical` + `ToggleLayoutCommand`, backed by `AppSettings.LayoutMode` (writes through
  on toggle). Both screens observe it.
- **Caption toggle button** (`MainWindow.xaml` caption row): a vector `Path` icon matching the G-029 style (1px
  stroke, `TextPrimaryBrush`, gold on hover, ~46×34). Icon shows the mode it will switch **to** (D5: tall-rect while
  horizontal, wide-rect while vertical) + matching tooltip. Bound to `ToggleLayoutCommand`.
- **Axis-aware container** — `SplitView.xaml` + `JoinView.xaml` currently use a 3-**column** Grid (video `*` /
  GridSplitter 6 / tools 360). In vertical mode, lay the same three regions on 3 **rows** (video+timeline top /
  horizontal GridSplitter / tools bottom, scrollable). **Keep ONE instance of each region control** — drive the
  Grid's RowDefinitions/ColumnDefinitions + each child's Grid.Row/Column + the GridSplitter orientation from
  `IsVertical` (DataTriggers, or a small custom oriented-3-pane panel/attached behavior). Don't duplicate the region
  markup. Vertical default split ≈ 62% video / 38% tools; tools keep their ScrollViewer + a MinHeight so Run is reachable.
- **Per-axis splitter ratio (D6)**: remember the horizontal and vertical split positions independently (persist or
  in-memory per session — persist preferred), so flipping doesn't distort the other axis.
- Every existing command/binding/content intact — this is a layout-axis change, not a rewire.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Title-bar toggle button flips horizontal ⇄ vertical instantly on BOTH Split and Join; icon + tooltip reflect the target mode.
- [ ] Vertical: video+timeline top (full width), tools stacked below (scrollable), splitter is a horizontal divider.
- [ ] LayoutMode persists — reopen the app in the last-used mode.
- [ ] Per-axis split ratio kept independent across flips.
- [ ] All existing controls/commands work in both modes (load, markers, parts, run, player, join flow); hover
      thumbnail (G-030) + scrub (G-028) still work (timeline strip identical).
- [ ] Build 0-warning; suite green (baseline 532) + tests: settings round-trip of LayoutMode, MainViewModel toggle
      flips IsVertical + writes settings, default Horizontal when unset.
- Matrix — Success: toggle flips both screens; persists. Boundary: first launch (default Horizontal); very short
  window in vertical (tools scroll, Run reachable); toggle mid-operation (pure view change). (Exact look = app-run/user-verified.)

## Risks
The WPF axis-flip (one control instance, RowDefs↔ColDefs + child placement + splitter orientation switched by
IsVertical) is the tricky part — pick the cleanest mechanism (DataTriggers on a shared IsVertical, or a small
oriented panel). Don't duplicate region markup or break bindings. Don't regress the resizable-pane (G-006) inner
video/timeline splitter.

## Out of scope
Keyboard shortcut + auto-detect portrait (D-001 deferred); a Join per-screen different mode. Docs (T-082).
