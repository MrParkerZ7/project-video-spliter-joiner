## Concept
Hovering many buttons shows an **empty-looking floating tooltip** — the text is there but invisible because the tooltip
renders **light text on a light background**. Fix it **app-wide** with one themed global `ToolTip` style so every tooltip
reads clearly on the dark+gold theme.

## Grounding (2026-08-22 — root cause found)
- **No `ToolTip` style exists anywhere** — `grep ToolTip src/App/Themes/*.xaml` for a Style/Template returns nothing. So
  every tooltip uses WPF's **default ToolTip template** (pale `SystemColors.InfoBrush`-ish background).
- **63 `ToolTip=` usages** across `src/App/Views/*.xaml` (Split, Join, Bulk Cut, timeline, caption buttons, …) — all rely
  on the default. The dark theme's inherited **light** foreground (`TextPrimaryBrush #EEF0F3`) bleeds into that pale
  default background → **light-on-light → empty**.
- The app **already uses implicit global styles** — `Controls.xaml:41` has an un-keyed `<Style TargetType="Button">`. So an
  implicit (un-keyed) `<Style TargetType="ToolTip">` in the same dictionary is the established pattern and covers **all 63**
  tooltips + any future ones automatically ("fix all").
- Tokens available (`Tokens.xaml`): `Surface2Brush`/`Surface3Brush` (raised dark surfaces), `TextPrimaryBrush` (#EEF0F3
  near-white, readable), `BorderStrongBrush`/`BorderBrush`, `RadiusSm`/`RadiusMd`, `MonoFontFamily`/`FontSizeSmall`.

## Design
Add ONE implicit `<Style TargetType="ToolTip">` to `src/App/Themes/Controls.xaml` (beside the existing implicit `Button`
style), fully self-contained so it can't inherit a clashing foreground/background:
1. **Explicit both colors** — `Background` = `Surface3Brush` (a clearly-raised dark surface, distinct from the panel behind
   it), `Foreground` = `TextPrimaryBrush` (near-white, high contrast). Setting BOTH explicitly is the actual fix — never
   rely on inheritance for either.
2. **Full `Template`** — a `Border` (Background/BorderBrush = `BorderStrongBrush`, `BorderThickness=1`,
   `CornerRadius` from `RadiusSm`, `Padding=10,6`) wrapping a `ContentPresenter`, so the chrome is themed (the default
   template won't reliably honor `Background`). Add a soft `DropShadowEffect` (low opacity, small blur, depth 1–2) OR keep
   `HasDropShadow` off with the border alone — tasteful, matches the app's surface cards.
3. **Type/size** — `FontSize` = `FontSizeSmall` (tooltips are secondary), default sans font; `MaxWidth` ~360 with
   `TextWrapping` so long tooltips (e.g. error hints) wrap instead of a single ultra-wide line. `TextOptions` crisp.
4. **Placement/behavior unchanged** — do not alter `ToolTipService` timings globally unless trivial; just restyle. Keep it
   a pure visual/theme change — no XAML `ToolTip=` content edited, no VM change.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Every tooltip (hover any button in Split / Join / Bulk Cut / the caption min-max-close / timeline handles) shows
      **readable light text on a dark surface** with a visible border — no more empty/washed-out floating box.
- [ ] One implicit `<Style TargetType="ToolTip">` in `Controls.xaml` covers all 63 usages (+ future ones) — no per-tooltip edits.
- [ ] Both `Foreground` and `Background` set explicitly from tokens (no inherited color); long tooltips wrap (MaxWidth).
- [ ] Uses design tokens only (Surface3/TextPrimary/BorderStrong/Radius) — no hardcoded hex.
- [ ] Build 0-warning; full suite green (baseline **671**; theme-only, no test needed — but don't break existing tests).
- Matrix — Success: all tooltips readable on dark. Boundary: a very long tooltip (wraps, MaxWidth); a bound tooltip
  (`{Binding IntroEnd.Display}`) styles the same; tooltip over a light gold button still readable (dark surface, not transparent).
  Required-Fail: none. (Exact look = app-run/user-verified — tunable.)

## Dependencies
None. Touches only `src/App/Themes/Controls.xaml` (+ `Tokens.xaml` only if a tooltip-specific token is genuinely needed —
prefer reusing existing surface/text tokens).

## Risks
Low — additive implicit style. Ensure the `Template` `ContentPresenter` inherits the explicit `Foreground` (set it on the
Border/ContentPresenter or via `TextElement.Foreground`), so string tooltips actually pick up the light color. Don't over-
darken to where a tooltip over a dark panel disappears — `Surface3Brush` + a border keeps it distinct. Keep it un-keyed
(implicit) so it applies globally; a keyed style would require touching all 63 sites.

## Out of scope
Redesigning tooltip content/wording; per-control custom tooltips; changing hover timing; any non-tooltip styling.
