## Why / vision
Today cut points are entered as numbers / from a marker list — you can't SEE the video while choosing where to cut. This makes the app feel like a batch tool, not an editor. Adding an in-app **preview player** with a scrubbable timeline, where you **watch and pick cut points from the playhead**, turns "type a timestamp" into "scrub to the moment and click cut." It closes the loop with the existing keyframe-snap: scrub roughly → click → snaps to the nearest keyframe (so player seek precision is a non-issue).

## Gap from current state
The Split screen (T-007) has a marker LIST + numeric position input + auto-detect candidates, but **no video display and no way to pick a cut visually**. Missing: a media player control, transport + scrub, capture-playhead-as-cut, seek-to-marker, and a timeline overlay showing markers/candidates for visual selection.

## Decisions (locked at plan time)
- **D1 · Player = WPF `MediaElement`** (auto-selected under `--auto-approve`). Native, no new dependency, binds a seek slider to `Position`, plays the common mp4/H.264/AAC case. Seek precision is irrelevant because cut points keyframe-snap. **Parked decision (D1-alt):** if MediaElement's Media-Foundation codec coverage proves too narrow (some MKV/HEVC preview-fail though they still cut), upgrade to **FFME** (`Unosquare.FFME`) which decodes via ffmpeg — requires switching the bundled ffmpeg *essentials* build to the *shared* (dll) build + a packaging change. Revisit only if a real file fails to preview.
- **D2 · Player is abstracted behind `IMediaPlayer`** (Position/Duration/IsPlaying/Play/Pause/Stop/Seek + events) so the ViewModels are unit-testable with a fake; `MediaElementPlayer` is the concrete WPF impl. Live playback is only verifiable on a real desktop (via `app-run`) — headless workers test the VM logic against the fake.
- **D3 · Reuse, don't duplicate:** capture-playhead adds a cut through the EXISTING `SplitViewModel` marker/snap path (T-003 `SnapToNearestKeyframe`). No second snap implementation.

## Risks
- MediaElement codec coverage (D1) — mitigated by the parked FFME upgrade + a clear "preview unavailable, cut still works" fallback message.
- MediaElement can't be verified headless — mitigated by the `IMediaPlayer` fake for tests + a real `app-run` smoke.
- Timeline overlay UX complexity — mitigated by an MVP (ticks on the existing slider) before any drag polish.

## Out of scope (this goal)
Frame-accurate stepping, thumbnail filmstrip, audio waveform, in-player trimming handles beyond cut markers, re-encode preview — all later.
