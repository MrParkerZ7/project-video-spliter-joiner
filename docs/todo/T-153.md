## What is wrong

**1. `docs/specs/_index.md` is stale in both directions.** Last touched at `9ebf00f` (2026-08-30). Since
then 58 invariant definitions were added and 8 removed: the real count is **680** documented invariants
against the table's stated 633, and per-spec rows are badly off (SPEC-011 says 102, has 121; SPEC-007 says
72, has 94; SPEC-013 says 48, has 52). The "Coverage: 98.5% / 622 covered" figure is self-described as
derived rather than measured. Its one honest tripwire — *"Two of the four SPEC-008 additions have no
test"* — is now **false in both directions**: I41–I44 are all covered.

**2. Two docs still deny a test that exists.** `docs/ARCHITECTURE.md:230` states Exact cut is *"Verified
against fakes only — never against real media"* and *"There is no real-media integration test for this
path"*; `docs/ROADMAP.md:18` repeats it. Both became false at commit `4649328`, which added
`tests/Core.Tests/SmartCutEngineIntegrationTests.cs` — five real-ffmpeg tests including
`ExactCut_ReEncodesOnlyTheHead_TheRestStaysCopied`, precisely the claim ARCHITECTURE says is undemonstrated.

## The concrete failure it allows
The index's untested-invariant list is the project's tripwire for "we documented behaviour nobody
enforces". Wrong in both directions, it points at covered invariants and stays silent on uncovered ones —
so the next person to trust it audits the wrong thing. And a caveat that says a risky path is unverified,
when it is verified, invites redundant work or an unnecessary release hold.

## Design
1. Recount the invariants mechanically and regenerate `_index.md`; note in the file whether the coverage
   figure is measured or derived.
2. Delete the two stale Exact-cut caveats, citing `SmartCutEngineIntegrationTests`.
3. If the count can drift silently, `command-analytics`-style freshness is the durable cure — a check that
   compares the index's totals against the spec files. Cheap; do it while the numbers are fresh.

## Acceptance criteria
- [ ] `_index.md` totals match a mechanical count of the spec files.
- [ ] The untested-invariant list is re-derived, not carried forward.
- [ ] ARCHITECTURE.md and ROADMAP.md no longer deny a test that exists.

## Out of scope
Writing tests for whatever the re-derived list turns up — that is its own ticket once the list is honest.
