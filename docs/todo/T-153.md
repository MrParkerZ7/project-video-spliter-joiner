## What is wrong

**1. `docs/specs/_index.md` is stale in both directions.** Last touched at `9ebf00f` (2026-08-30). Since
then 58 invariant definitions were added and 8 removed: the real count is **680** documented invariants
against the table's stated 633, and per-spec rows are badly off (SPEC-011 says 102, has 121; SPEC-007 says
72, has 94; SPEC-013 says 48, has 52). The "Coverage: 98.5% / 622 covered" figure is self-described as
derived rather than measured. Its one honest tripwire — *"Two of the four SPEC-008 additions have no
test"* — is now **false in both directions**: I41–I44 are all covered.

**2. Two docs still deny a test that exists.** `docs/ARCHITECTURE.md:230` states Exact cut is *"Verified
against fakes only — never against real media"* and *"There is no real-media integration test for this
path"*; `docs/ROADMAP.md:18` repeats it. Both became false at commit `4649328`, which added
`tests/Core.Tests/SmartCutEngineIntegrationTests.cs` — five real-ffmpeg tests including
`ExactCut_ReEncodesOnlyTheHead_TheRestStaysCopied`, precisely the claim ARCHITECTURE says is undemonstrated.

## The concrete failure it allows
The index's untested-invariant list is the project's tripwire for "we documented behaviour nobody
enforces". Wrong in both directions, it points at covered invariants and stays silent on uncovered ones —
so the next person to trust it audits the wrong thing. And a caveat that says a risky path is unverified,
when it is verified, invites redundant work or an unnecessary release hold.

## Design
1. Recount the invariants mechanically and regenerate `_index.md`; note in the file whether the coverage
   figure is measured or derived.
2. Delete the two stale Exact-cut caveats, citing `SmartCutEngineIntegrationTests`.
3. If the count can drift silently, `command-analytics`-style freshness is the durable cure — a check that
   compares the index's totals against the spec files. Cheap; do it while the numbers are fresh.

## Outcome — 2026-09-02

### The counts were wrong in both directions
Recounted mechanically: **680** documented invariants against the table's 633. Per-spec drift was not
uniform — SPEC-002 +7, SPEC-007 +22, SPEC-011 +19, SPEC-013 +4, and SPEC-014 **−5**. A number that is too
low in one row and too high in another cannot be repaired by adding a delta; it needed recounting.

### Coverage was deliberately NOT re-derived
The obvious move — carry the old `Covered` figures forward and adjust — would state a coverage number for
invariants that did not exist when coverage was measured. Those five specs' `Covered`/`Gaps` cells now
read `?`, with the last honest measurement (98.5%, 606/615, 2026-08-29) preserved and dated. A real figure
needs another per-invariant audit, which is its own ticket. **A guessed coverage percentage is worse than
an absent one**, because it reads as measured.

### The tripwire was wrong in the reassuring direction
The index carried a standing warning that two SPEC-008 additions (I42, reporting *while a run is in
flight*; I44, "starts no run, touches no run state") had no test. Both are covered —
`ReportFailure_WhileRunning_SetsErrorOnly_AndDoesNotDerailTheRun`,
`…_SurvivesTheRunsEnd_UntilTheNextRunClearsIt`, `…_StartsNoRunAndEndsNone_MarshallingNothing`. So the file
was simultaneously warning about a closed gap and silent about 47 invariants added since. For a tripwire,
being wrong in the *reassuring* direction is the worse failure.

### Two docs denied a test that exists
`ARCHITECTURE.md` said Exact cut was *"Verified against fakes only — never against real media"* and that a
re-encoded head concatenating onto a copied tail is *"not demonstrated by the suite"*; `ROADMAP.md`
repeated it. `SmartCutEngineIntegrationTests` has demonstrated exactly that since `4649328`. Both now say
what is true and name the suite.

### The durable cure
`SpecIndexFreshnessTests` recounts every spec and fails when the table disagrees — plus checks that every
indexed spec exists and every spec on disk is indexed. Mutation-checked: nudging one count 94→95 fails it.
The 47-invariant drift accumulated over three days precisely because nothing looked.

While writing it the guard was briefly vacuous — the row regex lacked `RegexOptions.Multiline`, so `^`
only matched at the start of the file and **zero rows parsed**. It failed loudly rather than passing on an
empty set, because it asserts `rows.Count > 0` first. Worth keeping that assertion in any doc-parsing test.

Suite 1315 → **1319 green**.
