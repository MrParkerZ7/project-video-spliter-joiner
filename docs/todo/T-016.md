## Concept
Drag video files from Explorer onto the app: the Split screen loads the dropped file, the Join screen adds all dropped files (in order). Reuses the existing load/add commands; only the drop plumbing + a shared file filter are new.

## Design
- **`VideoFileFilter`** (pure static, App) — `IReadOnlyList<string> AcceptVideoFiles(IEnumerable<string> paths)`: keep paths whose extension is a known video type (`.mp4 .mkv .mov .avi .m4v .webm .ts .mpg .mpeg .wmv .flv`), case-insensitive; drop the rest; dedupe; preserve order. Unit-tested.
- **SplitView code-behind** — `AllowDrop=true`; `DragOver` → if the drag payload has `FileDrop` with ≥1 video → `e.Effects=Copy` + show drop highlight, else `None`; `Drop` → filter → `LoadCommand.Execute(firstVideoPath)` (Split loads a single file). Reuse the existing `LoadCommand`/`Load(path)`.
- **JoinView code-behind** — same drag affordance; `Drop` → filter → `AddFilesCommand.Execute(allVideoPaths)` (order preserved) → the existing compat re-check fires.
- **Drop affordance** — a subtle overlay/border highlight while a valid drag is over the target (bind a `IsDragOver` flag or toggle a border in code-behind). Keep it simple.

## Detail
- Handle the case where the dragged data isn't FileDrop (e.g. text) → `e.Effects=None`, ignore.
- Empty-after-filter (dropped only non-videos) → no-op (optionally a brief status "no video files in drop"); never crash.
- Wire on the whole view (or the player/list area) so the drop target is generous.
- `e.Handled=true` on Drop.

## Interfaces / contracts
- Consumes: existing `SplitViewModel.LoadCommand`/`Load`, `JoinViewModel.AddFilesCommand`.
- Produces: `VideoFileFilter` (also reused by T-017 if needed) + the drop wiring.

## Acceptance criteria + Case-Coverage Matrix
- [ ] `VideoFileFilter.AcceptVideoFiles`: keeps `.mp4/.MKV/.mov` (case-insensitive), drops `.txt/.jpg`, dedupes, preserves order. (unit)
- [ ] SplitView: dropping a video → `LoadCommand` invoked with that path (verify via the VM being called; the event wiring itself is manual/app-run).
- [ ] JoinView: dropping 3 videos → `AddFilesCommand` invoked with all 3 in order.
- [ ] Non-video-only drop → no command invoked, no crash.
- [ ] Build + existing 205 tests green.
- Matrix — Required-Success: valid video drop → load/add. Required-Fail: non-video drop → ignored. Boundary: mixed drop (videos + non-videos → only videos); empty drop; duplicate paths (deduped); many files.

## Edge cases
Mixed payload; non-FileDrop payload; only-non-videos; duplicate paths; a folder path (ignore in v1 — filter drops non-files by extension).

## Dependencies
None unfinished (Split/Join screens shipped in G-001).

## Risks
Drag events unverifiable headless (D2) → filter is unit-tested; live drop via `app-run`.

## Out of scope
Reorder-drag (T-017); folder recursion; drop-on-timeline.
