## What is wrong

`tests/Core.Tests/FfmpegTestBinaries.cs` hardcodes ffmpeg at
`D:\_env_storeage\ffmpeg-7.1.1-essentials_build\bin\ffmpeg.exe`. `SkipIfMissing` writes an xUnit
output line and returns `true`; every caller then does a bare `return;`.

**xUnit records that method as PASSED, not Skipped.** That is why a local run reports 0 skipped while the
guard is live — the guard is invisible in the result count.

On GitHub's `windows-latest` that path does not exist, and `packaging/fetch-ffmpeg-shared.ps1` runs
*after* the `Test (release gate)` step and would not put ffmpeg there anyway. So **43 `[Fact]`/`[Theory]`
methods** across `SplitEngineIntegrationTests`, `JoinEngineIntegrationTests`, `SmartCutEngineIntegrationTests`
and the probe suites report green on CI **without executing anything**.

## The concrete failure it allows
The release gate is the last thing standing between a broken cut and a shipped installer. Every test that
actually exercises ffmpeg — lossless split, join, smart/exact cut, keyframe probing — passes vacuously
there. A regression that corrupts output would go out with a green gate.

## Design
1. Resolve ffmpeg by discovery, not a hardcoded absolute path: `FFMPEG_PATH` env var → `PATH` →
   the packaging download location → the current hardcoded path last.
2. When it genuinely is absent, the tests must **skip visibly** (`[SkippableFact]` / `Assert.Skip`), never
   return as passed. A skipped test is honest; a vacuous pass is not.
3. Make CI **fail** if the integration tests skip on the release-gate job: fetch ffmpeg *before* the test
   step, then assert a minimum executed count so absence is loud rather than silent.

## Acceptance criteria
- [x] No test method can report Passed without executing its body. `SkipIfMissing` can no longer
      return `true` (asserted: `TheOldShimCanNoLongerReturnTrue`) — it returns false or throws.
- [x] Absent ffmpeg throws a skip rather than returning (asserted:
      `AMissingBinarySkipsVisibly_RatherThanPassingSilently`), and all 39 affected tests now carry
      `[SkippableFact]`/`[SkippableTheory]`, which is what turns that into a Skipped result.
- [x] `release.yml` fetches ffmpeg **before** the gate and sets `VSJ_REQUIRE_FFMPEG=1`, which makes a
      missing binary a hard failure (asserted:
      `WhenTheEnvironmentDeclaresFfmpegRequired_AMissingBinaryFAILS`).
- [x] Verified by mutation. Making every split segment one second short
      (`-to` given `duration - 1s`) left **all 17 fake-based `SplitEngineUnitTests` passing** and
      **failed the real-media `SplitEngineIntegrationTests`** — the suite that previously reported
      PASSED on CI without running. That is the defect class the gate exists to stop.

## Out of scope
Rewriting the integration tests themselves. They are fine; nothing runs them.

## Outcome — 2026-09-02

**The gate could not fail, and now it can.**

### What was actually wrong
`FfmpegTestBinaries` pointed at one absolute path on one machine, and `SkipIfMissing` returned `true` so
callers could early-`return`. xUnit records a method that returns normally as **PASSED** — so on CI, where
that path does not exist, 43 integration tests reported green **without executing anything**. The old
summary comment stated the intent out loud: *"a CI machine without the binaries stays green."* Staying
green by not running is not a gate. Compounding it, `release.yml` fetched ffmpeg in the step **after** the
gate, so even a correct guard would have found nothing.

### What changed
- **Resolution by search, not assumption**: `VSJ_FFMPEG_DIR` → `ffmpeg-shared/` and `ffmpeg/` walked up
  from the test output (where `packaging/fetch-ffmpeg-shared.ps1` writes) → `PATH` → the historical
  hardcoded path **last**, so the machine it worked on keeps working. Extracted as `ResolveFrom` so the
  search is tested by behaviour rather than asserted from a comment.
- **Absence is loud**: skip visibly by default, **hard fail** when `VSJ_REQUIRE_FFMPEG` is set. 39 tests
  across 11 suites converted to `[SkippableFact]`/`[SkippableTheory]` — and only those; the fake-based
  tests in the same files were deliberately left alone.
- **CI order fixed**: fetch precedes the gate, which now runs with `VSJ_FFMPEG_DIR` pointed at the fetched
  build and `VSJ_REQUIRE_FFMPEG=1`.

### The proof that matters
Reasoning about a gate is worth little, so it was mutated: `-to` was given `duration - 1s`, making every
split segment a second short — a real, user-visible output defect.

| suite | result under the mutation |
|---|---|
| `SplitEngineUnitTests` (17, fake-based) | **all pass** — fakes cannot see it |
| `SplitEngineIntegrationTests` (real media) | **fails** |

Before this ticket that second row would have read *"passes, without running"* on CI. The gate now catches
the class of defect it exists for.

### Honest limit
That skip-throw becomes a *Skipped* result is the documented behaviour of `Xunit.SkippableFact`, and the
attribute is applied to all 39 tests — but it was not observed end-to-end here, because this machine has
ffmpeg and every integration test genuinely runs (0 skipped, 461 Core tests). The unit tests prove the
throw; the library provides the translation. First CI run will confirm it in the wild.

Suite 1303 → **1312 green**, 0 skipped.
