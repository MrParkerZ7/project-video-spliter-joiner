## Why / vision
The natural place to export cut parts is next to the source file. The user wants the output dir to default there and re-anchor to each newly-loaded file — while staying editable for the one-off case.

## Gap from current state
After G-010/T-038 ("remember last input/output folder"), `SplitViewModel` defaults `OutputDir` to the **remembered `LastOutputDir`** (falling back to the input folder only when unset), and a new load does NOT reliably re-anchor it to the new file's folder. So the default is "last place I exported," not "where this file is" — the opposite of the ask.

## Decisions
- **D1 · On every load, reset `OutputDir` = the loaded file's folder** — in `SplitViewModel.LoadAsync` (which both the drag-drop and picker paths call via `LoadCommand`), unconditionally set `OutputDir` to `Path.GetDirectoryName(path)` on each load. This overrides the T-038 "default to remembered last-output" precedence — the file's folder wins as the default, and a new load re-anchors it (discarding any manual change the user made for the previous file).
- **D2 · Still configurable** — `OutputDir` stays user-editable (the output field / picker); the reset only happens on a NEW load, not while the user is working with the current file.
- **D3 · Keep the input-folder memory** — remembering `LastInputDir` for the file **picker's** initial directory (T-038) is orthogonal + still useful — keep it. Only the OUTPUT-dir default rule changes (file's-folder per load, not remembered-output). Decide whether to drop `LastOutputDir` entirely or keep it as a non-default hint — dropping the output-default is simplest and matches the ask; note it.

## Risks
- Interaction with T-038 — don't regress the input-picker memory; only change the output default. Update the T-038 output-dir tests to the new expectation.
- Path edge cases (file at a drive root, UNC, unicode) → `GetDirectoryName` handles most; guard null.

## Out of scope
Per-file remembered output overrides, an output-naming template change — later. This only sets the default + reset rule.
