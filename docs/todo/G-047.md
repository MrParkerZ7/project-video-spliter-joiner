## Why

User: *"I want button snapt-shot current play video into thumnail of profile thumnail"*

Cut profiles already carry a picture, and there are two ways to set one: it is grabbed automatically from
the intro-end frame when a profile is saved, or the user picks an image file (**Thumbnail…**, added in
T-129 after the same user reported the upload was unreachable).

Neither matches what someone actually does when choosing a profile picture: they play the video until
they see a frame that represents it, and then want *that* frame. Doing it today means grabbing a
screenshot with another tool, saving it somewhere, and uploading it — for a frame the app already has
decoded on screen.

Everything needed is already in place — the frame-grab service, the profile thumbnail width, and the
store-and-attach step with its classified failure reporting. This is a third entry point onto that path,
not new machinery.

## Out of scope
Cropping/editing the frame. Per-row thumbnails, which already come from the cut points (T-108).
