## Concept
Put the **cut-positions list** (the "Cut markers" / marker list — the cut POSITIONS) and the **"Parts to export"
list** **side by side**, sharing the horizontal width, instead of stacking each full-width. Uses the tool-panel
width better and saves vertical space.

## ⚠ Interpretation to confirm (premise)
The user wrote *"section of `Position` and `Parts to export` to share horizontal size."* I'm reading **`Position`**
as the **Cut-markers / marker LIST** (it holds the cut positions, and its field is labelled `POSITION`) — so the
plan pairs the **marker list** with the **segments list** as two equal-width columns. **If instead you meant the
compact `POSITION` field ROW (`POSITION` label + time box + "Add at time", `SplitView.xaml:216-228`) sitting beside
the Parts-to-export block, say so — the layout differs (a thin control beside a tall list).** Building assumes the
two-lists reading; flip at the review gate if wrong.

## Design (two-column, grounded)
- In `SplitView.xaml`, wrap the **Cut-markers section** (header + "Add cut at playhead" + POSITION row + marker
  `ListBox` `:231`) and the **Parts-to-export section** (header + chips + segments `ListBox` `:294`) into a
  **2-column `Grid`** (`ColumnDefinition *` / small gap / `*` — equal, shared width), each section its own column.
  Keep every control/binding (Add-at-playhead, POSITION field, All/None chips, seek/remove, selection) intact —
  re-parent, don't rewire.
- **Height:** give the two lists a shared/comparable `MaxHeight` so the columns balance; the shorter column's
  trailing space is acceptable.
- **★ Narrow-panel tension (the real design risk — UI Designer lens):** in **horizontal** mode the tool panel is
  ~360px (300–520), so two side-by-side lists get ~165px each — tight but workable for mono rows; verify the marker
  rows (`Display` + ▶seek + Remove) and part rows don't clip/wrap badly at min width. In **D-001 vertical** mode the
  tool panel is the **full-window-width bottom row** — side-by-side is roomy there. If ~165px proves too cramped in
  horizontal mode, the fallback is a responsive stack-when-narrow / side-by-side-when-wide (note it; don't over-build).
