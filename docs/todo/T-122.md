## Concept
Make `ReplaceOriginal` safe by construction. Under `_trimmed` a wrong cut costs a disk write; under replace it
is **unrecoverable**. The ordering produce → verify → replace is non-negotiable, and the user must have an undo path.

## Design
- **Verify before replace** — the original is only touched AFTER ffmpeg has fully exited and the temp output is
  verified complete. Keep the existing "was not produced by ffmpeg (got fewer segments than planned)" throw
  (`SplitEngine.cs:454-458`, SPEC-001 I35) as the gate; a failed/cancelled/partial run must leave the original
  **bit-identical**.
- **Atomic replace with backup** — prefer `File.Replace(temp, original, backup)` (single-volume by construction).
  On `PlatformNotSupportedException`/`IOException` (exFAT/SMB/network) fall back to rename-original-to-backup →
  move temp into place → dispose backup.
- **Undo path** — a new `IOriginalDisposer` seam modelled on `IDiskSpaceProbe` (`src/Core/Io/IDiskSpaceProbe.cs`):
  the default impl sends the backup to the **Recycle Bin** (undo survives batch end and app exit); plain-delete
  and keep-backup impls exist for tests/opt-in. Core stays UI-free and the seam keeps this deterministically testable.
- **Release the file first** — `RunBatchAsync` calls `Player.Stop()`, but `FfmeMediaPlayer.Stop` only stops
  playback; `Unload` is what closes the element and releases the handle. Under `ReplaceOriginal` the preview must
  **Unload** the selected row's file before the batch, or the replace fails on a locked file.
- **Double-trim guard** — a `Done` row stays enabled today, so a second Run re-trims the already-trimmed master.
  Under `ReplaceOriginal`, skip/disable rows already `Done` in this batch.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Happy path: the original is replaced by the trimmed output and a recoverable backup exists (Recycle Bin by default).
- [ ] ffmpeg fails / produces fewer parts → the original is **untouched and byte-identical**; no partial clobber.
- [ ] Cancel mid-run → the original is untouched.
- [ ] `File.Replace` unsupported → the fallback still ends with the original replaced and a backup present; never a
      state where the data exists nowhere.
- [ ] The preview player no longer holds the file open when the batch starts in this mode.
- [ ] Re-running a `Done` row does not double-trim the master.
- Matrix — Required-Success: replace + backup. **Required-Fail: every failure mode leaves the original intact**
  (the load-bearing case). Boundary: locked file, read-only file, zero-byte temp, cancel between verify and
  replace, cross-volume fallback. **Perf (no-I/O-on-reject): a run blocked by pre-flight/validation performs ZERO
  destructive calls — assert the disposer/replace seam is never invoked.**

## Out of scope
A Recycle-Bin restore UI; multi-volume moves beyond the documented fallback.
