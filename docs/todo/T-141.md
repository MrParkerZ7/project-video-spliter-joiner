## Reported
> when I click save new profile the profiles bar move to middle of page and all content gone

With a screenshot: the profile bar floating mid-window, clipped on the right, and the preview, list and
footer all absent.

## Cause — REPRODUCED, and it is a layout bug, not the input bug I twice guessed at

```xml
<ColumnDefinition Width="*" />      <!-- subtitle, TextWrapping="Wrap" -->
<ColumnDefinition Width="Auto" />   <!-- profiles bar -->
```

A WPF `Auto` column is **measured with infinite available width**. The profiles bar therefore reported
its full one-line desired width (~1130px once a profile exists and the picker + both Apply buttons
appear). The Grid honoured that, leaving the `*` column ~115px. The subtitle wraps, so at 115px it became
a one-word-wide column many lines tall — and root row 0 is `Auto`, so the header grew to fit it and
pushed everything below out of the window.

Trigger is `HasProfiles` false→true, i.e. **saving the first profile** — which is exactly when the user
saw it. Narrower windows make it worse, which is why it hit hardest in Vertical layout mode.

Reproduced deterministically without any clicking: write a settings file containing one `cutProfiles`
entry, launch, open Bulk Cut. The subtitle is visibly crushed into a vertical sliver.

## Two earlier fixes were aimed at the wrong thing
T-138 attempt 1 (release mouse capture on close) and attempt 2 (drop `StaysOpen="False"`,
`AllowsTransparency`, `PopupAnimation`) were both about input being swallowed. Nothing was swallowing
input; the controls had been pushed off-screen. Both changes are independently correct and stay, but
neither addressed this.

## Fix
Reverse the sizing so neither column can starve the other:

```xml
<ColumnDefinition Width="Auto" />                <!-- subtitle, bounded by MaxWidth="420" -->
<ColumnDefinition Width="*" MinWidth="240" />    <!-- profiles bar -->
```

The subtitle can never demand more than 420px; the bar takes the remainder as a **finite** width, which
is also what finally lets its `WrapPanel` (T-136) actually wrap instead of overflowing.

## Verified
Screenshotted at 1074×900 — the width from the user's report — with a profile present: subtitle on two
lines, bar wrapped onto three rows, preview + list + footer all present, nothing clipped.

## Out of scope
The bar's visual grouping. This is about it not destroying the page.
