## Why

User: *"I also want auto clear all after done check box near by `replace originals`"*

The batch workflow already automates the two steps after a run — *Auto-delete originals* and *and empty
bin* (G-050 / T-156). Clearing the list is the third and last thing you do before loading the next season,
and it is still manual. Asking for it beside the others is consistent with what those two already do.

## What makes this less trivial than it looks

`Clear()` (`BulkCutViewModel.cs:1232`) does not only drop rows. It also calls `Operation.Reset()`, sets
`BatchState = Idle`, and empties `LastFailedItems`. Wire the existing method to "batch finished" and the
run's **report vanishes at the moment it is produced** — the aggregate summary, the per-row outcomes, the
"Sent N to the Recycle Bin. Still in use: …" line. The user would watch the batch complete and be left
with an empty screen and no evidence of what happened.

That is worse than the manual Clear it replaces, because a manual Clear is a decision made *after* reading
the report. So this feature is not "call `Clear()` when the batch ends"; it is "clear the rows and keep the
account of what was done to them".

## Out of scope

Auto-clear on the Split or Join screens. Bulk Cut is the screen with a list worth clearing; the other two
load one file at a time. If it proves useful here it can be mirrored, exactly as delete-original was
(G-052) — mirroring a feature that has settled is cheap; mirroring one that has not is how three screens
end up disagreeing.
