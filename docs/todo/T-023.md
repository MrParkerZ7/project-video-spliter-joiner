## Concept
The user finds auto-detect unhelpful — remove it entirely. Delete the black/white/scene detector and every UI/VM hook, leaving manual cut markers + the playhead + click-to-cut intact. A clean subtractive change that keeps the build + remaining tests green.

## Design
Remove, end to end:
- **Core:** delete `src/Core/Detect/` (`SplitPointDetector`, `DetectArgsBuilder`, `DetectParser`, `Candidate`, `CandidateKind`, `DetectOptions`, `RawHit`).
- **Composition:** `MainViewModel` stops constructing `SplitPointDetector`; drop the `ISplitPointDetector` ctor arg from `SplitViewModel`.
- **SplitViewModel:** remove `Candidates`, `AutoDetectCommand`, `AddSelectedCandidatesCommand`, `PreviewCandidateCommand`, and the `CandidateViewModel` type. Keep markers/load/run/set-cut-at-playhead/seek-to-marker.
- **SplitView.xaml:** remove the "Auto-detect" button + the candidates list panel + any candidate legend. Keep the marker list + player + timeline.
- **Timeline (T-014):** remove `CandidateTicks` from `TimelineViewModel` + candidate rendering + the kind legend from `TimelineView`; keep `MarkerTicks`, playhead, click-to-cut, `ClickAt`, marker seek. Remove `CandidateKindToBrushConverter` if now unused.
- **Tests:** delete `DetectParserTests`, `DetectArgsBuilderTests`, `SplitPointDetectorIntegrationTests`, and any candidate-specific cases in `SplitViewModelTests`/`TimelineTests`/playhead tests. Keep all marker/split/join/player tests.

## Detail
- This is DELETION — do not leave dead references, unused usings, or orphaned converters. Grep for `Candidate`, `Detect`, `AutoDetect`, `SplitPointDetector`, `CandidateKind` across `src/` + `tests/` and clean every hit.
- Keep `CandidateKind`/detect types out of the public surface — nothing outside Detect should still import them after removal.

## Interfaces / contracts
- `SplitViewModel` ctor loses the detector param (update `MainViewModel` + any test constructing it).
- No new API; the `IMediaPlayer`/split/join contracts are untouched.
