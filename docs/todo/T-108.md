## Concept
On each Bulk Cut row, show a small **frame thumbnail at the intro-end cut point** (and, when set, at the **outro-start**),
so the user can verify where the cut lands at a glance — without hovering or scrubbing. The thumbnails update (debounced)
as the handles move, grabbed at the keyframe-**snapped** time so they match the real cut. Best-effort — a placeholder
while loading / if unavailable; never blocks the UI.

## Grounding (real reuse)
- `IThumbnailService.GetThumbnailAsync(inputPath, TimeSpan time, int width, ct) → string?` — `src/Core/Thumbnails/IThumbnailService.cs:31`
  (LRU time-bucket cache, coalescing, best-effort null). The Bulk tab holds the shared instance (T-101/G-037).
- `ThumbnailPreviewViewModel` (`src/App/ViewModels/ThumbnailPreviewViewModel.cs`) — the **debounce (60ms) + latest-wins
  coalesce + cancel-prior** pattern to mirror (a superseded grab is dropped; only the current request updates the image).
- `BulkItemViewModel` (`src/App/ViewModels/BulkItemViewModel.cs:163/166`): `IntroEnd` (CutMarkerViewModel) + `OutroStart?`
  handles, each with a `Snapped` time; `IntroEnd.PropertyChanged += OnHandleChanged` (`:122`) already fires on Snapped
  change — the hook to trigger a re-grab. `Path`, `HasOutro`.
- `BulkRowScrubView` / the row DataTemplate in `BulkCutView.xaml` — where the two small thumbnails render (near the
  IN/OUT readouts or under the handles).

## Design
1. **Per-row thumbnail state (WPF-free on `BulkItemViewModel`)** — `IntroThumbnailPath` (string?) + `OutroThumbnailPath`
   (string?). A small per-handle grabber modeled on `ThumbnailPreviewViewModel`: on `IntroEnd.Snapped` change (via the
   existing `OnHandleChanged`) → debounce ~150–250ms (slower than hover; the cut settles) → cancel any prior grab →
   `GetThumbnailAsync(Path, IntroEnd.Snapped, thumbW, ct)` → set `IntroThumbnailPath` only if still current. Same for
   `OutroStart.Snapped` when `HasOutro`. Clear the outro thumb on `ClearOutro`. Inject `IThumbnailService` into the row
   (the tab VM already has it — thread it through `AddFilesAsync`'s row construction).
2. **Trigger points** — initial grab when the row's keyframes resolve (Snapped becomes real), and on every handle move
   (debounced) + apply-to-all/profile-apply (Snapped changes → re-grab). Reuse the shared cache so repeated times are cheap.
3. **View** — two small `Image`s (~48–64px wide) on the row: one at the intro-end, one at the outro-start (shown only when
   `HasOutro`). Null-safe path→ImageSource binding → a placeholder (muted chip / the scrim) while loading or if the grab
   returned null. Keep the row height reasonable (thumbnails compact; consider showing them under/next to the scrub bar).
   Load images with `BitmapCacheOption.OnLoad` so files aren't held open.
4. **Bound concurrency** — the per-row grabs must respect the existing keyframe-scan discipline (don't thundering-herd on
   add). Reuse/extend the `SemaphoreSlim` bound (T-096) or the thumbnail service's own coalescing; a large batch must not
   fire N×2 simultaneous ffmpeg frame grabs. Grabs are best-effort + off the UI thread + cancellable per row (Remove/Clear).

## Acceptance criteria + Case-Coverage Matrix
- [ ] Each Bulk row shows a frame thumbnail at intro-end; when an outro is set, a second at outro-start; both update (debounced) as the handles move, grabbed at the keyframe-snapped time.
- [ ] Best-effort: a placeholder shows while loading / if the grab returns null; a failed/cancelled grab never breaks the row; images don't lock their files.
- [ ] Grabs are debounced + latest-wins (a fast drag doesn't spawn a grab per pixel) + bounded in concurrency across a large batch; per-row cancel on Remove/Clear; WPF-free VM state.
- [ ] Reuses IThumbnailService (shared cache) — no second frame-grab path; Split/Join untouched; per-row scrub bar (T-097) still works.
- [ ] Build 0-warning; suite green + tests (fake IThumbnailService): grab-on-snapped-change, debounce coalesces rapid moves, outro thumb appears/clears with the handle, null grab → placeholder, per-row cancel.
- Matrix — Success: mark a cut → its frame appears; drag the handle → thumb updates. Boundary: no-outro row (one thumb), rapid drag (debounced, one grab), grab returns null (placeholder), row removed mid-grab (cancelled), 20-file batch (bounded, no herd). Required-Fail: none. (Look = app-run.)

## Dependencies
Reuses `IThumbnailService` + the `ThumbnailPreviewViewModel` debounce pattern + `BulkItemViewModel` handles. Independent
of T-106/T-107 (no profile dependency) — a second proceedable root of G-038.

## Risks
Performance — many rows × 2 thumbnails must stay cheap: lean on the shared LRU cache + coalescing + a concurrency bound +
a slower debounce than hover. Don't hold image files open (OnLoad). Row height/layout pressure — keep thumbnails small and
integrated near the handles/readouts, not a new full column that crowds the scrub bar.

## Out of scope
Profile thumbnails (T-106/T-107); Split/Join thumbnails; scrubbable/animated per-row previews; a thumbnail on the preview pane (already has the player).
