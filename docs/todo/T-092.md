## Concept
Make the **"Add cut at playhead"** button visually pop — it's THE primary cut gesture but currently renders in the
plain default button style (surface grey), so it doesn't read as the main action. Give it an "extra highlight"
treatment, distinctly more prominent than a normal button (even more than the standard gold `AccentButton`).

## Current state (grounded)
`SplitView.xaml:245` — `<Button Content="Add cut at playhead" ... Command="{Binding SetCutAtPlayheadCommand}" />`
with **no explicit Style** → the default surface button. On the Cut-markers add row (a `WrapPanel` shared with the
POSITION field + "Add at time"). The app already has `AccentButton` (Controls.xaml:84 — "GOLD primary action, dark
text, bolder"), used by the Run/Split button (`:439`). Accent tokens: `AccentBrush` #E0A83A, `AccentHoverBrush`
#F0BC55, `AccentTextBrush` #16130A (dark on gold), `AccentMutedBrush`.

## Design (the "extra highlight" treatment — build applies as a new keyed style, e.g. `HeroButton`)
Beyond the standard `AccentButton` gold, add prominence (UI Designer lens — differentiate by ≥2 of size / weight /
color / elevation / ornament, not just a tint):
- **Gold accent fill** (`AccentBrush`) + **dark accent text** (`AccentTextBrush`), **SemiBold/Bold** — the primary look.
- **Larger** — bigger padding (~`16,8`) + slightly larger font than the surrounding buttons, so it's the biggest control in the section.
- **An icon** — a small `✚`/cut/playhead glyph (a 1px vector `Path` in the caption-icon style, or a mono glyph) left of the text, to reinforce "add a cut."
- **A subtle gold glow / elevation** — a soft `DropShadowEffect` (AccentColor, low opacity, small blur) OR a stronger accent border, so it lifts off the panel. Keep it tasteful (not a neon).
- **Hover** — brighten to `AccentHoverBrush` (lighter gold) — already the AccentButton hover.
- Keep it on the Cut-markers add row; if it now dominates the `WrapPanel`, giving it **its own line above** the POSITION field is acceptable (it's the primary gesture) — the build decides what balances best.
- Preserve `SetCutAtPlayheadCommand` + the tooltip.

## Acceptance criteria + Case-Coverage Matrix
- [ ] "Add cut at playhead" is clearly the most prominent control in the Cut-markers section (gold + larger + bolder + icon + subtle elevation).
- [ ] Reads well on the dark theme; hover brightens; disabled state still legible (button disables when no file/not ready per its command).
- [ ] Doesn't break the Add-cut/POSITION row layout (wraps or takes its own line gracefully at narrow width + in both layout modes).
- [ ] Uses design tokens (AccentBrush/AccentTextBrush/AccentHoverBrush) — no hardcoded hex.
- [ ] Build 0-warning; suite green (layout/style-only; no VM change).
- Matrix — Success: the button pops as the primary action. Boundary: narrow panel (row wraps), vertical mode, disabled (no file). Required-Fail: none. (Exact look = app-run/user-verified — tunable up/down.)

## Dependencies
None. Refines the Cut-markers section (post T-090/T-091).

## Risks
"Extra highlight" is subjective — start with the treatment above (gold + icon + larger + subtle glow); the user
dials it up/down after seeing it. Don't overpower the Run/Split button (also gold) — the cut button can differ by
icon + placement so both read as primary without clashing.

## Out of scope
Other buttons; the Run button; new commands; animation beyond a subtle hover.
