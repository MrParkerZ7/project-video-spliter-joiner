## Concept
`todo-automate` reached **97% spec-case coverage (496/512)**; the remaining **16 invariants** aren't testable against
the code as-is — each needs a small **source refactor** (extract a pure helper / add an injectable seam) or a harness.
This task makes them testable, then adds the `serves-spec` tests, closing the coverage tail. Low priority — the code is
correct + verified live; this is testability hygiene. Full deferred list: `docs/specs/_GAPS.md`.

## Design (per gap group — do the high-value, low-risk ones first)
1. **`IDiskSpaceProbe` seam on `SplitEngine`** (SPEC-001 I31) — mirror `BulkTrimEngine`'s injectable disk probe so the
   DiskFull + unmeasurable-drive branches unit-test with a fake. **Highest value / lowest risk — do first.**
2. **Extract pure geometry/math helpers from the WPF views** (SPEC-014 I31/I32/I33/I35) — pull `NearestTick(x,width,ticks,radius)`,
   the Bulk scrub span-geometry (`introX/outroX/keepLeft/keepRight`), `PickHandle` (dIntro/dOutro/radius/tie-by-Y), and
   `PeakForColumn` max-per-column bucketing into a WPF-free helper class (App or Core) → unit-test the math directly. The
   view code-behind calls the helpers (no behavior change).
3. **Extract `WM_GETMINMAXINFO` `rcWork→ptMax` math** (SPEC-015 I23) into a pure helper → test the clamp.
4. **Refactor `App.xaml.cs` crash-handler wiring** (SPEC-015 I24) to injectable methods (log→dialog→Handled) → test the policy.
5. **Resource-style tests** (SPEC-015 I26/I27/I28 — ToolTip/ScrollBar/HeroButton) — needs a harness that loads the merged
   theme dictionary (pack URIs). Assess feasibility; if no cheap load path, leave as visual-QA + note (lowest value).
6. **Defensive-guard assertions** (SPEC-001 I22, SPEC-003 I23) + **FfmeMediaPlayer WPF-bound** (SPEC-013 I47/I48) —
   likely **stay deferred** (unreachable / needs a MediaElement harness; verified live). Confirm + document, don't force.

## Risks

## Out of scope
Any behavior change; the resource-style theme-load harness if it proves expensive (note + move on).
