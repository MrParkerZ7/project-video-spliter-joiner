## Concept
Replace the concrete player behind `IMediaPlayer` with an FFME-backed one, and swap the WPF `<MediaElement>` in `PlayerView` for FFME's control — so the preview decodes via ffmpeg. The `IMediaPlayer` contract, `PlayerViewModel`, `SplitViewModel`, and all their tests are unchanged (D3).

## Design
- New/renamed impl (e.g. `FfmeMediaPlayer : IMediaPlayer`) wrapping `Unosquare.FFME.MediaElement`:
  - `Open(path)` → `await Media.Open(new Uri(path))` (FFME is async; marshal safely — fire-and-forget with error surfaced, or an async void handler).
  - `Play/Pause/Stop` → FFME's; `Position` get/set → FFME `Position`; `Duration` ← FFME `NaturalDuration`/`MediaOpened`.
  - Events: use FFME's real `PositionChanged`, `MediaOpened`, `MediaEnded`, `MediaFailed` → map to `PositionChanged`/`DurationAvailable`/`Ended`/`Failed`. **Drop the DispatcherTimer** (FFME reports position natively).
  - Keep the `Attach(control)` seam so `PlayerView` code-behind hands the control in.
- `PlayerView.xaml`: replace `<MediaElement x:Name="Media">` with `<ffme:MediaElement x:Name="Media">` (add the `xmlns:ffme` + package ref). Keep the same layout/row.
- `MainViewModel` composition: construct the FFME-backed player instead of `MediaElementPlayer` (or keep the class name, swap internals — least churn).

## Detail
- FFME's `MediaFailed` still drives the existing `PreviewFailed` banner — but with ffmpeg decoding, genuinely-cuttable files should no longer fail.
- Ensure `Library.FFmpegDirectory` (T-019) is set before the control initializes.
- Preserve behavior: first-frame-on-open (FFME shows the first frame after Open), scrub via `Position`, the seek-feedback suppression in `PlayerViewModel` still applies.

## Interfaces / contracts
- Consumes: the FFME package + init from T-019.
- Produces: the FFME-backed `IMediaPlayer` + updated `PlayerView`. The `IMediaPlayer` surface is IDENTICAL — no VM change.

## Acceptance criteria + Case-Coverage Matrix
