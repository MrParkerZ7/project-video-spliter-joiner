## Why

User: *"for profile setting please make sure setting was saved and restore able even after reinstall app
again"*

Checked before planning. Uninstall already leaves them alone — the Inno script has no `[UninstallDelete]`
— but that is an accident of the current script rather than a guarantee, and nothing would catch a future
edit that started deleting user data.

The sharper problem is that a profile lives in **two different roots**: the profile itself in Roaming
`%APPDATA%`, its picture in Local `%LOCALAPPDATA%`. Back up "settings" and you keep the profiles and lose
every image, with the `ThumbnailPath` left pointing at a folder that does not exist. And there is no
export/import, so "restorable" today means copying two folders by hand.

## Out of scope
Cloud sync. Sharing profiles between users.

## Outcome — 2026-09-01 (T-147)

All three success criteria met.

- *Uninstall/reinstall leaves everything intact, with a test saying so* — `InstallerLeavesUserDataTests`
  asserts the real installer script deletes nothing under the user profile; `ProfileSurviveReinstallTests`
  asserts neither storage root sits under the install directory and that fresh instances over the same
  folders find every profile and picture.
- *Export to one file, import on another machine, pictures included* — `ProfileBackup` embeds images
  inline as base64, so one file survives the trip across the Roaming/Local split that would otherwise
  strip every picture silently (ADR-0021).
- *A broken or partial import never damages what is already there* — import plans before it acts, a
  failed plan proposes nothing, and a name collision defaults to keeping the existing profile.

Backup remains a manual gesture; automatic/scheduled/cloud backup was not built and is not implied.
