## Why / vision
Two polish gaps: (1) the scrollbar is the default light WPF chrome — primitive against the dark themed UI; (2) the operation state is unclear — the progress/status UI is bound to `IsRunning`, so when a split/join finishes it just disappears with no "done" confirmation. The user should always know the state: running, done (with a result), cancelled, or failed.

## Grounding (2026-07-18)
- **No custom `ScrollBar` style** in `Themes/Controls.xaml` (the ScrollViewers at :143/:341 are inside TextBox/ComboBox templates). The right-column tool panel + others use `ScrollViewer` → default OS scrollbar.
- **`OperationState` enum:** Idle / Running / Completed / Cancelled / Failed (`OperationViewModel`). `IsRunning`, `Error` (Failed), `Progress`, `StatusText`, `EtaText`, `CanCancel` exist.
- **UI today** (`SplitView.xaml` ~:335-378): ProgressBar + StatusText + EtaText + Cancel are all `Visibility=IsRunning` → they vanish on Completed. The Error block shows only when `Operation.Error != null` (Failed). **No Completed/Cancelled surface** — success is invisible.

## Decisions
- **D1 · Themed scrollbar** — add an implicit `Style TargetType="{x:Type ScrollBar}"` (+ thumb / repeat-button templates) in `Controls.xaml`: thin, rounded, track = a low surface tier, thumb = `BorderStrongBrush` with `AccentBrush` (gold) on hover/drag; support vertical + horizontal. Implicit (no `x:Key`) so it applies app-wide. Keep it usable (min thumb size, hit area).
- **D2 · Operation state surface** — replace the `IsRunning`-only block with a small state panel that renders per `OperationState`:
  - **Running** — gold-accented progress bar (indeterminate while preparing, % when known) + StatusText + ETA + Cancel. (Enhanced by G-025 taskbar/per-part if that lands.)
  - **Completed** — a clear success line: ✓ (green `OkBrush`) + a result summary (e.g. "Split into 3 parts" / "Joined 4 clips → joined.mkv") + an **Open folder** affordance. Persists until the next load/run/clear.
  - **Cancelled** — a muted "Cancelled" note (neutral, not error-red).
  - **Failed** — keep the existing red error block (copy error / open log).
  - Add VM helpers: `bool IsCompleted/IsCancelled`, a `ResultSummary` string — unit-testable — so the view switches on state cleanly (a state→visibility/style converter or per-state bindings).
- **D3 · Apply to both screens** — Split and Join share the pattern; do both.

## Risks
- Custom ScrollBar templates are fiddly (repeat buttons, thumb min-size, both orientations) — reuse a known-good pattern; test scrolling still works (the tool panel, lists).
- The Completed surface must clear correctly on the next run/load/clear (no stale "done" from a previous file). Tie to state transitions + `Reset()`.
- Don't regress the existing Failed error block or Cancel.

## Out of scope
Scrollbar auto-hide/overlay animation; toast notifications; sound. Per-part/taskbar progress is G-025 (complementary — this is the overall lifecycle clarity).
