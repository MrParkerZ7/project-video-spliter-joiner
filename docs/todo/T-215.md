## Concept

`JoinViewModel.RefreshCompatAsync` (`JoinViewModel.cs:418`, called on add, remove and move at `:327, 338, 378`) has
no cancellation and no generation guard. With rapid removes or reorders, overlapping passes can finish out of order,
and whichever finishes last sets the banner and `IsCompatible`, which can be stale.

The fix is the `ThumbnailPreviewViewModel` pattern: a per-view-model CTS plus a generation counter, so only the
latest pass may set state.

## Why later

The race is verified in code but not reproduced. After T-193 a refresh is all cache hits and finishes almost at
once, which narrows the window.

## Trigger

A stale banner is reported. Or the next change to Join's compatibility flow.
