## Concept
The cut-profiles controls are a **flat inline horizontal strip** (`Profile [ComboBox] [Apply→selected] [Apply→all]
[Delete]` + `Save current as…`) — functional but visually undifferentiated. Improve the UX/UI: a clear, grouped, on-theme
profiles control with proper hierarchy, so the thumbnail-aware picker + its actions read as a coherent unit.

## Grounding (real state)
- `BulkCutView.xaml` profiles bar (T-103/T-107): a `StackPanel Orientation="Horizontal"` (`:119`) with a `Profile` label,
  the thumbnail `ComboBox` (`ProfileItemTemplate` = `[thumb chip] Name`, `:127`), **Apply → selected** (`:134`),
  **Apply → all** (`:141`), **Delete**, and a separate **Save current as…** button + inline name Popup; visibility gated on
  `HasProfiles` (an empty-state hint when none).
- Tokens/styles: `Controls.xaml` (`AccentButton`/`HeroButton`, themed ComboBox), `Tokens.xaml` (Surface/Border/Accent,
  Radius, spacing) — the UI Designer palette (dark + gold), the same system the rest of the app uses.

## Design (UI Designer lens — differentiate by hierarchy, not a flat row)
Establish the visual system first, then implement against tokens:
1. **Group into a bordered "Profiles" section/card** — a `Border` (SurfaceBrush/Surface2, RadiusMd, 1px BorderBrush,
   padding) with a small "Profiles" caption, so the profile controls read as one grouped unit distinct from the tab-strip
   Add/Clear/Run actions. Keep it compact + collapsible/subtle when there are no profiles (the empty "Save a cut profile"
   affordance stays unobtrusive).
2. **Make the thumbnail picker the hero** — the ComboBox (with its `[thumb] Name` items) prominent (a touch larger row,
   the selected profile's thumbnail shown clearly), the actions secondary + grouped: **Apply** (→ selected / → all as a
   split/paired control or two clearly-secondary buttons), **Save current as…** (primary/accent — the create action),
   **Delete** (subtle/danger-on-hover). Icons where they clarify (⧉ apply, ＋ save, ✕ delete) per the app's vector-icon style.
3. **Hierarchy by ≥2 of size/weight/color-role/spacing** — not a tint alone (the app's design rule). Save = accent/primary;
   Apply = secondary; Delete = muted→danger. Consistent spacing (SpaceSm/Md), aligned baseline, no cramped inline run.
4. **Tokens only** — reuse `AccentButton`/`HeroButton`/`Surface*`/`Border*`/`Radius*`/spacing; no hardcoded hex. Keep it
   working in BOTH layout modes (coordinate with T-112 — the profiles group lives in the header, above the split).
5. **No behavior change** — same commands (`SaveProfileCommand`/`ApplyProfileToSelected`/`ApplyProfileToAll`/`DeleteProfileCommand`),
   same thumbnail display, same empty-state; this is a visual/layout refactor of the View. (The apply-to-all *bug* is T-111.)

## Acceptance criteria + Case-Coverage Matrix
- [ ] The profiles controls are a grouped, bordered, on-theme section (not a flat inline strip) with clear hierarchy: hero picker, primary Save, secondary Apply, muted Delete.
- [ ] The thumbnail-aware ComboBox reads clearly (selected profile's thumb visible); the empty-profiles state stays unobtrusive.
- [ ] Tokens only (no hardcoded hex); differentiated by ≥2 of size/weight/color-role/spacing; consistent with the app's dark+gold system.
- [ ] Works in both layout modes (T-112); no command/behavior change — all profile actions still fire (Save/Apply/Delete + thumbnails).
- [ ] Build 0-warning; suite green (864 — view/style-only, existing profile VM tests stay green).
- Matrix — Success: profiles group reads as a coherent, attractive unit. Boundary: no profiles (subtle affordance), many profiles (ComboBox scrolls), long profile name (ellipsis), narrow width + both layout modes. Required-Fail: none. (Look = app-run/user-verified — tunable.)
