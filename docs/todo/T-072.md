## Concept
Replace the default light WPF scrollbar with a themed dark+gold style matching the IBM Plex design, applied app-wide.

## Design
- In `src/App/Themes/Controls.xaml`, add an implicit `Style TargetType="{x:Type ScrollBar}"` (no `x:Key`) with a `ControlTemplate` for both orientations (trigger on `Orientation`), plus a themed `Thumb` style and near-invisible `RepeatButton`s (line-up/down usually hidden or minimal in a modern flat scrollbar).
- **Look:** thin (~8–10px), track = a low surface tier (e.g. `Surface0/1Brush` or transparent), thumb = `BorderStrongBrush` (#3a4250) rounded (RadiusSm), `AccentBrush` (gold) on `IsMouseOver`/`IsDragging`. Min thumb length so it stays grabbable.
- Ensure it flows to nested `ScrollViewer`s (the right-column tool panel, marker/segment/clip lists, ComboBox dropdown). Implicit style covers all unless a local style overrides.

## Acceptance criteria + Case-Coverage Matrix
- [ ] Vertical scrollbar (tool panel / lists) uses the themed style — dark track, themed thumb, gold on hover/drag.
- [ ] Horizontal scrollbar themed too (where present).
- [ ] Scrolling still works (thumb drag, wheel, click-track); thumb has a usable min size.
- [ ] No light/primitive default scrollbar remains anywhere in the app.
- [ ] Build 0-warning; suite green (XAML resource change; no logic).
- Matrix — Required-Success: themed bar on the tool panel + a long list. Boundary: very long content (small thumb clamps to min); short content (bar hidden via Auto). (Exact look = app-run/user-verified.)

## Dependencies
None.

## Risks
Custom ScrollBar templates are fiddly (both orientations, repeat buttons, thumb min-size). Reuse a known-good flat-scrollbar pattern; verify scrolling isn't broken.

## Out of scope
Auto-hide/overlay animation; the operation-state surface (T-073).
