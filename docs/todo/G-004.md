## Why / vision
The preview uses WPF `MediaElement` (Windows Media Foundation), which lacks decoders for HEVC/H.265 and many MKV files — so the player shows "preview unavailable" for files the app can still cut. Decoding the preview via **ffmpeg** (Unosquare.FFME) makes the player show *exactly what the app can cut*. This is the parked **D1-alt** from G-002, now ripe because a real file hit the limit.

## Gap from current state
- Preview = `MediaElement` (MF codecs). Engine = bundled ffmpeg **static essentials** build (exe-only, no shared DLLs). No FFME package; no shared ffmpeg DLLs on disk.
- Missing: the FFME NuGet, an ffmpeg **shared** build (avcodec/avformat/avutil/… DLLs) matched to FFME's required major version, startup `Library.FFmpegDirectory` wiring, the player-impl swap, and packaging of the DLLs.

## Decisions
- **D1 · Unosquare.FFME.Windows** (user-chosen) — renders to a WPF surface (clean fit with the timeline overlay, no airspace issues), decodes via ffmpeg. Version-pin: the FFME NuGet version dictates the ffmpeg MAJOR version of the shared build (resolve exactly in T-019, don't assume).
- **D2 · Consolidate on ONE ffmpeg shared build** — the shared build ships `ffmpeg.exe`/`ffprobe.exe` too, so the split/join engine (CLI) and FFME (DLLs) use the SAME bundled build. Replaces the essentials-exe bundle.
- **D3 · Keep the `IMediaPlayer` seam** — swap only the concrete impl (MediaElement → FFME) behind `IMediaPlayer`; `PlayerViewModel`/`SplitViewModel` + their tests are untouched. FFME has a real `PositionChanged` event (drop the DispatcherTimer).
- **D4 · Native libs gitignored** — shared DLLs are NOT committed (like the essentials binaries); a dev-setup step + packaging copy them in.

## Risks
- **FFME ↔ ffmpeg version mismatch** = the #1 failure mode (FFME hard-fails to init on the wrong ffmpeg major). Resolve the exact pairing in T-019 and verify init before building the swap.
- Native-lib load path (FFmpegDirectory must be set before the first FFME use).
- Packaging size grows (~+40MB shared DLLs); note it.
- Live playback only verifiable on the real desktop → verified via app-run + user confirmation on the failing file.
