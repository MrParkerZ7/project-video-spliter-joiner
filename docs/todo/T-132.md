## Concept
T-131 makes the failure legible. This makes it stop being a failure: the preview plays, and the
set-at-playhead gestures work, on a share whose server name contains a space.

## Why this is a separate ticket
`new Uri` cannot represent such a host — T-131 probed every construction and all of them throw. FFME's
only other entry point is `MediaElement.Open(IMediaInputStream)`, whose contract is:

```
Read(void*, byte*, int)    Seek(void*, long, int)    CanSeek
ReadBufferLength           StreamUri                 OnInitializing / OnInitialized
```

`Read` and `Seek` take raw pointers, so `VideoSplitJoiner.App` must enable `AllowUnsafeBlocks` — a real
change to the project's posture that deserves its own decision record, not a drive-by edit buried in a
bug fix.

## Design
1. **ADR** for enabling `AllowUnsafeBlocks`, scoped to the media-input adapter, recording the rejected
   alternative (no `Uri` form can express the host — see T-131's probe table).
2. `FileMediaInputStream : IMediaInputStream` over a `FileStream`: `CanSeek` true, a sane
   `ReadBufferLength`, `Read` copying into the supplied buffer and returning the count (0 / `AVERROR_EOF`
   at end), `Seek` handling `AVSEEK_SIZE`. `StreamUri` is an identifier only — nothing opens through it,
   so a synthetic placeholder is legitimate; say so in a comment or the next reader will assume it matters.
3. `FfmeMediaPlayer` routes to the adapter **exactly when** the path cannot be expressed as a `Uri`;
   every currently working path keeps the existing `Open(Uri)` route untouched.
4. Dispose the stream on Unload/Close, and confirm the T-080 reopen guard still sees a settled element —
   a held file handle would also block a later cut over the same file.

## Acceptance criteria
- [~] Preview plays, seeks, and reports duration from a path with a space in the server name.
- [x] The file handle is released on Unload — a subsequent cut over the same file is not blocked.
- [x] Every already-working path still goes through `Open(Uri)` — asserted, not assumed.
- [x] T-131's actionable message is kept for anything still refused; the now-working case and kept for anything still refused.
- [ ] **NOT MET — Verified against a real share.** No share with a space in its name exists on the dev
      machine, so end-to-end playback is UNPROVEN. The route is fail-safe by construction (it handles only
      paths that already error, and falls back to T-131's message if the file cannot be opened), and the
      AVIO contract is unit-tested over local files — but "it plays from a real NAS" must not be claimed
      until someone tries it. Recorded in ADR-0020 rather than ticked.

## Out of scope
Streaming from http(s)/rtsp or any non-file source.
