## Concept
The core interaction the user asked for: watch the video, and at the right moment click **"Set cut point"** to drop a cut at the current playhead — which then keyframe-snaps. Plus the inverse: click a marker or a detected candidate to **seek the player there** and preview before committing.

## Design
- Wire `PlayerViewModel` (T-012) ↔ `SplitViewModel` (T-007). Simplest: `SplitViewModel` owns/holds the `PlayerViewModel` (or they share via MainViewModel composition).
- `SetCutAtPlayheadCommand` (on SplitViewModel) → reads `Player.Position` → calls the EXISTING add-marker path (`AddMarker` with that TimeSpan) → the marker snaps via T-003 (reuse, D3). Enabled only when a file is loaded + Duration known.
- `SeekToMarkerCommand(marker)` → `Player.Seek(marker.Requested)` (or `Snapped` — seek to the SNAPPED time so the user sees exactly where the cut lands).
- `PreviewCandidateCommand(candidate)` → `Player.Seek(candidate.Time)` so the user can preview a detected candidate before selecting it.

## Detail
- On file load, `SplitViewModel.Load` also calls `Player.Open(path)` so the player and the marker/keyframe state load from the same file in one action.
- The "Set cut point" button lives near the player transport (added in T-012's PlayerView or SplitView); markers/candidates rows get a "�​go" affordance to seek.
- Guard: SetCutAtPlayhead when Duration unknown → disabled.

## Interfaces / contracts
- Consumes: `IMediaPlayer`/`PlayerViewModel` (T-012), `SplitViewModel.AddMarker` + snap (T-007/T-003).
- Produces: the commands T-014's timeline overlay also invokes (seek, set-cut-at-time).
- Add a general `AddCutAtCommand(TimeSpan)` on SplitViewModel (used by both playhead-capture and, in T-014, timeline-click) — one entry point, snaps once.

## Acceptance criteria + Case-Coverage Matrix
- [ ] With a fake player at Position=P, SetCutAtPlayhead adds a marker whose Requested==P and Snapped==nearest keyframe (reuses existing snap; asserted via fake keyframes).
- [ ] SeekToMarker(m) calls Player.Seek(m.Snapped) (fake records it).
- [ ] PreviewCandidate(c) seeks to c.Time.
- [ ] Load opens the file in the player (fake records Open(path)).
- [ ] SetCutAtPlayhead disabled when no file / Duration unknown.
- Matrix — Required-Success: playhead at P → snapped marker added. Required-Fail: capture with no loaded file → disabled/no-op. Boundary: playhead at 0 / at end; capture the same position twice → deduped by the existing marker logic.

## Edge cases
Capture at 0/end; duplicate capture (existing dedupe); seek-to-marker when player not ready; candidate preview before any play.

## Dependencies
T-012 (player), T-007/T-003 (marker + snap, reused).

## Risks
VM wiring/ownership between Player and Split VMs — keep one composition point (MainViewModel) to avoid a tangle. No new snap logic (reuse T-003).

## Out of scope
The visual timeline overlay (T-014) — this ticket is the commands + wiring; T-014 renders them on a timeline.
