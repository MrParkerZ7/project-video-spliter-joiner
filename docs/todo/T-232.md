## Concept

So that the 4K speed-up the owner asked for (T-187) is in the exe they actually click, and starting that exe does not
cost them their settings, caches or files: this is the one closing check that the build the owner runs is G-059's
finished code. Three G-059 tickets deferred it in their Build log (T-189, T-193 and T-195: workers neither run
`packaging/package.ps1` nor launch the app, because it reads and writes the owner's real `settings.json` and
`VideoSplitJoiner` data folder - logs, thumbnail and waveform caches, profile pictures - so the relaunch "moves to one
settings-isolated relaunch at the end of G-059"). T-191, T-192, T-194, T-196 and T-219 carry the same "Rebuilt and
relaunched" acceptance line, still open, and T-221 (not a G-059 ticket) points here. This ticket is the one deliberate
exception to the standing rule that drain workers never run `package.ps1` or launch the app (T-189 Build log). The
project's own rule (`CLAUDE.md` § Rebuild before reporting a UI fix done) says a change that affects the running app is
not done until the app is rebuilt, relaunched and the change observed: G-041 shipped green while the binary the owner
clicked was an hour older than the fix.

This ticket runs those relaunch checks (the table in Design step 5, rows R1-R8). It does not re-prove what the tickets'
own tests and bench already prove (the TS and HEVC fallbacks on generated test files, probe counts and bytes read by the
bench), and it claims only what its table observes.

Why isolation needs a backup, not an env var: `AppSettings.cs:406`, `ProfileThumbnailStore.cs:83`, `ErrorLogWriter.cs:48`,
`FfmpegThumbnailService.cs:98` and `FfmpegWaveformService.cs:105` resolve their root with
`Environment.GetFolderPath(SpecialFolder.ApplicationData / LocalApplicationData)`, which reads the known-folder path
from the shell, not the `APPDATA` / `LOCALAPPDATA` environment variables. And the isolation has to reach past the two
folders: the saved settings can turn on `SplitAutoDeleteSource`, `SplitAutoEmptyRecycleBin`, `BulkAutoDeleteOriginals`,
`BulkAutoEmptyRecycleBin` and `BulkReplaceOriginals` (on this machine today `SplitAutoDeleteSource` and
`BulkReplaceOriginals` are on), Split writes beside its source (`SplitViewModel.cs:949-961` re-anchors the output folder
on every load), Bulk writes `<name>_trimmed` beside its source, and Join's save picker opens at the owner's last output
folder (`JoinViewModel.cs:161`). A Recycle Bin that was emptied, or a file that was binned or replaced, is not
something git or a folder backup can bring back.

## Design

Recommended (star): **no product change. Check, back up, neutralise, run, restore, prove.**

1. **Never touch the owner's running app.** Look for a running `VideoSplitJoiner.App` process before anything else
   (`Get-Process VideoSplitJoiner.App -ErrorAction SilentlyContinue`). An instance this run did not start is the
   owner's and is never stopped: set `needs-user: close VideoSplitJoiner, then proceed` on this ticket and stop before
   the build (`package.ps1` deletes `dist\publish\`, which a copy running from there locks). Then list
   `%TEMP%\vsj-t232-backup-*`: a folder that holds `manifest-before.txt` but no `manifest-after.txt` is an interrupted
   earlier attempt. Its backup, not the live folders, is the owner's truth: run step 6 from it first and prove the
   restore, then start this run fresh.
2. **Build from the finished code.** Require a clean tree and a finished epic: `git status --porcelain -- src bench tests
   packaging Directory.Build.props` prints nothing and every ticket in `blocked-by` is `done`; record `git rev-parse
   HEAD`. Run `powershell -File packaging/package.ps1`; it must exit 0. It produces `dist/publish/VideoSplitJoiner.App.exe`
   and `dist/VideoSplitJoiner-v<Version>-win-x64.zip`, replacing the earlier local zip of that version; it is a local
   build, not a release (T-151 builds the release from the tag).
3. **Back up and prove the backup.** Resolve both folders the way the app does -
   `[Environment]::GetFolderPath('ApplicationData')` and `[Environment]::GetFolderPath('LocalApplicationData')` plus
   `\VideoSplitJoiner` - and record the two absolute paths. Require the backup volume to have free space of at least
   both folders' size. For each folder that exists, hash every file, hidden ones included (`Get-ChildItem -LiteralPath
   <dir> -Recurse -File -Force | Get-FileHash -Algorithm SHA256`), write `<backup>\manifest-before.txt` (one `sha256
   <root>\<relative path>` line per file, `<root>` = `APPDATA` or `LOCALAPPDATA`, sorted ordinally by
   `<root>\<relative path>`), copy the folder to `<backup>\APPDATA\` or `<backup>\LOCALAPPDATA\`, where `<backup>` is a NEW
   folder `%TEMP%\vsj-t232-backup-<yyyyMMdd-HHmmss>` outside the repo (never back up into a folder that already exists),
   then hash the copy and require its manifest to equal `manifest-before.txt` under the comparer before anything is
   launched. The comparer is one function used for the backup check, both negative controls and the final proof: it reads
   two manifests and passes only when the relative-path sets are equal and every SHA-256 is equal. Also record the
   Recycle Bin's item count, `(New-Object -ComObject Shell.Application).NameSpace(10).Items().Count`, and write its item
   names to `<backup>\recycle-bin-before.txt` (outside git; the names are the owner's and never go in the Build log). A folder that does not exist is
   recorded as `absent`. The Build log records counts, paths and match results only, never file contents
   (`settings.json` holds the owner's personal folder names).
3b. **Neutralise the settings that act outside the folders.** Read the backed-up `settings.json` and record the values of
   `SplitAutoDeleteSource`, `SplitAutoEmptyRecycleBin`, `BulkAutoDeleteOriginals`, `BulkAutoEmptyRecycleBin` and
   `BulkReplaceOriginals`. Before launch, set all five to `false` in the live `settings.json`; the backup keeps the
   owner's values and step 6 restores them. Edit the live file with a text-level replace, or `ConvertFrom-Json` /
   `ConvertTo-Json -Depth 20` (the default depth flattens `cutProfiles`); keep every other key; add a missing key in
   PascalCase exactly as the file writes these five (for example `SplitAutoEmptyRecycleBin`); then re-read the file and
   require all five to read `false` (a missing or corrupt file needs no edit - the app reads an absent key as off).
4. **Launch and check health.** `Start-Process dist\publish\VideoSplitJoiner.App.exe -PassThru`, wait 5 s, then require
   all of: `$p.HasExited` is false; after `$p.Refresh()`, `$p.MainWindowHandle` is not 0 and `$p.Responding` is true; a
   UI Automation walk of the desktop's top-level windows (`Add-Type -AssemblyName UIAutomationClient`) finds exactly one
   window owned by the PID, with no `#32770` dialog class and no title containing "error"; and no file was added to
   `<LocalApplicationData>\VideoSplitJoiner\logs\` since launch (the app writes a log and shows a dialog on an unhandled
   exception). Save a screenshot of the window to `<backup>\run-evidence\`.
5. **Drive the G-059 paths on synthetic fixtures only.** Build the fixtures into a new bench root:
   `D:\_env_storeage\dotnet\dotnet.exe build VideoSplitJoiner.sln -c Release`, then
   `bench\VideoSplitJoiner.Bench\bin\Release\net8.0\VideoSplitJoiner.Bench.exe fixtures --root "$env:TEMP\vsj-t232-fixtures" 4k 1080 g10 hevc mkv`
   (about 2.9 GB for the five fixtures and about 6 GB more for the scratch outputs and the Bulk copies: require 12 GB free
   on the `%TEMP%` volume before the bench starts; bench exit 7 means not enough disk and is recorded; the default root
   holds no fixture today and a bare `fixtures` makes the whole ~8 GB matrix). Once the fixtures are built, list the
   fixture root (relative path, length, LastWriteTime) to compare after the app is closed. Split and Join take an output
   location: after each load and before pressing Run, set it to the scratch folder `%TEMP%\vsj-t232-out` (Split
   re-anchors its output folder to the source's folder on every load; for Join type the output's full path in the save
   picker). Bulk Cut has no output setting - it always writes `<name>_trimmed<ext>` beside its source - so R6-R9 load
   copies, never the fixtures: copy `4k`, `g10`, `1080` and `hevc` into `%TEMP%\vsj-t232-out\bulk\` and add only those
   copies as Bulk rows. Confirm Bulk Cut's Replace originals is unchecked. Type each input's full path in the file
   picker's File name box; the picker opens in the owner's last input folder, so do not browse it. Drive the rows
   with Windows UI Automation from PowerShell, and record each as `observed: <value>`, `FAILED: <value>` or
   `not observed - <tool tried and why>`. "ffprobe poll" = `Get-CimInstance Win32_Process -Filter "Name='ffprobe.exe'"`
   every 100 ms, command lines kept. Neither ffmpeg nor ffprobe is on PATH here: every `ffprobe` / `ffmpeg` command in the
   table is the bundled build (`$ff = "<repo>\dist\publish\ffmpeg"`, then `& "$ff\ffprobe.exe" ...` /
   `& "$ff\ffmpeg.exe" ...`), and each is run only while no ffprobe poll is recording.

   `dist\publish\ffmpeg\` to be running (`Get-CimInstance Win32_Process`; wait up to 30 s, then `Stop-Process` the
   stragglers). Read the Recycle Bin's count and item names again and compare the sorted names, duplicates kept, with

   `<backup>\run-evidence\recycle-bin-diff.txt`. List the fixture root again (same fields) and require it to equal the

   `<backup>\run-evidence\`. Then make each folder equal to the backup: copy the backup over it, delete every file that
   is not in `manifest-before.txt`, remove every directory the run created, and remove a folder that was `absent`. Prove

## Edge cases

- The owner has the app open: leave it, set `needs-user: close VideoSplitJoiner`, and stop.
- The app wrote a log or a new file during a failed start: it is copied to `run-evidence\` before the restore deletes it.
- `package.ps1` fails: fix only an environment cause; a code cause becomes a fix ticket.
- A row cannot be driven even with UI Automation: the health check, the five-settings guard and the restore proof still
  run; the row is `not observed` and goes to the owner's hand checklist.
