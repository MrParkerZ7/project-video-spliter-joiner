## Concept
THE reported bug. Every visible surface of a Bulk row derives from `Snapped` alone, so when a second
set-at-playhead snaps to the same keyframe, `SetProperty` suppresses the notification and **zero pixels
change** — indistinguishable from a click the app ignored. `Requested` is visible only in a hover tooltip.
The Split screen already binds `Display` (`requested → snapped (±delta)`) and `docs/USER_GUIDE.md:258-260`
already promises Bulk does the same. Make that true.

## Grounding
- `src/App/Views/BulkCutView.xaml:710-711` — tooltip has `Display`; the field shows `Snapped` only.
- `src/App/ViewModels/CutMarkerViewModel.cs:120-123` — `Display` = `"0:05.0 → 0:04.0 (−1.0s)"`, already built.
- `src/App/Views/SplitView.xaml:305` — the Split list binds `Display` (the precedent to match).

## Fix
Surface both numbers inline on the row: the editable field shows the **requested** time; a compact secondary
label beside it renders `→ 00:04.0 (−1.0s)` from `Delta`/`Snapped`, visually de-emphasised but always present
when the snap is non-identity (hidden when Delta == 0). UI Designer sets the token/hierarchy first (adjacent
levels differentiated by ≥2 of size/weight/colour-role — never a tint alone). Must read correctly in BOTH
layout modes and not re-clip the row (see T-116's off-screen lesson).

## Acceptance criteria + Case-Coverage Matrix
- [ ] Set intro at 5s on a 4s-GOP row → row shows the request (5s) AND `→ 0:04.0 (−1.0s)`.
- [ ] Set it again at 6s → the requested number VISIBLY changes to 6s and the delta updates to `(−2.0s)`, even though `Snapped` is unchanged — the gesture is never invisible again.
- [ ] Identity snap (Delta == 0) → no delta chrome (no noise on files with fine GOPs).
- [ ] Both layout modes; long values don't clip or push the ⧉ cluster off-screen; on-theme tokens.
- Matrix — Success: both handles (intro + outro) show it. Boundary: Delta 0, large negative delta, snap-pending state, narrow horizontal row. **Perf (sync-path-cheap): the readout updates synchronously on the Requested change — no extra probe/scan.**

## Out of scope
Keyframe ticks on the scrub bar (nice-to-have, not required to fix the report); changing the snap policy.
