## Concept

- `ProbeAsync` with `-skip_frame nokey`: 0.229 s against 0.287 s on 4K, with every mapped `MediaInfo` field
  identical on 3 fixtures (g10 0.231 s against 0.343 s; 1080 0.083 s against 0.142 s).
- In-flight dedup of concurrent probes on the T-093 pattern.

## Why later

- After T-193 each file is probed once, so the first idea saves about 0.06 s per file.
- No concurrent duplicate probe has been measured, so dedup only adds cancel-safety surface.

## Trigger

- A profile shows first-probe time mattering, for example when adding dozens of 4K rows.
- A concurrent duplicate probe is observed.

## Build log


- re-validate (2026-10-05, from T-193): `ProbeAsync` now has a success-only result cache (SPEC-004 I33-I36) and deliberately no in-flight dedup; I35 records that two simultaneous calls on one uncached file each run ffprobe and store equal results, so adding dedup amends I35. Measured on the bench's libx264 fixtures, one first probe costs 0.07-0.08 s (4k, 4k10m) and 0.045 s (1080) — the same order as this ticket's "about 0.06 s per file" estimate, below the 0.27 s T-193's ticket quoted from the T-187 NVENC fixtures.
