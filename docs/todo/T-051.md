## Concept
Make the video follow the scrub pin AS the user drags — responsively, with no lag — by seeking live during the drag but coalescing (latest-target-only) + throttling so FFME never backs up.

## Design
- **Live scrub (PlayerView.xaml.cs):** while dragging (`_isUserScrubbing`), feed the current drag position to a live-scrub seek. Add a `Thumb.DragDelta` handler (or observe the slider value during drag) → `vm.ScrubPreview(TimeSpan)` at the current position. Keep `DragStarted → BeginUserScrub`, `DragCompleted → EndUserScrub(final)` (final exact seek).
- **Coalesce (D2, the anti-lag — in PlayerViewModel + FfmeMediaPlayer):** a "seek to latest, one-in-flight" mechanism. `ScrubPreview(t)`: if no seek is in flight → seek now + mark in-flight; if one IS in flight → store `t` as the pending target (overwrite any earlier pending). On the `Seeked` completion event (T-033), if a pending target exists and differs → issue ONE seek to it (clear pending). So intermediate drag positions are dropped; the player always converges to the newest pin position.
- **Throttle (D3):** additionally cap issue rate (e.g. ignore a new live-scrub seek if <~60–80ms since the last), so a slow codec + fast drag still can't flood. Coalescing already bounds in-flight to 1; the throttle bounds issue frequency.
- **Keep pop-back protection (D4):** route live-scrub seeks through the existing `BeginSeek`/seek-target hold so echoes don't pop the pin. `EndUserScrub` issues the final exact seek to the released position.
- FFME `ScrubbingEnabled` already true (fast frame preview) — verify.

## Detail
- Put the coalescing state (in-flight flag + pending target) where it can see the `Seeked` signal — likely `PlayerViewModel` (subscribed to `IMediaPlayer.Seeked`) driving `IMediaPlayer.Seek`. Keep it testable with the fake (fake raises `Seeked`).
- Mid-drag preview need not be frame-exact; the release seek is exact, and cuts keyframe-snap regardless.
- Don't seek if the new target ≈ current (dead-band a few ms) to avoid redundant seeks.

## Interfaces / contracts
- `PlayerViewModel.ScrubPreview(TimeSpan)` + internal coalescing over `IMediaPlayer.Seek`/`Seeked`; `PlayerView` `DragDelta` wiring. No engine change. VM fake-testable.

## Acceptance criteria + Case-Coverage Matrix
- [ ] With a fake player: rapid `ScrubPreview(t1..tN)` while a seek is in-flight → only ONE seek issued now, and exactly ONE more (to the LAST target) after the `Seeked` completes — intermediate targets dropped (no N seeks). (the core coalescing test)
- [ ] `ScrubPreview` throttle: calls within the window don't each issue a seek.
- [ ] Live scrub routes through the seek-target hold (no pop-back regression — the T-033 test still passes).
- [ ] `EndUserScrub` issues a final exact seek to the released position.
- [ ] Build 0-warning; prior tests green.
- Matrix — Required-Success: fast drag → player converges to final pin with ≤ a couple seeks, no backlog. Boundary: single tiny drag (one seek); drag then hold still (converges, stops); drag to 0/end (clamped). Required-Fail: n/a.

## Dependencies
None (builds on T-033's drag gating + `Seeked` event).

## Risks
Reintroducing pop-back / feedback → feed the existing hold, don't bypass it. Verify live feel via app-run (headless can't confirm smoothness).
