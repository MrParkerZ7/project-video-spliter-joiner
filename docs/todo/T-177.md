## Found

[[T-175]]'s "flag, don't fix" check (G-057 docs pass). `docs/USER_GUIDE.md` § Bulk Cut says:

> **Exact cut and Replace originals do not combine.** If both are on, the row is cut **losslessly** (to the
> nearest keyframe) and says so on the row …

The code has combined them since T-130:

- `BulkTrimEngine` refuses the combination **only** when it has no original disposer
  (`opts.Precision == CutPrecision.Exact && replacingOriginal && _originalDisposer is null`,
  `src/Core/Bulk/BulkTrimEngine.cs:241`); with one, the exact cut is written to a sibling temp and swapped in
  through `OriginalReplacer` (backup, restore on failure, Recycle Bin).
- The app always passes one: `BulkCutViewModel` builds its default engine with `new RecycleBinOriginalDisposer()`
  (`src/App/ViewModels/BulkCutViewModel.cs:252-256`), and `MainViewModel` uses that default.

So a user who needs an exact cut is told to turn Replace originals off for no reason, and the row warning the
guide quotes should never appear in the shipped app.
